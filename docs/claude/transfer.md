# 다음 단계와 비교 · 복사 옮기기 (팀 프로젝트 ① → ② → ③)

> **다시 그리는 옮기기(「② ○○로 보내기」, 2026-11-16 ~ 11-19)는 없앴다.** Figma 플러그인은 파일끼리 복사할 수 없어 「읽어서 다시 그리기」였는데, 게시된 라이브러리에 없는 컴포넌트(예전 화면을 복제해 남은 예전 컴포넌트 · 그 파일 안의 로컬 컴포넌트)까지 받는 쪽에 「옮긴 컴포넌트 (예전 라이브러리)」로 새로 그려 버렸다.
> **그 대신 복사 옮기기(2026-11-20)**: Figma의 복사(Ctrl+C) · 붙여넣기(Ctrl+V)는 컴포넌트 연결까지 그대로 옮긴다. 플러그인이 앞뒤(화면 골라 두기 · 붙은 화면 찾아 제자리에 놓기 · 기록)를 하고, **키는 이 PC 서버가 사람 대신 누른다**(`node/server/keys.js`). 키를 못 누르면 사람이 누르면 된다.
> 비교 · 옮기기 모두 Figma 플러그인(Common UX Sync)과 서버가 한다. Claude는 하지 않는다.

## 비교(① 기준으로 ②에 넘어갔는지, 2026-11-17)

- Workbench ① 탭 대상 줄의 「②와 비교」: ①의 **작업 페이지** 화면(프레임 목록)마다 상태를 보인다. 화면 이름을 누르면 그 화면으로 간다. 섹션별로 묶이고 섹션 이름으로 접는다.
  - **안 옮김**: 받는 쪽 기록(`.history/transfer/{받는 키}.json`)에 없음. 섹션째 옮긴 화면은 그 섹션 기록으로 본다.
  - **옮김 · 같음 / 옮김 · ①과 다름 / 옮김 · 확인 전**: 가장 최근 「바뀐 것 확인」 결과로.
  - **②에서 없어짐**: 기록은 있는데 ②의 프레임 목록에 그 노드가 없음(지웠거나 목록 갱신 전). 「바뀐 것 확인」이 ②를 직접 읽어 정말 없다고 확인하면 그 기록을 지워 **「안 옮김」**으로 돌린다(2026-11-20) — 다시 옮기면 새로 붙는다.
- 「바뀐 것 확인」 = 작업 `kind: 'transfer'`, `mode: 'check'`. 비교 창을 열 때 「확인 전」이 있으면 알아서 맡기고, 「다시 확인」으로도 맡긴다. 같은 짝의 확인은 서버가 하나만 둔다.
  - **② 읽기(`phase: 'scan'`)**: ② 파일에도 플러그인이 켜져 있으면(서버가 파일마다 플러그인이 물은 시각을 봄, 3분 안) 먼저 ② 플러그인이 ② 작업 페이지 화면마다 내용 확인값을 낸다(예전 옮기기가 만든 「옮긴 컴포넌트」 섹션은 뺌) → `POST /api/transfer {action:'scan', id, frames:[{node, name, sig, rec}]}`. 서버는 ① 작업 페이지 화면 중 기록이 없고 ②에 같은 이름이 있는 것을 확인 대상에 더하고 ①로 넘긴다. ②가 꺼져 있으면 이 단계 없이 바로 ① 확인.
  - **① 확인(`phase: 'check'`)**: ① 파일을 연 플러그인이 대상 노드들의 해시 · 내용 확인값을 내 `POST /api/transfer {action:'check', id, frames:[{from, hash, sig, gone}]}` → 작업에 `compare {at, items, changed, gone}`, 「완료」.
  - **내용 확인값(`sig`)**: 크기 · 보이는 레이어 수 · 보이는 글자(순서대로) · 쓰인 컴포넌트 이름(`xSig`). 파일이 달라도 같게 나온다. 컴포넌트 안쪽 레이어는 원본 컴포넌트를 불러와야 다 보이므로, 개수가 더 늘지 않을 때까지 불러온 뒤 센다.
  - **① 기준으로 ②를 직접 비교**: ②를 읽었으면 옮긴 화면마다 ② 쪽 `sig`가 ①과 같으면 「옮김 · 같음」, 다르면 「옮김 · ①과 다름」, ②에 없으면 「②에서 없어짐」. ②를 못 읽었으면 ①의 지금 해시와 기록 해시를 견준다.
  - **Figma에서 사람이 직접 복사해 옮긴 화면도 「옮김」**: 기록이 없던 ① 화면과 `sig`가 같은 ② 화면이 있으면 하나씩 짝지어 받는 쪽 기록에 더한다(①에 똑같은 화면이 둘이면 같은 ② 화면과 짝).
  - **이름만 같은 화면은 짝짓지 않는다**(2026-11-17 — 이름으로 짝지었더니 옮기지 않은 화면이 「옮김」으로 나왔다). 이름은 ① 쪽 확인 대상을 줄이는 데만 쓴다.

## 복사 옮기기(2026-11-20, `mode: 'paste'`)

- 맡기는 곳 두 군데, 같은 작업 `kind:'transfer', mode:'paste'`(한 번에 200개까지, 섹션째 옮긴 화면 · 섹션 안 화면은 그 섹션 단위):
  - Workbench ① 탭 대상 줄의 **「② ○○(으)로 옮기기」**: 지금 고른 프레임 하나, 「페이지 전체로」면 그 페이지 화면 전체.
  - 비교 창에서 줄을 체크해 고르고(「전체 선택」 · 섹션 체크 · 「안 옮김 · 다른 화면만 고르기」, 처음엔 아무것도 안 고름) **「고른 화면 n개 ②로 복사해 옮기기」**.
- 복사 옮기기를 맡기면 서버가 ① 탭을, ①이 골라 두면 ② 탭을 앞으로 가져온다(`keys.js` showTab) — 뒤에 있는 탭의 플러그인은 거의 멈춰 작업을 늦게 가져가서(시험 2026-11-20).
- 단계:
  1. **`phase: 'select'`(fileKey = ①)**: ① 플러그인이 그 화면이 있는 페이지로 가서 화면들을 **선택해 두고** 화면에 보이게 한 뒤, 화면마다 해시 · 내용 확인값을 `POST /api/transfer {action:'selected', id, frames:[{from, name, hash, sig}]}` → `phase: 'paste'`, fileKey = ②.
  2. **`phase: 'paste'`(fileKey = ②)**: ② 플러그인이 작업 페이지를 열고 선택을 비우고(선택된 프레임이 있으면 그 안에 붙음) 맨 위 노드 목록을 적어 둔 뒤 `{action:'ready'}` → `phase: 'pasting'`.
  3. **키 누르기(`keys.js`, `ready`를 받은 서버 = 두 파일이 열린 PC)**: `figma://file/{① 키}`로 ① 탭을 앞으로 → **Figma 창이 맨 앞인지 확인**(아니면 키를 보내지 않음) → Ctrl+C → 클립보드에 ① 파일의 Figma 데이터(`(figma)` · `(figmeta)` fileKey)가 들어왔는지 확인 → `figma://file/{② 키}` → 맨 앞 확인 → Ctrl+V. 실패하면 note에 이유와 「①에서 Ctrl+C, ②에서 Ctrl+V를 직접 누르세요」.
     - 윈도우: PowerShell(-STA, user32 SendInput). 맥: `osascript`(open location · keystroke) — 「손쉬운 사용」에 Figma AI Run(또는 터미널) 허용이 필요하고 클립보드 확인은 하지 않는다(시험 전).
     - 작업에 `auto: false`를 주면 키를 누르지 않고 사람이 누르기를 기다린다.
  4. **붙은 화면 놓기**: ② 플러그인이 1초마다 새로 생긴 맨 위 노드를 본다(골라 둔 수만큼 생기고 1.5초 그대로, 또는 하나라도 생긴 뒤 5초 그대로면 끝, 3분까지 기다림). 원본 화면과는 이름 → 순서로 짝짓는다.
     - 예전에 옮긴 화면(받는 쪽 기록에 있고 그 노드가 ② 작업 페이지에 있음)은 **그 자리 · 같은 순서로 바꿔 끼우고** 예전 노드를 지운다.
     - 새 화면은 붙은 배치를 그대로 두고 통째로 기존 내용 아래(400px 띄움)로 옮긴다.
     - `{action:'done', made:[{from, to, name, hash, replaced}]}` → 서버가 받는 쪽 기록 · ② 프레임 목록을 고치고 「완료」.
- 「진행 중」으로 10분 소식이 없으면(붙이는 중 멈춤) 서버가 **「실패」**로 둔다(되돌려 다시 하면 두 번 붙을 수 있어서). 사람이 ② 페이지를 확인하고 다시 맡긴다.

## 조건 · 알림

- ① · ② 파일을 **같은 PC의 Figma 데스크톱에서 열고(탭 두 개) 각각 플러그인을 켜 두어야** 한다(창을 최소화해도 플러그인은 작업을 받는다). 복사 옮기기는 그 PC의 서버가 키를 누르므로 두 파일이 같은 PC에 열려 있어야 한다.
- **Figma는 뒤 · 최소화 상태로는 옮길 수 없다**(시험 2026-11-20: 창에 키 메시지를 직접 보내도 Figma가 반응하지 않음). 그래서 옮기는 10 ~ 20초 동안만 앞으로 가져오고, **끝나면(완료 · 실패) 되돌린다**: 맡길 때의 상태(맨 앞 창 · Figma 최소화 여부)를 작업에 `restore`로 적어 두었다가 Figma가 최소화였으면 다시 최소화하고 쓰던 창을 다시 앞으로(그때 Figma를 쓰고 있었으면 그대로, `keys.js` winState · restoreWin, 윈도우만).
- 복사 옮기기 동안 Figma 창이 앞으로 오고 키가 눌린다 — 그동안 키보드 · 마우스를 쓰지 않는다(Workbench 확인 창 · 작업 note가 안내). 이 PC 클립보드 내용은 바뀐다.
- 진행 상황은 Workbench 요청 칸 위 「복사 옮기기 · …」 / 「비교」 줄과 `GET /api/jobs?kind=transfer`에 보인다.
- 예전 다시 그리는 옮기기 작업(`mode` copy, phase read · build)이 대기열에 남아 있으면 서버가 「실패」로 바꾼다(플러그인은 받지 않는다). 받는 파일의 「옮긴 컴포넌트 (예전 라이브러리)」 섹션은 그대로 둔다 — 사람이 정리한다.
- 백그라운드 감시 · Claude는 `transfer` 작업을 받지 않는다(`node/agent.js` scan에서 뺌).
