# 다음 단계와 비교 (팀 프로젝트 ① → ② → ③)

> **옮기기(「② ○○로 보내기」)는 2026-11-20에 없앴다.** Figma 플러그인은 파일끼리 복사할 수 없어 「읽어서 다시 그리기」였는데, 게시된 라이브러리에 없는 컴포넌트(예전 화면을 복제해 남은 예전 컴포넌트 · 그 파일 안의 로컬 컴포넌트)까지 받는 쪽에 「옮긴 컴포넌트 (예전 라이브러리)」로 새로 그려 버렸다. **옮기기는 사람이 Figma에서 화면을 복사해 붙여 넣는다**(컴포넌트 연결이 그대로 간다). Claude도 옮기지 않는다.
> 남은 것은 **비교**다: ① 화면이 ②에 넘어갔는지 · 넘어간 뒤 달라졌는지 본다. 비교는 Figma 플러그인(Common UX Sync)이 하고 Claude는 하지 않는다.

## 비교(① 기준으로 ②에 넘어갔는지, 2026-11-17)

- Workbench ① 탭 대상 줄의 「②와 비교」: ①의 **작업 페이지** 화면(프레임 목록)마다 상태를 보인다. 화면 이름을 누르면 그 화면으로 간다. 섹션별로 묶이고 섹션 이름으로 접는다.
  - **안 옮김**: 받는 쪽 기록(`.history/transfer/{받는 키}.json`)에 없음. 섹션째 옮긴 화면은 그 섹션 기록으로 본다.
  - **옮김 · 같음 / 옮김 · ①과 다름 / 옮김 · 확인 전**: 가장 최근 「바뀐 것 확인」 결과로.
  - **②에서 없어짐**: 기록은 있는데 ②의 프레임 목록에 그 노드가 없음(지웠거나 목록 갱신 전).
- 「바뀐 것 확인」 = 작업 `kind: 'transfer'`, `mode: 'check'`(서버는 이 mode만 받는다 — 다른 mode는 「없앴습니다」 오류). 비교 창을 열 때 「확인 전」이 있으면 알아서 맡기고, 「다시 확인」으로도 맡긴다. 같은 짝의 확인은 서버가 하나만 둔다.
  - **② 읽기(`phase: 'scan'`)**: ② 파일에도 플러그인이 켜져 있으면(서버가 파일마다 플러그인이 물은 시각을 봄, 3분 안) 먼저 ② 플러그인이 ② 작업 페이지 화면마다 내용 확인값을 낸다(예전 옮기기가 만든 「옮긴 컴포넌트」 섹션은 뺌) → `POST /api/transfer {action:'scan', id, frames:[{node, name, sig, rec}]}`. 서버는 ① 작업 페이지 화면 중 기록이 없고 ②에 같은 이름이 있는 것을 확인 대상에 더하고 ①로 넘긴다. ②가 꺼져 있으면 이 단계 없이 바로 ① 확인.
  - **① 확인(`phase: 'check'`)**: ① 파일을 연 플러그인이 대상 노드들의 해시 · 내용 확인값을 내 `POST /api/transfer {action:'check', id, frames:[{from, hash, sig, gone}]}` → 작업에 `compare {at, items, changed, gone}`, 「완료」.
  - **내용 확인값(`sig`)**: 크기 · 보이는 레이어 수 · 보이는 글자(순서대로) · 쓰인 컴포넌트 이름(`xSig`). 파일이 달라도 같게 나온다. 컴포넌트 안쪽 레이어는 원본 컴포넌트를 불러와야 다 보이므로, 개수가 더 늘지 않을 때까지 불러온 뒤 센다.
  - **① 기준으로 ②를 직접 비교**: ②를 읽었으면 옮긴 화면마다 ② 쪽 `sig`가 ①과 같으면 「옮김 · 같음」, 다르면 「옮김 · ①과 다름」, ②에 없으면 「②에서 없어짐」. ②를 못 읽었으면 ①의 지금 해시와 기록 해시를 견준다.
  - **Figma에서 직접 복사해 옮긴 화면도 「옮김」**: 기록이 없던 ① 화면과 `sig`가 같은 ② 화면이 있으면 하나씩 짝지어 받는 쪽 기록에 더한다(①에 똑같은 화면이 둘이면 같은 ② 화면과 짝). 이제 옮기기는 모두 이 방식이다.
  - **이름만 같은 화면은 짝짓지 않는다**(2026-11-17 — 이름으로 짝지었더니 옮기지 않은 화면이 「옮김」으로 나왔다). 복사한 뒤 어느 한쪽을 고친 화면은 「안 옮김」으로 남는다. 이름은 ① 쪽 확인 대상을 줄이는 데만 쓴다.

## 조건 · 알림

- ① · ② 파일을 **Figma 데스크톱에서 열고 각각 플러그인을 켜 두어야** 확인이 돈다(②가 꺼져 있으면 ① 확인만). 창을 최소화해도 플러그인은 작업을 받는다.
- 진행 상황은 비교 창 위 안내와 `GET /api/jobs?kind=transfer`에 보인다.
- 예전 옮기기 작업(`mode` copy, phase read · build)이 대기열에 남아 있으면 서버가 「실패」로 바꾼다(플러그인은 받지 않는다). 받는 쪽 기록(`.history/transfer/`)과 받는 파일의 「옮긴 컴포넌트 (예전 라이브러리)」 섹션은 그대로 둔다 — 섹션은 사람이 정리한다.
- 백그라운드 감시 · Claude는 `transfer` 작업을 받지 않는다(`node/agent.js` scan에서 뺌).
