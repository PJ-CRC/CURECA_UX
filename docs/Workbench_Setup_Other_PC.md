# Figma Workbench · 다른 PC에서 쓰기

다른 사람이 **자기 PC · 자기 Figma 계정 · 자기 Claude 계정**으로 Workbench를 실행하고, 요청을 Figma에 반영하기까지의 준비 절차다.

```
Workbench(브라우저) ── 요청 등록 ──▶ workbench/edit_requests.json
        ▲                                   │ 감시 (watch_requests.ps1)
        │ 캡처 · 상태                          ▼
   로컬 서버(8765) ◀── 캡처 ── Figma 플러그인    Claude Code ── Figma MCP ──▶ UX AI TEST › SH.L
```

---

## 1. 준비물

| 항목 | 내용 |
|---|---|
| PC | **Windows 10/11** 또는 **macOS**. 둘 다 추가 설치 없음 (윈도우는 기본 PowerShell, 맥은 기본 Perl로 서버가 돈다) |
| 폴더 | 이 저장소 폴더 **전체** (파일 하나만 옮기면 동작하지 않음) |
| Figma | **데스크톱 앱** + 본인 계정. UX AI TEST 파일 **편집 권한** 필요 (파일 소유자에게 초대 요청) |
| Claude | **Claude 데스크톱 앱(Code 탭)** 또는 Claude Code CLI + 본인 계정 |
| Git | GitHub로 받을 때만 필요 (`https://github.com/PJ-CRC/CURECA_UX`, 저장소 접근 권한 필요) |

---

## 2. 설치 (압축 파일)

- 관리자에게 받은 설치 파일을 원하는 위치에 푼다. 윈도우는 `UX_AI_TEST_Workbench_v{버전}_Windows.zip`, 맥은 `UX_AI_TEST_Workbench_v{버전}_Mac.zip`이다.
- 폴더 위치는 자유다. 경로가 하드코딩된 곳은 없다.
- **업데이트는 자동이다.** 실행할 때마다 새 버전이 배포됐는지 확인해 프로그램 파일만 바꾼다. 내 요청 · 캡처 · 설정은 그대로 남는다. 다시 압축을 받을 필요가 없다(8단계 깃허브 연결이 끝나 있어야 한다).

---

## 3. 로컬 서버 실행 · 시작 안내

1. 폴더의 **`Figma AI Run`** 더블클릭 (윈도우 `Figma AI Run.bat`, 맥 `Figma AI Run.app`)
   - **윈도우**: 터미널 창 없이 서버가 뒤에서 돌고 브라우저가 열린다. 마지막 Workbench 탭(창)을 닫으면 3초 뒤 서버도 저절로 꺼진다(묻지 않음).
   - **맥**: 창 없이 서버가 뒤에서 돌고 브라우저가 열린다. 설치할 것은 없다(맥 기본 Perl로 도는 `guide_server_mac.pl`, 윈도우 `guide_server.ps1`과 같은 기능).
     - 끌 때는 페이지 상단 메뉴 오른쪽 **[서버 종료]**를 누른다.
     - 앱은 압축을 푼 폴더 안에 그대로 둔다(작업 폴더를 앱 위치로 찾는다).
     - 처음 열 때 「확인할 수 없습니다」 경고로 열리지 않으면 **시스템 설정 › 개인정보 보호 및 보안** 맨 아래 「그래도 열기」를 누르고 다시 연다(처음 한 번).
     - 그다음 「UX_AI_TEST_Workbench 폴더를 선택하세요」가 뜨면 압축을 푼 폴더를 고른다(처음 한 번). 다운로드 파일 보호 표시를 지워 다음부터는 바로 열린다.
     - 문제가 생기면 기록 `~/Library/Logs/Figma AI Run.log`를 본다. 터미널로 실행하려면 `bash "Figma AI Run (Terminal).command"`.
   - **처음 실행한 PC에서는 「시작 안내」(`Setup.html`)가 열리고 자동으로 세팅을 시작한다.**
     - Claude 앱 실행, Figma 앱 실행(기본 작업 링크 UX AI TEST › SH.L), git이 없으면 설치 창(윈도우 winget · 맥 개발자 도구), 있으면 깃허브 로그인 · 작업 이력 공유 연결
     - 설치되지 않은 앱은 2 · 5단계의 [설치] 버튼으로 설치한다(윈도우는 winget 설치 창, 맥은 다운로드 페이지).
     - 남은 것(이름 입력, 플러그인 등록, Claude에 Figma 연결, 감시 시작)은 8단계 안내대로 하면 되고, 끝난 단계는 자동으로 체크된다.
     - Claude Code(터미널 `claude`)가 설치된 PC는 [터미널에서 Claude 시작]을 누르면 이 폴더에서 Claude가 뜨고 요청 감시까지 바로 시작한다.
   - 안내를 끝낸 뒤에는 가이드가 열린다. 상단 메뉴 「시작 안내」로 언제든 다시 볼 수 있다.
   - Windows 보안 경고가 나오면 「추가 정보 › 실행」.
2. Workbench: `http://localhost:8765/Figma_Workbench.html`
   - 상단 「작업자」에 본인 이름을 넣는다. 요청 · 이력에 남는다.

> 서버는 각자 PC에서 각자 띄운다(`localhost`). 같은 서버를 여러 PC가 보게 하려면 방화벽 · 포트 설정이 따로 필요하다.

## 4. Figma 플러그인 등록 (처음 한 번)

1. Figma 데스크톱 앱에서 **작업할 파일**(시작 안내 3단계에 넣은 링크의 파일, 기본은 UX AI TEST)을 연다.
2. 메뉴 › **Plugins › Development › Import plugin from manifest…**
3. 폴더의 `figma_plugin/manifest.json`을 고른다.
4. **Plugins › Development › Common UX Sync** 실행 → 위쪽에 「서버 연결됨」 확인
   - 실행하면 **이 파일의 페이지 이름 전체와 지금 보고 있는 페이지의 프레임 목록**을 Workbench로 보낸다. Workbench 메뉴가 이 파일 기준으로 바뀐다.
     - Figma가 무거워지지 않게 다른 페이지는 스스로 불러오지 않는다. Figma에서 다른 페이지로 가면 그 페이지 목록이 자동으로 더해진다.
     - 한꺼번에 채우려면 「나머지 페이지 천천히」(한 장씩 불러오고 쉬어 간다, 「멈춤」 가능). 프레임을 추가 · 삭제한 뒤에는 「다시 보내기」.
   - 시작 안내 링크가 가리키는 노드의 페이지가 수정 가능 페이지가 된다. 나머지 페이지는 보기 전용이다.
   - 켜 두면 작업 페이지를 고칠 때마다 바뀐 프레임 캡처(JPG, 원본 크기)가 Workbench에 자동으로 들어온다. Workbench에서 「캡처 받기」를 누른 프레임도, 지금 열린 페이지에 있으면 플러그인이 바로 받는다(다른 페이지 프레임은 Claude가 Figma 클라우드에서 받는다).
   - 프레임 목록은 Workbench의 **[Claude에게 목록 만들기 요청]**으로 만들면 내 Figma에 부담이 없다(권장).

> 폴더 위치를 옮기면 플러그인을 다시 등록한다.

## 5. Claude 연결

1. Claude 데스크톱 앱 › **Code** 탭에서 이 폴더를 연다. (CLI는 폴더에서 `claude` 실행)
   - 폴더의 `CLAUDE.md`를 자동으로 읽는다. 작업 범위 · 요청 처리 순서 · 캡처 방법이 들어 있다.
2. **Figma 연결(본인 계정)**
   - 데스크톱 앱: 설정 › 커넥터(Connectors)에서 Figma를 연결하고 본인 Figma 계정으로 로그인
   - CLI: `/mcp`에서 figma를 선택해 인증
   - 연결 후 Claude에게 「Figma 연결 확인해줘」라고 하면 UX AI TEST 파일 접근을 확인한다.
3. 요청 처리 시작: Claude에게 **「워크벤치 요청 감시 시작해줘」**
   - 「대기」 요청이 들어오면 Claude가 진행 중 → Figma 반영 → 캡처 갱신 → 변경 이력 → 완료 순으로 처리한다.
   - 감시를 안 켰다면 Workbench의 **Claude 작업 요청문 복사**를 눌러 Claude에게 붙여 넣는다.

## 6. 여러 사람이 함께 쓸 때

- **Figma 파일은 하나**(원본)라서 누가 고치든 모두에게 보인다.
- **작업 이력은 깃으로 공유된다.** 요청이 「완료」되면 누가 · 어떤 프레임을 · 무엇을 고쳤는지(캡처 포함)가 저장소의 `history` 브랜치로 올라가고, 다른 PC의 「변경 이력 › 작업 이력 (공유)」에 나타난다(5초마다 확인 · [깃 동기화]). 압축으로 받은 폴더도 된다.
  - 처음 한 번: 저장소 관리자에게 깃허브 아이디를 알려 초대를 받고 수락 → 시작 안내 8단계 **[깃허브 연결]**.
  - 열린 창이 git 설치(없으면) → 브라우저 로그인 → 연결까지 차례로 한다. 윈도우 · 맥 모두 토큰이 필요 없다(맥은 터미널에 나온 8자리 코드를 브라우저에 넣는다).
- **요청 목록 · 캡처 원본은 각자 폴더**에 쌓인다. 이것까지 공유하려면 둘 중 하나를 정한다.
  - OneDrive 같은 **공유 폴더 하나**를 모두가 쓴다 (권장, 서버는 한 사람만 띄움)
  - Git으로 각자 커밋 · 풀 (충돌 주의: `workbench/edit_requests.json`, `shots_meta.json`, `Common_UX_Changelog.md`)
- 같은 프레임을 두 사람이 동시에 고치지 않는다. 작업 전 공유 채널에 알린다.

## 7. 문제 해결

| 증상 | 해결 |
|---|---|
| Workbench에 「서버 없음」 | html을 더블클릭해 연 경우. `Figma AI Run.bat` 실행 후 `http://localhost:8765/Figma_Workbench.html` |
| 플러그인 「서버에 연결할 수 없습니다」 | 서버가 꺼져 있다(Workbench 탭을 모두 닫으면 꺼진다). 다시 실행 |
| 「서버를 시작하지 못했습니다」 | 다시 실행. 안 되면 기록 파일(윈도우 `%LOCALAPPDATA%\UX_AI_TEST_Workbench\server.log`) 확인 |
| Plugins에 Development가 없음 | 브라우저 Figma다. 데스크톱 앱에서 실행 |
| Claude가 Figma를 못 고침 | Figma 커넥터 미연결 또는 파일 편집 권한 없음. 5-2 확인, 파일 소유자에게 편집 권한 요청 |
| Claude가 요청을 처리하지 않음 | 감시가 꺼져 있다. 「워크벤치 요청 감시 시작해줘」 |
| 한글이 깨진 json | 메모장 등으로 저장하지 않는다. Claude에게 복구 요청 |
