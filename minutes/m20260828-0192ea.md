[일정 논의]
- MS 일정은 9월까지 순차적으로 먼저 처리해서 공유
- 나머지는 우선순위에 따라 진행하되 상황에 따라 우선순위 변경하며 진행

[MS]
- 토스트팝업 추가는 9/11까지 미리 적용하여 전달
- 트롤리의 사용한 소모품 제거 UI는 추석 전까지 작업하여 전달

[소모품 트롤리 도킹해제 위한 Unlock 기능 및 DX 입고 관련 논의 결과]
- 업체별 기계 트롤리 도킹 방식
ㄴ단디: 시스템이 초음파 센서로 인식하여 정상 도킹 여부 확인하며 사용자가 프론트 유리문을 닫으면 자동으로 유리문이 Lock되며 트롤리도 도킹이 자동으로 진행됨. 또한 기존에 진행하던 Run이 있다면 자동으로 이어서 진행되도록 설계
ㄴ로체: 트롤리가 입고 되면 QR을 찍어 트롤리 입고여부 체크 -> 유리문을 닫고 Door에 있는 걸쇠같은 장치를 걸면 Docking 됨

- 트롤리 회수 시나리오(전제조건: 소모품 트롤리 하단을 '회수용'으로 사용함으로써 전처리 장비의 소모품 미회수)
ㄴ사용자: Instrument의 [Door Control]에서 Unlock을 클릭
    ㄴPrep Consumable Storage 모듈 상태값: Ready(or Error)
ㄴ시스템: 트롤리 Undock 처리 후 유리문 Door Unlock 적용
ㄴ사용자: Door 열고 트롤리 회수

- 트롤리 입고 시나리오(문이 닫혀있으면 Door Control에서 Unlock 작업 진행)
ㄴ사용자: 트롤리 입고 후 유리문 Door 닫기
ㄴ시스템: 유리문 및 트롤리 Dock 상태를 Lock로 전환
   ㄴ1. 기존에 진행 중이 Run이 있다면 이어서 진행
   ㄴ2. 기존에 진행 중이 Run이 없다면 대기

-결론
ㄴ도킹을 Lock 해제하는 장치는 따로 만들지 않고, 시스템에서 Door의 상태값 변경을 인식해서 자동으로 처리되도록 적용
ㄴDX 저장장치의 열수 있는 상태값은 따로 만들지 않고 Storage 서랍을 열수 없는 상태면 알럿을 적용하여 잠시 후 다시 시도할 수 있도록 안내

- 정책 결론
ㄴ모듈이 Ready 및 Error 상태일 때만 유리문 Lock 해제할 수 있다. (기존 정책 유지-모든모듈 해당)
ㄴDX는 검사 장치에 유리문이 있고 저장장치에 유리문이 없기 때문에 영향도 없음
ㄴPrep은 모듈의 상태값에 따라 트롤리 회수 가능여부가 정해지지만 DX의 경우 모듈 상태값에 영향을 받지 않기 때문에 DX는 모든 상태값에서 DX저장장치 Open이 가능하다.
 
[Buffer Cartridge Storage 정책 변경]
ㄴ장치가 여분의 Cap을 확인할 수 있는 장치가 없음. 현재로서는 1회 리턴 후 재사용 시 Recap이 되지 않아 폐기가 필요한 상황(또는 1회 사용 후 재사용을 할 수 없는 구조)
ㄴ관련해서 다시 씨젠측 내부 논의 후 정책 반영 필요

[Run 배치 관련 논의 내역]
ㄴ검체 트롤리 기준 Run 진행 중 STAT Storage 통해 검체가 입고 되어 run start를 진행할 경우,
ㄴ전처리 장비에 입고된 검체소켓의 모든 검체가 소진된 이후 STAT Storage 소켓을 갖고 가서 검사가 진행됨
ㄴ또한 DWP도 기존 검체 트롤리용과 STAT으로 들어온 것을 섞어서 분주하지 않음(분리되어 검사 진행)
ㄴ기존 배치 TAT는 멈추지 않고 계속 시간은 늘어나는 구조
