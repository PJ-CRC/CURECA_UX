[Door Control]
- Door 버튼명 'Unlock'으로 변경 논의 
  ㄴ1차 요인: 번역으로 인한 버튼명 길이 이슈
  ㄴ정책 변경에 따라 케이스가 줄어서 안내 문구로 일시 정지된 내역 표기하는 방식으로 적용해도 무방해 보임
  => 다국어 작업 및 일시정지되는 부분은 안내 문구로 하되, 색깔로 구분을 줄 수 있는 방식으로 적용 후 다시 논의
  ㄴ 통합상태가 Running일 경우 Unlock all doors 비활성화 처리 (Error와 Ready 일때만 활성화)

[가동 리포트]
- 배치 단위로 리포트 생성
- Run Summary
  ㄴ처리 완료 및 실패한 수도 총 개수 표기 필요 (상태값별 개수 표기 / stop 했을 경우도 분류되게 적용)
  ㄴ예상 시간 제거 / 실제소요시간 기입하는 것으로 정의
  ㄴ배치 ID 생성 규칙 추가 > 기존 인덱스 기준에서 고유 ID 부여되는 방식으로 정의
  ㄴ Run start 되어 Ready된 샘플이 아예 스캔도 안되고 트롤리에 위치했다가 중지되면 다시 상태값이 Ordered로 변경
  ㄴ 프로세스별 Start / end date/time 제거
  ㄴ 검사군 및 검사종류 추가로 표기
- Event Summary
  ㄴ 건수는 Error / Warnning 2가지 분기되서 합산된 정보 표기 요청
  ㄴ Event type별 모듈 개수 정보 제거
- Cumulative Operation
  ㄴ 모듈 인덱스별 Run-time 표기
  ㄴ Events 최근 30일 Instrument type만 합산하여 표기
- Maintenance
  ㄴ TBD 유지보수 메뉴 설계 후 관련된 정보 요약하여 추가하는 방향으로 정리

[TSS 기타]
- Storage를 물리적으로 닫을 경우 'Done' 버튼과 동일하게 처리 (작업이 완료되었음)
- 입고 진입 화면에서 UNLOCK 버튼과 QR 부분은 SB와 동일한 기조로 적용

[정책]
- 검체 트롤리도 Run Start되는 시점에 리셋되지 않게 해야함 (장비를 Stop할 경우 검사를 시작하지 않은 검체가 있을수도 있어서)
