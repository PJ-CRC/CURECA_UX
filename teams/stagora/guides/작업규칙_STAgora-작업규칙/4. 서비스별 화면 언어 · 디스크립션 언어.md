# 4. 서비스별 화면 언어 · 디스크립션 언어

화면에 표시되는 문구와 디스크립션에 쓰는 언어를 정의한다.

## 4-1. 서비스별 언어

| Secure Uploader | 영어       | 한국어, 영어, 독일어, 스페인어, 이탈리아어, 프랑스어, 포르투갈어 |

## 4-2. 디스크립션 언어

| 구분    | 규칙                                               |
| ----- | ------------------------------------------------ |
| 디스크립션 | 설계 화면 언어와 상관없이 모든 디스크립션은 한국어로 작성한다.             |
| 예시    | ~~GMCS(기본 화면 언어: 영어)의 화면 문구는 영어, 해당 화면의 디스크립션은 한국어~~ |

## 4-3. 언어셋

- 7개 언어 문구는 언어셋 문서(Sheet)로 관리한다. 문구마다 ID가 있고, 고유명사도 따로 관리한다.
- 언어셋은 `기준데이터 / 언어셋`에서 관리한다. 각 서비스별 담당자가 관리하며, 점진적으로 Claude가 관리하도록 바꿀 예정이다. 그 관리 체계는 담당자가 정해 이 문서에 반영한다.
- 언어셋에 없는 문구는 `4-A. 다국어 번역`을 참고해 생성한 뒤 `기준데이터 / 언어셋`에 반영한다(`4-6. 새 문구와 언어셋 등록`).
- UX 작업에서 Claude는 언어셋에 있는 문구를 그대로 쓰고 고치지 않는다. 언어셋에 없는 문구만 `4-6`의 흐름대로 생성해 반영한다.

## 4-4. 화면 산출물

화면 하나를 설계하면 두 가지 화면을 만든다.

| 화면       | 내용                                                                        | 보는 사람              |
| -------- | ------------------------------------------------------------------------- | ------------------ |
| 기본 언어 화면 | 서비스별 기본 화면 언어로 작성한 UX 화면                                                  | 고객 (리뷰·컨펌)         |
| 최장 언어 화면 | 같은 화면의 문구 자리마다 7개 언어 중 가장 긴 표현을 넣은 화면. 문구마다 가장 긴 언어가 다를 수 있어 여러 언어가 섞여 보임 | UI 디자이너 (언어 길이 참고) |


## 4-5. 작업 순서

화면을 설계하거나 문구를 바꿀 때 Claude는 다음 순서로 작업한다.

1. **기본 언어로 화면 설계:** 요구사항을 반영해 화면(와이어프레임)을 먼저 구성하고 각 UI 요소에 번호를 매긴다. 라벨, 버튼, 메시지 등 화면의 모든 UI 텍스트는 `4-1`의 서비스별 기본 화면 언어(**STAgora 임상의**는 한국어, 그 외 서비스는 영어)를 따르며, 언어셋에서 발췌하는 것을 원칙으로 한다.
2. **디스크립션 작성 및 화면 보완:**  1단계에서 작성한 화면의 번호를 기준으로 `4-2`에 따라 모든 디스크립션을 한국어로 작성한다. 작성 중 누락된 요구사항이나 맥락상 어색한 흐름이 발견되면, 1단계 화면(와이어프레임)에도 변경 사항을 반영한 **최종 수정 화면**을 다시 제시하여 화면과 디스크립션이 일치하도록 한다.
3. **문구 찾기:** 최종 확정된 화면의 UI 문구마다 언어셋에서 같은 문구와 그 ID를 찾는다. (언어셋에 없는 문구는 `다국어 번역` 정책 문서를 참고해 생성한 뒤, 언어셋에 추가한다.)
4. **제공 언어 가져오기:** 찾은 문구에 대해 해당 서비스의 제공 언어(기본 7개 언어, **GMCS**의 경우 한국어·영어 2개 언어) 번역을 가져온다. 고유명사는 언어셋의 고유명사 기준을 따른다.
5. **가장 긴 표현 찾기:** 문구마다 해당 서비스의 제공 언어 중 가장 긴 표현을 고른다.
6. **최장 언어 화면 만들기:** 기본 언어 화면의 각 문구를 가장 긴 표현으로 바꾼 화면을 만들고, 레이아웃(버튼 폭, 줄바꿈, 말줄임)에 문제가 생기는 곳을 표시한다.
7. **보고:** 문구별 언어셋 ID, 서비스별 제공 언어 번역(가장 긴 언어와 표현 표시 포함), 이번 작업에서 번역 요청 목록에 새로 올린 문구를 결과에 붙인다.


## 4-6. 새 문구와 언어셋 등록

언어셋에 없는 문구가 생기면, 묻지 않고 해당 문구의 7개 언어를 `4-A. 다국어 번역`을 참고해 생성한 뒤, `기준데이터 / 언어셋`에 반영한다.

### 언어셋 등록 흐름

| 순서 | 단계 | 내용 |
| --- | --- | --- |
| 1 | 확인 | 언어셋에서 같은 문구를 찾는다. 있으면 그 ID와 번역을 쓰고 등록하지 않는다 |
| 2 | 생성 | 없으면 `4-A. 다국어 번역`의 규칙으로 7개 언어(ko-KR, en-US, de-DE, es-ES, it-IT, fr-FR, pt-PT)를 생성한다 |
| 3 | 추가 | **Figma AI Run**을 통해 `기준데이터 / 언어셋`에 새 행으로 반영한다. 구분 · Type · 비고는 같은 구분의 기존 행을 따른다 |
| 4 | 보고 | 새로 반영한 문구와 번역을 결과에 붙인다(`4-5`의 7단계) |
