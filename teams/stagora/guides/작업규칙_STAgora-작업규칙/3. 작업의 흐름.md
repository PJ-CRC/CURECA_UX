# 3. 작업의 흐름

작업 대상 문서는 공통 자료 · 화면설계서(SB) · 언어셋 3가지로 구분하며, 문서 종류에 따라 작업 방식이 다르다.

## 3-1. 공통 자료

작업의 기준을 마련해 주는 문서이며, 바로 수정하지 않는다.

| 항목 | 내용 |
|---|---|
| 정의 | 작업규칙, 정책서, UX 가이드, 용어집, Common UX 등 **작업의 기준**을 마련해 주는 문서 |
| 원칙 | 바로 수정하지 않는다 |

**변경 절차**

```
임시 정책으로 등록
   ↓
모두가 함께 확인
   ↓
SB 영향도 리스트업 후 확인
   ↓
[승인]
   ↓
[승인] 후에만 SB 반영
```

| 단계 | AI의 행동 | 비고 |
|---|---|---|
| ① 임시 정책 등록 | 변경안을 확정 내용과 구분하여 "임시 정책"으로 등록 | 공통 자료 확정 내용은 수정하지 않음 |
| ② 전체 확인 | 변경 내용을 모두가 확인할 수 있도록 정리하여 공유 | |
| ③ SB 영향도 확인 | 영향받는 SB 리스트업 (최상위 원칙 3의 형식) → 사용자 확인 | |
| ④ 승인 | 승인 여부 확인 | **승인 전에는 SB를 수정하지 않는다** |
| ⑤ SB 반영 | 승인된 항목만 SB에 반영 + 히스토리 기록 | |

## 3-2. 화면설계서 (SB)

개별 화면에 대한 정의를 담은 문서이다.

| 항목 | 내용 |
|---|---|
| 정의 | 개별 화면에 대한 정의를 담은 문서. 와이어프레임과 이에 대한 기능 설명이 주로 구성된다 |
| 성격 | 각 작업자가 **실제로 반영해야 하는 문서** |
| 작업 기준 | 반드시 승인된 정책(공통 자료)을 기준으로 작업한다 |
| 히스토리 | 변경 시 히스토리를 남긴다 (최상위 원칙 4) |

## 3-3. 언어셋

서비스에서 운영 중인 7개 언어 리스트를 반영한 문서이다.

| 항목 | 내용 |
|---|---|
| 정의 | 서비스에서 운영 중인 **7개 언어** 리스트를 반영한 문서 |
| 운영 언어(7개) | 한국어, 영어, 독일어, 스페인어, 이탈리아어, 프랑스어, 포르투갈어 |
| 반영 시점 | SB 변경으로 **UI 또는 문구가 변경**되면, 변경해야 할 언어셋을 함께 반영한다 |
| 확인 | SB를 수정할 때마다 언어셋 영향 여부를 확인한다 (신규 · 수정 · 삭제 문구, 7개 언어 모두 대상) |
| 히스토리 | 변경 시 히스토리를 남긴다 (최상위 원칙 4) |
