# 5. 작업 유형

작업을 대분류 · 중분류로 나누고 사전 확인 · 승인 조건을 정의한다.

| 대분류 | 중분류 | 설명 | 사전 확인·승인 |
|---|---|---|---|
| **1. 공통 자료 변경** | 임시 정책 등록 | 정책서, UX 가이드, 용어집, Common UX, 작업규칙의 변경안을 임시 정책으로 등록 | 모두 확인 필요 |
| | 임시 정책 확정/폐기 | 승인 결과에 따라 정식 반영하거나 폐기 | [승인] 필수 |
| | 정책 신설 제안 | 관련 정책이 없는데 서비스 전체에 영향을 주는 경우 별도 정책 개설을 제안 | 사용자에게 알림 |
| **2. 화면설계서(SB) 수정** | 화면 수정 | 개별 화면의 신규/변경/삭제. 와이어프레임과 기능 설명(디스크립션) 수정 | 정책 위배 시 확인 요청 |
| | 승인된 공통 정책 반영 | [승인]된 정책을 영향도 리스트의 체크 항목에 따라 SB에 반영 | [승인] 이후에만 가능 |
| | 정책 없는 화면 작업 | 관련 정책이 없어 SB만 작업. 서비스 전체 영향 여부 모니터링 포함 | 영향 있으면 알림 |
| **3. 언어셋 반영** | 문구 추가/수정/삭제 | SB의 UI·문구 변경에 따른 언어셋 변경 | SB 변경 시 동반 |
| | 7개 언어 반영 | 한국어, 영어, 독일어, 스페인어, 이탈리아어, 프랑스어, 포르투갈어 전체 반영 | |
| | 용어 변경에 따른 일괄 변경 | 용어집이 변경되어 여러 화면의 문구를 한꺼번에 바꾸는 경우 | 용어집 [승인] 이후 |
| **4. 검토·분석** | SB 영향도 리스트업 | 정책 변경 시 영향받는 화면/위치를 체크 가능한 리스트로 정리 | 사용자 체크 필요 |
| | 정책 위배 검토 | 요청 작업이 정책서에 위배되는지 확인 | 위배 시 작업 보류 |
| | 논리·공통 UX 검토 | 요청이 논리적 오류이거나 공통 UX에 위배되는지 확인 | 해당 시 확인 요청 |
| **5. 문서 관리** | 변경 히스토리 기록 | 버전명, 작업자, 변경 내용 필수 기록. 비고는 선택 | 모든 문서 변경 시 |
| | 버전 관리 | 문서별 버전 규칙에 따라 버전 업데이트 | 사용자 요청 시에만 변경 |

> 한 요청이 여러 유형에 걸칠 수 있다. 예) 용어 변경 요청: 1(임시 정책 등록) → 4(영향도 리스트업) → 승인 → 2(SB 반영) → 3(언어셋) → 5(히스토리)
