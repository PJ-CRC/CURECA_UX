# 4-A. 다국어 번역

>언어셋에 없는 문구를 7개 언어로 번역할 때 따르는 지침이다. Figma Workbench에서 화면을 만들다 언어셋에 없는 문구가 필요하면, 이 지침으로 번역한 뒤 언어셋에 추가한다.

## 4-A-1. 적용 범위

| 구분 | 내용 |
| --- | --- |
| 언제 쓰나 | 화면 설계 중 UI 문구를 언어셋에서 찾았는데 없을 때 (`4. 서비스별 화면 언어 · 디스크립션 언어`의 문구 찾기 단계) |
| 무엇을 하나 | 새 문구를 7개 언어로 번역하고, 언어셋에 추가한다 |
| 번역 대상 | 화면에 표시되는 UI 문구(버튼, 라벨, 메시지, 툴팁 등). 디스크립션은 한국어로만 쓰므로 번역하지 않는다 |
| 제공 언어 | 서비스별 제공 언어는 `4. 서비스별 화면 언어 · 디스크립션 언어`의 `4-1. 서비스별 언어`를 따른다. `기준데이터 / 언어셋`에는 늘 7개 언어를 모두 넣는다 |

## 4-A-2. 번역 배경

| 항목 | 내용 |
| --- | --- |
| 시스템 | 진단 검사(PCR) 결과를 차트 · 그래프로 보여 주는 통계 플랫폼 |
| 주요 사용자 | 검사실에서 진단 검사를 수행하는 사람, 진단 검사를 의뢰하고 결과를 받아보는 사람(임상의 · 의사) |
| 번역 톤 | 진단 · 의료 분야에 맞는 정확하고 간결한 표현. 사용자가 읽는 UI 문구이므로 군더더기 없이 쓴다 |

번역은 이 배경에 맞는 전문 용어로 한다. 같은 뜻의 용어가 언어셋 · 기준데이터(고유명사 · 용어)에 이미 있으면 그 표기를 따른다.

## 4-A-3. 번역 언어와 순서

번역 언어와 순서는 아래로 고정한다. 어떤 언어로 요청이 와도 순서를 바꾸지 않는다.

| 순서 | 언어 | 언어셋 열 |
| --- | --- | --- |
| 1 | 한국어 | ko-KR |
| 2 | 영어 | en-US |
| 3 | 독일어 | de-DE |
| 4 | 스페인어 | es-ES |
| 5 | 이탈리아어 | it-IT |
| 6 | 프랑스어 | fr-FR |
| 7 | 포르투갈어 | pt-PT |

## 4-A-4. 번역 규칙

| 규칙 | 내용 |
| --- | --- |
| 그대로 번역 | 입력한 단어 · 문장을 그대로 번역한다. 뜻을 더하거나 빼거나 풀어 쓰지 않는다 |
| 원문이 어느 언어든 같은 결과 | 요청 문구가 한국어든 영어든, 결과는 같은 7개 언어를 같은 순서로 낸다. 원문 언어 자리에는 원문을 그대로(필요하면 맞춤법만 다듬어) 둔다 |
| 여러 문구 한 번에 | 문구가 여러 개이면 한 줄에 하나씩 받아 문구마다 한 행으로 낸다 |
| 고유명사 | 언어셋의 고유명사 기준을 따른다. 기준에 없는 제품명 · 약어는 번역하지 않고 그대로 둔다 |
| 변수 · 기호 | `{name}`, `%d`, 줄바꿈, 괄호, 단위 같은 변수 · 서식은 원문 그대로 유지한다 |
| 글자 길이 | 화면에 들어갈 문구이므로 지나치게 길어지지 않게, 뜻이 같다면 짧은 표현을 고른다 |

## 4-A-5. 출력 형식

7개 언어는 위에서 아래가 아니라 **왼쪽에서 오른쪽**으로 나란히 출력한다. 문구 하나가 표의 한 행이다.

| ko-KR | en-US | de-DE | es-ES | it-IT | fr-FR | pt-PT |
| --- | --- | --- | --- | --- | --- | --- |
| 우리 병원 리포트 | My Reports | Meine Berichte | Mis informes | I miei report | Mes rapports | Meus relatórios |

## 4-A-6. 작업 순서

1. **언어셋 확인:** 같은 문구가 이미 있으면 번역하지 않고 그 ID와 번역을 쓴다. 비슷한 뜻의 문구가 있으면 그 표현과 맞춘다.
2. **번역:** `4-A-4` 규칙으로 7개 언어를 `4-A-3`의 순서대로 번역한다.
3. **검토:** 의료 용어, 고유명사, 변수 · 서식, 글자 길이를 점검한다.
4. **언어셋에 추가:** 번역한 문구를 언어셋에 추가한다. 새 문구의 구분 · Type · 비고는 같은 구분의 기존 행을 따른다.
5. **보고:** 이번에 새로 추가한 문구와 그 번역을 `4-A-5` 형식의 표로 결과에 붙인다.

## 4-A-7. 확인 요청이 필요한 경우

| 상황 | 처리 |
| --- | --- |
| 뜻이 둘 이상으로 읽히는 문구(예: 단독 단어) | 쓰임(버튼 · 라벨 등)을 확인한 뒤 번역한다 |
| 의료 · 검사 용어를 어떻게 옮길지 불확실 | 임의로 정하지 말고 확인을 요청한다 |
| 기존 언어셋 문구와 뜻은 같은데 표현이 다름 | 기존 표현을 쓰고, 바꾸자는 제안은 따로 올린다 |

## 4-A-8. 언어셋 기록 흐름

Figma Workbench로 언어셋에 문구를 추가 · 수정하는 작업을 했으면, 작업한 서비스에 맞는 시트에서 아래 순서로 기록한다.

| 순서 | 대상 | 할 일 |
| --- | --- | --- |
| 1 | `표지-STAgora-언어셋` 시트 | K13 셀의 날짜를 작업한 날짜로 바꾼다 |
| 2 | `문서이력` 시트 | 3번 row 아래에 새 row를 추가하고 아래 표대로 적는다 |
| 3 | 작업한 서비스의 시트 | 문구를 추가 · 수정 등 작업한 시트의 이름을 해당 버전으로 바꾼다 (`4-A-8-2`) |
| 4 | 변경된 row | `변경히스토리 이슈체크` 컬럼에 버전과 내용을 적고, **row 전체(A~P열)**에 노란색 배경을 적용한다 (`4-A-8-3`) |
| 5 | 이전 버전의 노란색 | 버전을 올리는 시트에서 **이전 버전업 때 칠한 노란색은 모두 원복**한다. 단 `0.공통문구` 시트와 각 시트 하단의 공통 문구 row는 예외다 (`4-A-8-5`, `4-A-8-6`) |
| 6 | 공통문구 | `0.공통문구` 시트에 문구가 추가 · 수정되면 각 시트 하단의 공통 문구 영역에도 같은 내용을 넣는다 (`4-A-8-6`) |

### 4-A-8-1. 문서이력 새 row

| 항목 | 내용 |
| --- | --- |
| Ver | 직전 버전에서 0.01 올린다 |
| 구분 | 작업한 서비스에 맞게 선택한다 |
| 날짜 | 변경한 날짜 |
| 내용 | 작업한 내용을 요약해 적는다 (예: 문구 추가 및 타입 변경, 미사용 처리, 영문 수정, 누락 추가) |
| 작성자 | Figma Workbench로 작업한 사람의 이름 |

### 4-A-8-2. 시트 이름 변경

시트 이름은 `{서비스}-v{N.NN}-{YYMMDD}` 형식이다. 작업 뒤 버전(`vN.NN`)과 작업일(`YYMMDD`)을 바꾼다.

| 구분 | 시트 이름 |
| --- | --- |
| 변경 전 (예: 임상의 화면 변경) | `1. 임상의-v1.97-261030` |
| 문구 CRUD 작업 뒤 | `1. 임상의-vN.NN-YYMMDD` |

### 4-A-8-3. 변경히스토리 이슈체크

| 항목 | 내용 |
| --- | --- |
| 컬럼 | `변경히스토리 이슈체크` |
| 적을 내용 | 버전과 작업 내용 |
| 배경색 | 변경된 **row 전체(A~P열 모든 칸)**에 노란색. `변경히스토리 이슈체크` 칸 하나(cell)만 칠하지 않는다 |
| 예시 | `v2.32 문구 추가` / `v1.68 문구 변경(다국어)` |

### 4-A-8-5. 이전 버전 노란색 원복

| 항목 | 내용 |
| --- | --- |
| 규칙 | 시트가 버전업되면, 이전 버전업에서 노란색 배경이 적용된 row는 **모두 원복**(노란색 제거)한다. 이번 버전업에서 바뀐 row만 노란색으로 남는다 |
| 예시 | v2.32로 업데이트할 때 v2.31 이하에서 노란색이 적용된 row가 있었다면 모두 원복하고, v2.32에서 바꾼 row만 노란색을 적용한다 |
| 순서 | 새 버전의 변경 row에 노란색을 칠하기 전에(또는 함께) 그 시트의 기존 노란색 row를 모두 찾아 원복한다 |
| 예외 | **공통 문구 row(Language ID가 `Common-`으로 시작하는 row)는 원복하지 않는다.** 공통 문구의 노란색은 `0.공통문구` 시트의 최신 리비전 기준으로 따로 관리한다 (`4-A-8-6`) |
| 확인 | 작업 뒤 그 시트에 노란색이 이번 버전의 변경 row와 공통 문구 최신 리비전 row에만 있는지 다시 읽어 확인하고, 원복한 row 수를 보고에 적는다 |

### 4-A-8-6. 공통문구 시트와 각 시트 하단의 공통 문구

| 항목 | 내용 |
| --- | --- |
| 구조 | `0.공통문구` 시트(Language ID `Common-…`)는 여러 서비스가 함께 쓰는 문구의 모음이다. 이 시트의 문구는 **각 서비스 시트(1~8) 하단에도 같은 Language ID · 같은 내용으로 붙어 있어야 한다** |
| 추가 · 수정 | `0.공통문구` 시트에 문구가 추가 · 수정될 때마다 각 서비스 시트 하단의 공통 영역에도 새로 추가 · 수정한다. 작업 전에 언어셋 파일에서 두 곳이 같은지 Language ID로 대조한다 |
| 노란색은 따로 | 공통 문구 row의 노란색은 서비스 시트의 버전업 원복(`4-A-8-5`)과 별개다. 공통 문구 row는 **`0.공통문구` 시트의 최신 리비전에서 바뀐 row만** 노란색(row 전체 A~P열)이고, 각 서비스 시트 하단의 같은 row에도 똑같이 노란색을 유지한다 |
| 예시 | `3.GMCS` 시트가 v2.32, `0.공통문구` 시트의 최신 리비전이 v2.31이면 GMCS 하단 공통 영역의 `v2.31` row(비고 `v2.31 …`)는 노란색이 살아 있어야 한다. GMCS 자체 row의 v2.31 이하 노란색만 원복한다 |
| 공통 최신 리비전이 올라가면 | `0.공통문구` 시트가 새 버전이 되면 그 시트와 각 서비스 시트 하단의 공통 row에서 이전 공통 리비전의 노란색을 원복하고 새 리비전 row만 노란색으로 한다 |
| 확인 | 작업 뒤 각 서비스 시트 하단의 공통 row 수와 내용이 `0.공통문구` 시트와 같은지, 노란색이 공통 최신 리비전 row에만 있는지 다시 읽어 확인한다 |

### 4-A-8-4. 기록 대상 · 위치 찾기

| 항목 | 내용 |
| --- | --- |
| 이 PC의 언어셋 파일을 즉시 수정 | 문구 작업이 끝나면 `4-A-8` 기록(표지 날짜 · 문서이력 · 시트 이름 · 변경 row)을 **이 PC의 언어셋 파일(기준데이터 언어셋)에 바로 수정해 남긴다**. 「원본 시트에서 따로 하세요」로 미루지 않는다 |
| 위치는 Language ID로 | 고칠 row는 행 번호가 아니라 **Language ID**(예: `GM-txt-390`)로 찾는다. 파일의 행 번호는 사용자가 보는 시트와 어긋날 수 있다(Language ID 칸에 ID가 아닌 글이 든 row 때문에 밀림) |
| 행 번호를 받으면 | 사용자가 행 번호를 말하면 먼저 그 번호의 Language ID가 파일과 시트에서 같은지 대조한다. 다르면 Language ID 기준으로 처리하고, 어긋난 것을 보고에 적는다 |
| 고친 뒤 확인 | 고친 row의 Language ID가 요청한 ID와 맞는지, 노란색이 그 row 전체(A~P열)에만 있고 다른 row에는 없는지 다시 읽어 확인한다 |
| 보고 | 고친 row는 「Language ID · 파일 행 번호」를 함께 적는다 |
