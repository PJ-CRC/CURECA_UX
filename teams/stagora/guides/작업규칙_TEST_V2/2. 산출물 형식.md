# 2. 산출물 형식

## 2-1. 산출물 표

| 산출물 | 형식 | 위치 · 전달 방법 |
|---|---|---|
| 수정한 화면 | 수정 가능 페이지의 Figma 프레임 | 요청의 파일 · 페이지 |
| 캡처 | 고친 프레임마다 `get_screenshot`(긴 변 = 원본 크기, 최대 8000) PNG | `POST /api/shots` → `projects/{fileKey}/shots/` |
| 고친 프레임 알림 | `frames:[{nodeId, name}]` (고친 순서, 최대 12개) | 「완료」 update에 함께 전송 |
| 변경 이력 | `Common_UX_Changelog.md` 항목 | 파일 맨 위, 제목 앞에 파일명 |
| 작업 이력 · 토큰 사용량 | 서버가 상태 변경마다 자동 기록 | `.history/` (깃 공유) |
| 요청 note | 줄바꿈으로 나눈 답변 | Workbench 「Claude 답변」 |

## 2-2. note 작성 형식

| 줄 | 내용 |
|---|---|
| 첫 줄 | 처리 요약 한 문장 |
| 다음 줄들 | `- 화면: 무엇 → 어떻게` (고친 곳마다 한 줄) |
| 참고 · 확인 필요 | 어긋난 점, 남은 일 (마지막 줄 앞) |
| 마지막 줄 | `작업 기준: 작업규칙 {제목\|없음} · 정책서 {제목\|없음} · UX가이드 {제목\|없음} · 기준데이터 {제목\|없음} · 화면 정의서 {제목\|없음}` |

## 2-3. 수정 이력 표기 (화면 위)

화면 위 수정 표기는 적용한 UX 문서의 규칙을 따른다. 규칙이 없으면 화면에 별도 표기를 넣지 않고 변경 이력으로만 남긴다.
