# 9. 케이스 작성

본 화면과 다른 상태 · 레이아웃은 케이스 프레임으로 빼고, 케이스 설명에는 본 화면과 달라지는 점만 쓴다.

## 9-1. 케이스로 뺄지 판단하는 순서

새 화면 · 케이스 · 한 줄 설명 중 무엇으로 쓸지 판단하는 순서를 정의한다.

| 순서 | 질문 | 그렇다면 |
|---|---|---|
| 1 | 새 화면인가 (진입 경로가 다르거나 팝업 · 별도 페이지로 열림) | 새 CID(IA 문서)로 만들고, 케이스로 쓰지 않는다 |
| 2 | 와이어프레임을 다시 그려야 이해되는가 (영역의 구성 · 배치가 바뀌거나 두 영역 이상이 함께 바뀜) | 케이스로 뺀다 |
| 3 | 둘 다 아니다 | 디스크립션에 한 줄로 쓴다 (예 : 버튼 비활성, 마우스 호버, 문구만 바뀌는 메시지, <Common UX>의 표준 동작) |

## 9-2. 자주 나오는 케이스

케이스로 자주 빼는 상태를 정의한다.

빈 상태 · 오류 · 권한 없음, 권한 · 데이터 조건에 따른 화면, 보기 전환(예 : 차트 ↔ 테이블), 펼친 상태(드롭다운 · 제시어), 입력 오류 · 단계, 산출물 예시(다운로드 파일), 문구 표 · 변수 표(10장)

## 9-3. 묶기와 나누기

여러 상태를 한 케이스로 묶을지 나눌지를 정의한다.

- 한 요소가 이어서 바뀌는 상태는 한 케이스에 나란히 둔다 (예 : 검색 중 → 제시어 선택 → 검색 결과 없음).
- 서로 다른 조건은 케이스를 나눈다 (예 : 데이터 0건과 권한 없음).

## 9-4. 이름과 번호

케이스의 배너 · 프레임 이름과 번호 규칙을 정의한다.

| 항목 | 규칙 |
|---|---|
| 배너 | `Case N. 제목` (Case와 숫자 사이 띄어쓰기) |
| 프레임 | `CID/CaseN`, 프레임 1개에 케이스 1개, 본 화면 프레임 밖에 둠 |
| 번호 | 화면마다 1부터, 본 화면 항목 순서대로 매김. 문서용 표는 맨 뒤 |
| 하위 케이스 | 한 화면(예 : 탭)의 상태 변형은 `Case 6-1`, `Case 6-2` |
| 전달 후 | 개발 전달 후에는 케이스 번호를 바꾸지 않는다. 새 케이스는 뒤에 붙인다 |

## 9-5. 설명 박스

케이스 설명 박스에 쓰는 내용을 정의한다.

```
검색 결과 없음
  • 화면 : (3) 검색 결과가 0건인 경우
  • (3) 리스트
    • 컬럼 헤더 유지, 리스트 영역 가운데에 안내 문구 표시
      • msg : No results found.
```

- 설명 박스의 번호와 케이스 배지는 본 화면 항목 번호를 그대로 쓴다.
- 첫 줄 `화면 :`에 어떤 조건의 화면인지 쓴다.
- 같은 내용을 두 케이스에 복사하지 않고 참조한다 (예 : 세션 종료는 XX-ABC [Case 1. 세션 종료 처리]에만).

## 9-6. 본 화면 디스크립션에 케이스 참조 쓰는 법

본 화면 디스크립션에서 케이스를 가리키는 위치와 형식을 정의한다.

| 항목 | 규칙 |
|---|---|
| 위치 | 케이스에서 달라지는 항목의 `참고` 아래. 화면 전체가 조건에 따라 바뀌면 `#`에, 기본 상태가 다르면 `*`에 쓴다 |
| 형식 | `조건 : [Case N. 제목]`. 조건은 케이스 설명 박스 첫 줄 `화면 :`과 같은 말로 쓴다 |
| 여러 항목 | 여러 항목이 같은 케이스로 바뀌면 그 항목들의 `참고`에 모두 적는다 |
| 고칠 때 | 케이스를 지우거나 제목을 바꾸면 참조한 곳도 함께 고친다 |

```
리스트
  • 노출
    • …
  • 참고
    • 검색 결과가 0건인 경우 : [Case 1. 검색 결과 없음]
    • 테이블 보기 : [Case 2. 테이블 보기]
```
