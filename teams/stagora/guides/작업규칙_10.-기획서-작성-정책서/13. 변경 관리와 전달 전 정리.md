# 13. 변경 관리와 전달 전 정리

수정한 화면은 그날 헤더 Date를 갱신하고, 개발 전달 전에 아래를 정리한다.

## 13-0. 전달 전 정리

개발 전달 전에 정리할 것을 정의한다.

| 항목 | 정리할 것 |
|---|---|
| 이름 변경 | 용어 · 문구를 바꾸면 디스크립션, 와이어프레임, 케이스, 문구 표를 함께 바꾼다. 디자인 섹션은 별도로 디자이너에게 전달한다 |
| 숨긴 레이어 | 기획서 프레임의 필요 없는 숨긴 레이어는 지운다. 디자인 · 프로토타입 화면은 건드리지 않는다 |
| 같은 이름 프레임 | 예전 초안은 지우거나 기획서 영역 밖으로 옮긴다 |
| 변경 이력 | 버전마다 13-1 업데이트 표시 규칙으로 기록한다 (`[버전_날짜 : 내용]`) |
| 번호 | 전달 후에는 항목 · 케이스 번호를 바꾸지 않는다 |
| 공유 파일 | 다른 파일로 공유할 때 페이지 간 참조에 링크가 걸려 있는지 확인한다 |

## 13-1. 업데이트 표시

바뀐 내용을 화면 옆 라벨, 디스크립션 표시, Revision History 표 세 곳에 함께 남기는 방법을 정의한다.

### 위치

| 위치 | 방법 |
|---|---|
| 화면 옆 라벨 | 프레임 오른쪽 위 바깥에 `Update history` 컴포넌트, 버전 변형(v0.1~v1.0) 선택 |
| 디스크립션 | 항목 제목 아래 빨간 안내 + 항목 배경 |
| 이전 문구 | 회색 취소선으로 남기고, 새 문구는 굵게 |
| Revision History 표 | 화면 묶음 위에 표, 최신 버전이 위 |

### 디스크립션 표시

| 항목 | 규칙 |
|---|---|
| 안내 | `[v버전_MM/DD : 변경 내용]`, 글자색 #FF0000, 굵게, 불릿 없이 항목 제목 바로 아래 (예 : `[v0.2_11/16 : 검색 조건 추가]`) |
| 배경 | 디스크립션 인스턴스에 #FF0000, 불투명도 10% |
| 지운 줄 | 회색 취소선으로 원래 자리에 남긴다. 원문은 이전 버전에서 가져오고 다시 쓰지 않는다 |
| 새로 생기거나 바뀐 줄 | 굵게 |
| 케이스 번호가 바뀐 참조 | 바뀐 줄로 표시한다 |

### 라벨 작성

- 첫 줄 : `v0.2 update : 11/16` (최초는 `v0.1 : 11/16`)
- `[번호] 변경 내용` 아래에 세부 내용 (예 : `[4] 검색 조건 추가` → `Default : 전체 → Default : 최근 3개월`)
- 여러 항목이 같은 변경이면 번호를 이어 붙인다 (예 : `[*][2][3] 메뉴 이름 변경`).
- 버전이 여러 개면 오래된 버전이 위로 쌓는다.
- 케이스가 바뀌면 케이스 프레임 옆에도 붙인다.

### Revision History 표

| 항목 | 규칙 |
|---|---|
| 열 | 개발 반영 / 버전 / 요청인 / 컨펌 요청 / 통합 공유 / 변경사항 / 페이지 / 담당자 / Design 수정 · 반영 |
| 행 | 화면 · 케이스 단위 (예 : `XX-ABC`, `XX-ABC/Case6`), 최신 버전이 위 |
| 변경사항 | 라벨과 같은 `[번호] 변경 내용` 형식 |

### 주의

- 기록 시작 : 기획서를 나누거나 개발에 전달한 시점부터
- 라벨은 프레임 바깥에 둔다. 프레임 폭을 넓히면 오른쪽 고정(MAX) 요소가 밀려 겹칠 수 있다.
