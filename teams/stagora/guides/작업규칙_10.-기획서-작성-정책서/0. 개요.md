# 0. 개요

화면 기획서(SB)를 프로젝트와 상관없이 같은 방식으로 쓰기 위한 작성 규칙이다. 개발 · QA가 기획서만 보고 구현과 검수를 할 수 있게 만드는 것을 목표로 한다. 참고 파일 `기획서_문서_작성_정책서_초안.md`(2026-11-16 · @브렉스 초안)의 내용을 그대로 옮기고, Workbench UX 문서 서식(대분류마다 파일 · `##` 항목 · 표)으로 나누어 정리했다.

> 이 문서는 기획서 **작성 방식**(프레임 구성 · 디스크립션 구조 · 문장 · 표기 · 케이스 · 변경 관리)만 정한다. 조직 단위 UI 규칙은 <Common UX>를 따르고, 두 문서가 다르면 <Common UX>를 우선한다. 프로젝트마다 다른 값은 「1. 목적과 적용 범위」의 1-1 프로젝트 설정 표에만 둔다.

## 기준 문서

| 항목 | 내용 |
|---|---|
| 참고 파일 | `기획서_문서_작성_정책서_초안.md` (초안, 2026-11-16) |
| 기준 Figma | 없음 (참고 파일만으로 정리) |
| 장 번호 | 원본의 1 ~ 14장 번호를 그대로 쓴다. 원본에 하위 번호가 없던 장은 굵은 소제목을 `{장}-{n}` 항목으로 나누었다 |
| 본문 예시 | `XX-ABC`는 CID(화면 ID) 자리이고, CID 규칙은 IA 문서에서 관리한다 |

## 쓰는 법

| 상황 | 볼 곳 |
|---|---|
| 새 프로젝트 시작 | 1-1 프로젝트 설정 표만 채우고 나머지 규칙은 그대로 쓴다 |
| 화면 프레임 · 디스크립션 작성 | 2장 문서 구성 → 3장 번호 → 4장 노출 / 표시 / 참고 → 5 · 6 · 7장 문장 · 표기 |
| 케이스 · 문구 표 작성 | 9장 케이스 → 10장 문구 표와 변수 표 |
| 화면 수정 | 13장 변경 관리 (13-1 업데이트 표시) |
| 개발 전달 전 | 14장 검수 체크리스트 |
| 시스템과 맞지 않는 것 | 마지막 「시스템 확인」 |
