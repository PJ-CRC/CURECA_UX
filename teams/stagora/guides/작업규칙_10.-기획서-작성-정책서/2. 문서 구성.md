# 2. 문서 구성

화면 1개는 프레임 1개로 만들고, 왼쪽에 와이어프레임, 오른쪽에 디스크립션 열을 둔다.

## 2-1. 프레임 종류

기획서에 두는 프레임의 종류와 이름 형식을 정의한다.

| 종류 | 이름 형식 | 내용 |
|---|---|---|
| 화면 | `CID` (예 : XX-ABC, XX-ABC-01-P), 규칙은 IA 문서 | 와이어프레임 + 디스크립션 |
| 케이스 | `CID/CaseN`, 하위 케이스는 `CID/CaseN-M` (예 : XX-ABC/Case6-1) | 본 화면과 다른 상태 · 레이아웃 · 문구 표 |
| 해상도 변형 | `CID_해상도` (예 : XX-ABC_1280) | 해상도별로 레이아웃이 다른 화면 |
| 공통 | `[공통] 이름` (예 : [공통] 유효성 메시지) | 여러 화면이 함께 참조하는 규칙 · 메시지 |

## 2-2. 헤더 표와 확인 행

디스크립션 열 맨 위의 헤더 표와 맨 아래의 확인 행에 쓰는 내용을 정의한다.

| 칸 | 작성 내용 | 예 |
|---|---|---|
| Ver | 문서 버전 (`v` 없이) | 0.1 |
| Date | 마지막 수정일, `YYYY.MM.DD` | 2026.11.17 |
| CID | 화면 ID | XX-ABC-01-P |
| 작성자 | 작성자 이름 | |
| 화면 | 화면 이름 (UI 언어 그대로) | Report Preview |
| 경로 | 진입 경로, `>`로 연결. 여러 개면 줄을 나눔 | Report List > Report Preview |
| 확인 행 (하단) | 확인 담당자(예 : Dev, SG)별 확인 일자 | Dev : 확인 일자 : 2026.00.00 |

헤더 Date와 업데이트 표시(13-1)의 날짜는 문서 관리용 형식이라, 화면에 보이는 날짜 형식(7장)과 다르다.

## 2-3. 디스크립션 열 순서

디스크립션 열에 내용을 쌓는 순서를 정의한다.

| 순서 | 내용 |
|---|---|
| 1 | 헤더 표 |
| 2 | `*` 화면 공통 (Default 화면, 표시 형식, 참고 자료, 팝업 닫힘) |
| 3 | `#` 화면 전체 규칙 (메뉴 접속 권한, 사용자 · 데이터 조건에 따른 화면 분기) |
| 4 | 번호 항목 (화면 위 → 아래, 왼쪽 → 오른쪽) |
| 5 | 확인 행 |

- `*` 박스는 `Default 화면` · `표시` · `참고`를 0단계 제목으로 나열한다. 내용이 약 30줄을 넘으면 `* 공통`, `* 표시`, `* 참고`처럼 박스를 나눠도 된다.
- 조건에 따라 화면 전체가 달라지면 `#`에 조건과 케이스를 짝지어 쓴다 (예 : `소속 기관 유형이 A인 경우 : 본 화면`, `그 외 : [Case 9. 제목]`).
