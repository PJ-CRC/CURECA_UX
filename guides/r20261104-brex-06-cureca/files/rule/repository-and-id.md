# 저장소 구조와 ID 체계

> 상태: 초안 v0.3 (2026-11-02). 메뉴 폴더는 `screens/<IA Lv.1 메뉴>/`로 정함 (`rules/screen-spec.md` 3절).

폴더 구조, 파일 이름, 문서 간 연결에 쓰는 ID와 버전 규칙을 정합니다.

## 1. 기본 원칙

- 문서 간 연결은 ID로만 합니다. 다른 문서의 내용을 옮겨 쓰지 않습니다(헌법 3조).
- 파일과 폴더 이름은 영어 소문자, 숫자, 하이픈(-)만 씁니다. CID, PD, PV 같은 ID는 원래 표기(대문자) 그대로 씁니다.
- 파일 안의 날짜는 항상 `YYYY-MM-DD`로 씁니다. 화면에 보이는 날짜 형식(YYYY.MM.DD)과는 별개입니다.

## 2. 화면 ID (CID)

- 지금 쓰는 CID를 그대로 씁니다. 새 ID 체계를 만들지 않고, 오타와 누락만 바로잡습니다.
- 접두어: T-IOS는 `TI`, L-IOS는 `LI`
- 접미어는 신규 CID부터 적용합니다. 기존 CID는 바꾸지 않습니다.

| 접미어 | 뜻 | 쓰는 경우 |
| --- | --- | --- |
| `-P` | Popup | 팝업 화면 |
| `-T` | Tab | 탭 화면 |
| `-V` / `-M` | 조회 / 수정 모드 | 필요한 화면에만 씀. 같은 데이터를 다루는 같은 구조의 화면인데, 수정 모드에서 UI가 추가되어 화면을 나눠야 할 때만 씀. 필수 아님 |

## 3. 화면설계서 파일

- **CID 하나에 파일 하나:** `TI-DAS.md`, `LI-DAS.md`처럼 T-IOS와 L-IOS 화면을 각각 따로 둡니다. 짝 화면이라도 구조, 버튼, 기능이 서로 다를 수 있어 하나로 합치지 않습니다.
- **짝 연결:** 짝이 있는 화면은 두 파일 모두 머리말에 `pair_cid`와 `tl_relation`(동일 / 권한 차이 / 기능 추가 / 단독)을 적습니다. 한쪽에만 적혀 있으면 검증 오류입니다.
- **공통 내용은 정책으로:** 두 화면에 함께 적용되는 규칙은 화면설계서에 따로따로 쓰지 않고 정책서에 정의한 뒤 정책 ID로 참조합니다. 그래야 한쪽만 고쳐지는 일이 줄어듭니다.
- **짝 확인:** 한쪽 화면을 고치면 짝 화면도 영향 범위에 넣고, 한쪽만 고쳐졌으면 다른 쪽도 고칠지 묻습니다(`rules/claude-work.md` 5절).
- **공통 팝업:** 여러 곳에서 열리는 팝업(예: Door Control)은 화면설계서에 호출 위치 목록을 둡니다.

## 4. 항목 ID

| 대상 | 형식 | 폴더 |
| --- | --- | --- |
| 협의 대기 | `PD-0001` | `pending/` |
| 임시 정책 | `PV-0001` | `provisional/` |
| 변경요청 | `CR-0001` | `changes/` |
| 결정 기록 | `ADR-0001` | `decisions/` |
| 정책 | `POL-영역-###` (예: POL-EQP-001) | `policy/<영역 코드 소문자>/` |
| 고객 논의 대상 | `CA-0001` | `customer-agenda/` |

- 정책 ID를 뺀 항목은 네 자리 일련번호입니다(정책은 영역마다 세 자리, `rules/policy-writing.md` 1절). 폴더(닫힌 항목 폴더 포함)에 있는 가장 큰 번호에 1을 더합니다.
- 한 번 쓴 번호는 다시 쓰지 않습니다. 같은 번호가 동시에 생기면 나중에 반영되는 쪽의 번호를 바꿉니다.

## 5. Module과 Unit

- 문서에는 UI 표기를 씁니다: `PCR Setup (1)`, `Waste Bin (Upper)`
- 데이터와 검증에는 코드명을 씁니다: `PcrSetup`, `UpperWasteBin`
- 기준: `glossary/module-units.csv`

## 6. 버전 (Ver)

화면 정보의 Ver는 `X.Y.Z` 세 자리입니다.

| 자리 | 뜻 | 예 (2.1.13) |
| --- | --- | --- |
| X | 프로젝트 차수 | 2 = 2차 프로젝트 |
| Y | 그 프로젝트 안의 릴리즈 순번. 0부터 시작 | 1 = 두 번째 릴리즈 |
| Z | 그 릴리즈 안에서 개발사에 전달한 순번 (내부 관리 번호). 항상 두 자리 (01, 02, … 13) | 13 |

- **버전은 CID마다 따로 갑니다:** 이번 작업에서 수정한 CID만 새 버전으로 올리고, 수정하지 않은 CID는 이전 버전을 그대로 유지합니다. 같은 메뉴 안에서도 CID마다 버전이 다를 수 있습니다.
- **작업 시작 때:** Claude는 쓰기 작업의 계획 확인(공통 순서 5단계)에서 이번 작업이 어느 버전에 들어가는지 묻고, 요청자가 정한 버전을 화면 정보에 적습니다.
- **개발사 전달 후:** 전달 완료가 기록되면, 이후 변경은 버전을 올려야 한다고 알립니다. 어느 자리를 올릴지는 요청자가 정합니다.
