# 3. 화면 설계

> 상태: 초안 (2026-11-10). 2026-11-10부터 이 문서로 작업합니다. "※ 정할 것" 표시는 이 문서 끝 "정할 것"에 안이 있습니다.

1단계 요건과 2단계 근거로 **화면 MD를 쓰고, 그것을 그대로 Figma에 그리는** 단계입니다. 화면 MD가 원본이고 Figma는 화면 MD를 옮긴 것입니다(헌법 6조). 질문이 있어도 먼저 그리고 빨간 글씨로 표시합니다.

## 읽을 것

1. 작업 기록: "요건"(요건 대상 화면 목록 · 기존 원본의 케이스 화면 · 이번에 반영할 반영 대기 항목 · 확인할 것), "근거"의 **읽은 자료 목록** · 관련 자료 없는 영역 · 요소 · 대조 · 정책 수정 범위 · 용어 목록, "이 작업의 결정", 질문 대기
2. **읽은 자료 목록에서 "설계에 씀"이 `O`인 자료.** 이 자료를 읽고 시작하며, 영역 · 요소를 그릴 때 그 영역에 쓰는 자료를 읽습니다. `-`인 자료는 읽지 않습니다. `관련 자료 없음`인 영역은 정책 · 가이드를 다시 찾지 않고 기존 UX 화면설계서에서 따옵니다.
3. `templates/screen.md` (화면 MD 틀), `reference-rules/description.md` (디스크립션 쓰는 법), `examples/`의 본보기
4. UX가이드의 "Figma 컴포넌트" 표(컴포넌트 · Variant), `reference-rules/guide-element-defaults.md` (가이드 요소 기본값)
5. 그릴 Figma 페이지: 그리기 전에 먼저 열어 무엇이 있는지 확인함. 있던 그림은 옮기거나 지우지 않음

- **표시된 자료만으로 정의할 수 없는 것이 나오면 추가로 자료를 찾아 읽을 수 있습니다.** 읽은 자료는 작업 기록의 "읽은 자료 목록"에 `(3단계에서 추가)`를 붙여 더하고 설계에 씀을 표시합니다. `-`로 뺐던 자료를 쓰게 되면 `O`로 바꿉니다. 읽고도 목록에 남기지 않는 일은 없어야 합니다.
- 추가로 읽다가 정책과 기존 화면이 다른 곳을 새로 찾으면 2단계 "대조" 표에 더하고, 정책을 바꿔야 하면 요청자에게 알립니다.
- 디스크립션 번호가 정해지면 목록의 "쓰는 화면 · 영역 · 요소" 칸에 새 번호를 덧붙입니다.

## 할 일

### 1. 화면 MD 쓰기 (CID마다)

1. `templates/screen.md` 구조를 그대로 씁니다(절을 빼거나 더하지 않음). 케이스 3은 `source: asis` → `tobe`로 바꾸고 변경 이력에 "신규 작업방에 새로 그림 (기존: 작업방 링크 · Ver)"을 남깁니다.
2. **디스크립션:** 먼저 본보기(`examples/description-samples.md`)를 읽고 그 결로 씁니다. 목록 화면은 본보기 1, 그 밖의 화면은 본보기 2를 따르고, 차트가 있는 화면만 본보기 3을 함께 봅니다. `reference-rules/description.md`대로 화면의 모든 영역 · 요소에 빠짐없이 씁니다. 개조식(명사로 끝냄)으로, 그 화면에서 보이고 일어나는 일을 풀어 쓰고 정책 ID는 블록 끝 `● 정책 참고`에만 둡니다(헌법 3조). T-IOS · L-IOS는 각자 완결합니다.
3. **화면 예시 표:** 그릴 때 넣을 값을 기준데이터에서 가져와 적고 "기준" 칸에 출처를 적습니다. 상태값은 `status-values.csv`, Module · Unit은 `module-units.csv`, 품목 · 수량은 `consumables.csv` · `pcr-reagents.csv`의 UI 표기입니다. 기준데이터에 없는 목록 제목 · 설명 글만 상황에 맞게 지어 씁니다.
4. **케이스 화면:** 화면 MD "케이스" 표에 근거가 있는 것만 적습니다(아래 "케이스 화면"). 근거 없이 Claude가 판단해 더하지 않고, 더 필요해 보이면 질문으로 올립니다.
5. **반영 대기 항목:** 1단계에서 "이번에 반영"으로 고른 항목(상태 `작업 중`)만 반영합니다. 고르지 않은 `대기` 항목은 건드리지 않습니다. 화면에 반영해도 상태는 `작업 중` 그대로 두고, 7단계 완료 때 `반영 완료`로 바꿉니다(`reference-rules/pending-changes.md` 4절)
6. **작업 중 결정:** 2단계에서 정한 결정(`결정` + 이 작업 기록)을 기준으로 씁니다. 정책서는 아직 고치지 않았으므로 디스크립션에는 결정 내용을 풀어 쓰고, 어느 논의 대상에서 온 것인지는 화면 MD 머리말(정책 참고)에 `POL-EQP-004 · DS-0012`처럼 적어 둡니다(디스크립션 · 패널에는 논의 대상 ID를 쓰지 않음). 7단계 반영 뒤 머리말의 논의 대상 ID를 뗍니다.
7. **기존 화면에 없는 가이드 요소:** 2단계에서 찾은 것을 `reference-rules/guide-element-defaults.md` 기본값 표대로 처리합니다. "넣음"은 넣고 `※ 변경 확인`을 둡니다(기존 화면에 없던 요소가 생긴 것이므로). "물음"과 표에 없는 요소는 `※ 질문 대기`로 둡니다.

### 2. 질문이 생기거나 기존 화면과 다르게 그릴 때

빨간 글씨는 두 가지입니다(`reference-rules/description.md` 5절).

- **번호:** 빨간 글씨에는 작업 하나에 통번호를 넣습니다(`※ 질문 대기 Q3: …`, `※ 변경 확인 C2: …`). T · L에 같은 것은 같은 번호. 디스크립션 · 화면 · 화면 MD 표 · 작업 기록에 같은 번호를 씁니다.
- **`※ 질문 대기` — 정해지지 않은 곳:** 먼저 그립니다. 따를 것을 이 순서로 찾습니다: 그 화면의 기존 원본(UX 화면설계서) → 정책서 → 공통 UX → 같은 메뉴의 다른 화면. 찾은 내용으로 그리고 쓴 뒤 그 줄 바로 아래에 빨간 글씨를 둡니다. 넷 다 없으면 지어 쓰지 않고 그 자리에 빨간 질문만 둡니다. 화면 MD 질문 대기 표와 작업 기록 질문 대기에 올립니다.
- **`※ 변경 확인` — 근거가 있어 기존 화면과 다르게 그린 곳:** 2단계 대조에서 "기존 화면이 정책과 다름"으로 나온 곳은 정책을 따라 그리고, 기존과 무엇이 달라졌는지 빨간 글씨로 적습니다. 반영 대기 항목을 반영해 달라진 곳, 행을 줄여 그린 곳도 같습니다. 화면 MD 변경 확인 표에 올립니다. 4단계 요청자 확인에서 맞는지 확인받고, 확인된 것은 빨간 글씨를 지우면서 패널 옆 **변경 내역 상자**(케이스 3은 `재설계 후 변경 내역`)에 정리합니다.
- 정책을 정해야 하는 질문이면 논의 대상을 `논의 중`으로 만들고(`work`에 작업 기록 이름) 질문 대기 표에 DS ID를 잇습니다(`reference-rules/discussions.md` "자주 있는 네 가지 경우" 라).
- 내 화면만 바뀌는 질문(표현 · 배치 · 문구)은 논의 대상을 만들지 않고 요청자가 답하면 고친 뒤 빨간 글씨를 지웁니다.
- 고객이 앞서 정한 결정을 다시 고치면 같은 논의 대상에 결정 줄을 더하고 화면을 새 결정으로 고칩니다(경우 다).

### 3. Figma 그리기

화면 MD를 그대로 그립니다. 페이지 · 배치 · 프레임 이름은 아래 "신규 작업방 구성"을 따릅니다.

1. **CID 묶음 순서:** 목록 화면 → 상세 → Popup처럼 메뉴 흐름 순서로, CID마다 T를 먼저 끝내고 바로 L을 그립니다.
2. **컴포넌트:** 가이드 "Figma 컴포넌트" 표의 컴포넌트를 인스턴스로 씁니다. 떼어 내지(detach) 않고 속성(Variant) · 글자 · 크기 · 보이기만 바꿉니다. 맞는 Variant가 있으면 그것을 쓰고, 없으면 그 컴포넌트의 기본 Variant를 쓴 뒤 빨간 글씨 `※ 질문 대기`를 둡니다. 다른 컴포넌트로 바꿔 쓰지 않습니다. ※ 정할 것 2
3. **가이드에 컴포넌트가 없는 요소:** 그 화면의 기존 **UX 화면설계서**에서 그 요소를 똑같이 따옵니다. 기존 프레임에서 그 요소의 크기 · 색 · 글자 크기 · 간격 값을 읽어 **같은 값으로** 그리고, 읽은 원본 위치를 화면 예시 표의 "기준" 칸에 적습니다. UX 화면설계서는 기존 작업방에서 오른쪽에 화면 정보 · 디스크립션 패널이 붙은 너비 2252의 기획 프레임입니다. **같은 CID의 디자인 화면(1920×1080 디자인 프레임)에서는 가져오지 않습니다.** 가이드에 그림만 있고 컴포넌트가 없는 경우도 같습니다. 따온 요소는 `common-ux/feedback.md`에 "컴포넌트 없음: {요소}"로 올립니다. **그 화면의 기존 UX 화면설계서에 그 요소가 없으면**(신규 화면이거나 기존 화면에 없던 요소) 그리지 않고 `※ 질문 대기`로 둡니다. 기존 화면 MD "사용 컴포넌트" 절에서 같은 이름의 컴포넌트를 쓴 다른 화면을 찾았으면 질문에 후보로 붙입니다(Claude가 골라서 그리지 않음)
4. **예시 데이터:** 화면 MD "화면 예시" 표의 값만 씁니다. **목록 · 표는 한 페이지 최대 노출 개수(예: 10 items)만큼 행을 채웁니다.** 최대 개수의 행이 화면 높이(1080) 안에 들어가지 않으면 들어가는 만큼만 그리고, 그린 행 수와 이유를 화면 예시 표에 적은 뒤 그 표 옆에 빨간 글씨 `※ 변경 확인`을 둡니다.
5. **L은 T를 복제한 뒤 다른 점만 바꿈:** LNB · GNB를 L-IOS로, CID · 호출 화면 CID를 L로, 0번에 Service Mode 소제목, 원본에서 찾은 L만의 차이. 바꾼 뒤 L 디스크립션이 T를 가리키는 말 없이 완결인지 확인합니다.
6. **패널:** 오른쪽 패널에 화면 정보 표와 디스크립션을 화면 MD 그대로 옮깁니다. 그리는 중에 문장을 고치면 화면 MD와 Figma를 함께 고칩니다. 패널은 모든 화면에서 같은 틀 · 크기 · 위치로 그립니다(`reference-rules/description.md` 7절): 화면 오른쪽에 너비 332, 맨 위 화면 정보(Ver · Date · CID · 작성자 · 화면 · 경로), 번호 칸은 영역은 회색 · 요소는 흰색, 맨 아래 Dev · SG 줄은 두지 않음. 케이스 3은 Ver · Date · 작성자를 기존 화면 그대로, 케이스 1 · 2는 Date는 작성일 · 작성자는 요청자
7. **번호 표시:** 화면 위 번호를 디스크립션 번호(영역 1 · 요소 1-1)와 같게 매깁니다. T · L의 같은 영역은 같은 번호입니다.
8. **질문 표시:** 디스크립션의 빨간 질문 줄마다 화면의 그 번호 옆에도 빨간 `※ 질문 대기`를 둡니다.
9. **케이스 화면:** 화면 MD "케이스" 표에 있는 것을 모두 그립니다(아래 "케이스 화면"). 표에 없는 것은 그리지 않습니다.
10. **마무리 확인:** CID 묶음마다 스크린샷을 찍어 아래를 보고, 고친 뒤에 다음으로 넘어갑니다. 묶음을 끝낼 때마다 작업 기록 `다음:` 줄을 고칩니다.
    - **글자가 칸을 넘지 않음:** 버튼 · 칩 · 표의 셀 · 입력란 · 카드 · 패널의 글자가 자기 칸 밖으로 나가거나, 잘리거나, 옆 요소와 겹치지 않음
    - 넘치면 이 순서로 고침: ① 컴포넌트의 너비 · 높이를 내용에 맞게 늘림(떼어 내지 않고 크기만) ② 가이드가 말줄임을 정한 곳(예: 표의 셀)은 말줄임으로 ③ 그래도 안 되면 배치를 넓히고, 배치를 바꿀 수 없으면 빨간 글씨 질문으로 남김. 글자 크기를 줄이거나 예시 값을 임의로 짧게 바꾸지 않음
    - 요소끼리 겹치지 않고, 번호 표시가 가리키는 요소 옆에 있으며, 패널이 화면 오른쪽에 붙어 있음

### 신규 작업방 구성

| 무엇 | 어떻게 |
| --- | --- |
| 페이지 | 메뉴(`screens/{메뉴}/`) 하나에 페이지 하나. 이름은 `_menu.md`의 `menu`, 순서는 LNB 순서. T-IOS · L-IOS 화면을 같은 페이지에 둠 |
| 페이지 안 배치 | 왼쪽 열은 T-IOS, 오른쪽 열은 L-IOS. 한 줄에 짝 CID 한 쌍을 IA 순서로. 짝이 없는 CID는 한쪽 열만 씀 |
| 섹션 | CID마다 섹션 하나, 섹션 이름은 CID. 테스트 그림은 섹션 이름 뒤에 `(테스트 N)` |
| 섹션 안 순서 | 위에서 아래로: 기획 프레임 → `CID/Case` 프레임(케이스가 있을 때) → 1280(1280에서 배치가 달라지는 화면만) |
| 기획 프레임 | 이름은 CID(예: `TI-INS-01-T`). 너비 2252 = 화면 1920×1080 + 패널 332. 패널이 길면 프레임 높이를 패널에 맞춤 |
| 케이스 프레임 | 이름은 `CID/Case`(예: `TI-INS-01-T/Case`). 기획 프레임 바로 아래 |
| 1280 프레임 | 이름은 `CID / 1280` |

- 신규 작업방에는 최신본만 둡니다. 같은 CID를 두 곳에 두지 않습니다.
- 같은 페이지에 이미 있는 그림은 옮기거나 지우지 않습니다.
- 최장 언어 화면은 6단계(다국어)에서, 메뉴 상태 카드는 7단계(완료)에서 정합니다. 그때까지 새로 만들지 않습니다.

### 케이스 화면 (2026-11-10 정함)

조건에 따라 화면의 모습이 달라지는 곳을 보여 주는 그림입니다(작업 유형인 케이스 1 · 2 · 3과 다른 말입니다). 본보기는 `examples/case-samples.md`이고, 이 결로 그립니다.

**케이스의 원본은 화면 MD "케이스" 표 하나입니다.** 따로 파일이나 버전을 두지 않습니다.

```markdown
| Case | 제목 | 조건 | 디스크립션 번호 | 종류 | 근거 |
| --- | --- | --- | --- | --- | --- |
| 1 | Order Reception Mode 선택에 따른 Port 입력 상태 | Push Mode / Query Mode | 3-1, 3-2 | 3 | 기존 원본 |
```

**표에 올릴 수 있는 근거는 셋뿐입니다.** 어느 것도 아니면 올리지 않고 질문으로 둡니다.

| 근거 | 뜻 |
| --- | --- |
| 기존 원본 | 기존 작업방에 있던 케이스. 빠짐없이 옮기고 Case 번호도 그대로 가져옴 |
| 디스크립션 조건 | 디스크립션에 적힌 조건 가운데 아래 여섯 종류에 드는 것 |
| 요청자 | 요청자가 그리라고 한 것 |

**"디스크립션 조건"으로 그리는 것은 여섯 종류입니다.** 여기에 들지 않는 조건(버튼 활성화 조건, 기본값 등)은 디스크립션에만 적고 그리지 않습니다.

| # | 종류 | 그리는 때 | 본보기 |
| --- | --- | --- | --- |
| 1 | 상태별 데이터 노출 | 상태에 따라 어떤 값이 '-'가 되거나 버튼이 비활성화되는지 보여 줄 때 | Samples Case 1 |
| 2 | 올리거나 눌렀을 때 뜨는 것 | 툴팁, 팝업, 알럿 | Samples Case 2 |
| 3 | 유형 · 대상에 따라 표출 항목 구성이 다른 것 | 고른 유형이나 대상마다 보이는 항목이 다를 때. 유형마다 한 장 | Samples Details Case 2, Waste Bin/Bottle Module별 |
| 4 | 개수가 기준을 넘어 요소가 생기거나 배치가 바뀌는 것 | 기준 개수를 넘으면 탭 · 스크롤 등이 새로 나타날 때. 같은 모양이 길어지기만 하는 것은 아님 | Test Management Case 3 |
| 5 | 처음 들어왔거나 데이터가 없을 때 | 그 화면만의 빈 모습이 있을 때. 공통 UX에 정의된 빈 목록 · 로딩은 그리지 않고 `공통 UX 참고`로 둠 | Test Management Case 2 |
| 6 | 한 번의 조작으로 화면이 여러 단계를 거쳐 바뀌는 것 | 한 장으로 보여 줄 수 없는 진행 과정. 장면을 옆으로 나란히 놓고 번호로 설명 | Door Control |

**그리는 법**

| 무엇 | 어떻게 |
| --- | --- |
| 두는 곳 | 케이스가 1개여도 `CID/Case` 프레임 하나에 모음. 기획 프레임 바로 아래에 둠 **(우선 이 안, 테스트해 보고 확정)** |
| 제목 | 초록 띠에 `Case 1. 제목` |
| 케이스 안 구분 | 노란 띠에 `1-1. 조건` |
| 설명 | 띠 아래 한두 줄. 왜 그렇게 보이는지 개조식으로 |
| 그림 | **달라지는 부분만** 잘라서 그림(표의 행 몇 줄, 카드 하나, 팝업 하나). 화면 전체가 달라질 때만 전체를 그림 |
| 번호 표시 | 조각에 본 화면 디스크립션의 번호를 붙임. 설명은 본 화면 디스크립션 한 곳에만 있음 |
| 패널 · 버전 | 케이스에는 패널과 화면 정보 줄(Ver · Date 등)을 두지 않음. 버전은 본 화면을 따르고, 케이스를 고치면 본 화면 변경 이력에 남김 |

- **늘 보이는 항목은 지우지 않습니다.** 값이 없으면 '-'로, 누를 수 없는 버튼은 Disabled로 둡니다. 항목이나 영역이 사라지는 것은 디스크립션에 `노출 조건`으로 적힌 경우뿐입니다.
- 케이스의 조건과 동작은 본 화면 디스크립션에 번호를 두고 적고, 그 블록 끝에 `● 참고 : CID/Case > Case n`을 둡니다. 케이스에서만 나타나는 요소도 본 화면 디스크립션에 번호를 줍니다.
- Case 번호는 바꾸지 않습니다. 케이스를 지워도 그 번호를 다시 쓰지 않습니다.
- T-IOS · L-IOS는 CID마다 케이스 표와 Case 프레임을 따로 둡니다.

### 4. 영향 화면 가운데 "함께 고침"으로 고른 화면

2단계 "영향 화면" 표에서 **함께 고침**으로 고른 화면은 이 단계에서 같이 고칩니다. 그 화면 MD 변경 이력에 `연동 변경`과 원인(CID · DS ID), 고친 사람을 남깁니다(`reference-rules/pending-changes.md` 1절). **반영 대기**로 고른 화면은 건드리지 않습니다(7단계에 줄이 생김).

### 5. 용어 점검

다 그린 뒤 `terms.csv`의 쓰지 않는 표현 · `glossary.md` 표기 규칙 · `status-values.csv` · `module-units.csv` UI 표기로 Figma 화면 글자 · 디스크립션 · 화면 MD를 **단어 단위로** 찾아 용어집 표기로 바꾸고, "용어 치환" 목록(원래 표현 → 표준어, 위치)을 남깁니다. 용어집에 없는 새 말은 지어 바꾸지 않고 질문으로 남깁니다.

## 남는 것

- 화면 MD: `screens/{메뉴}/{CID}.md` (테스트면 저장소 밖 작업 폴더)
- Figma: CID 섹션마다 기획 프레임, 케이스가 있으면 `CID/Case` 프레임
- 작업 기록 "설계" 절:

```markdown

### 그린 것
| CID 묶음 (T · L) | 섹션 | 기획 프레임 | 상태 · 케이스 프레임 |
| --- | --- | --- | --- |

### 빨간 글씨 질문 대기
| 번호 (Q) | 질문 | 관련된 곳 (CID · 디스크립션 번호) | 논의 대상 | T · L 같음 |
| --- | --- | --- | --- | --- |

### 빨간 글씨 변경 확인
| 번호 (C) | 기존 화면 | 바꿔 그린 것 | 관련된 곳 (CID · 디스크립션 번호) | 근거 | T · L 같음 |
| --- | --- | --- | --- | --- | --- |

### 근거로 풀린 것
| 질문 | 푼 근거 |
| --- | --- |

### 찾은 것
- 화면 MD 요약과 원본이 다른 곳, 원본 케이스와 디스크립션이 다른 곳, 규칙에 없어 판단한 곳

### 용어 치환
| 원래 표현 | 표준어 | 위치 |
```

### 답해 주실 것 (3단계 보고의 맨 끝)

단계가 끝나면 요청자가 답해야 할 것을 **한 번에 모아** 보여 줍니다. 작업 기록의 질문 대기 · 변경 확인 표에서 풀리지 않은 것을 모두 옮기며, T · L에 같은 것은 한 줄로 합칩니다. 요청자가 번호로 답하면("Q5 ID, C4 맞음") 그대로 반영합니다.

**질문 대기 — 답을 정해 주실 것**

| 번호 | 화면 · 위치 | 질문 | 고를 것 | 추천 |
| --- | --- | --- | --- | --- |
| Q5 | Details 4 Sample Location | Trolley Name과 Trolley ID 중 무엇으로 통일할지 | Name / ID | ID (Inventory 화면이 ID) |

**변경 확인 — 맞는지만 봐 주실 것**

| 번호 | 화면 · 위치 | 기존 | 바꿔 그린 것 | 근거 | 고를 것 |
| --- | --- | --- | --- | --- | --- |
| C4 | Samples 1-5 Status | Ready, Not Tested, Running … | Ready, Running, Completed, Failed, Not Tested | 상태값 표 순서 | 맞음 / 되돌림 |

- 고를 것은 되도록 둘로 적습니다. 추천은 근거가 있을 때만 적고, 없으면 비웁니다.
- 논의 대상으로 올린 질문은 논의 대상 ID를 "화면 · 위치" 칸에 함께 적습니다.
- 이 목록은 4단계(검토)의 요청자 확인에서 그대로 씁니다.

## 끝 관문

기계 검사입니다. 하나라도 통과하지 못하면 이 단계 안에서 고칩니다. 빨간 글씨 질문 대기가 남아도 그리기는 끝까지 하고, 남은 질문은 4단계 요청자 확인으로 넘깁니다.

| # | 검사 | 보는 것 |
| --- | --- | --- |
| 1 | 짝 CID | 1단계 화면 목록의 CID가 T · L 모두 화면 MD와 Figma 섹션으로 있음 |
| 2 | 화면 MD 틀 | `templates/screen.md`의 절이 모두 있음 |
| 3 | 화면 MD = Figma | 디스크립션 · 번호 · 예시 값이 같음 |
| 4 | 행 수 | 목록 행 수가 디스크립션의 노출 개수와 같음 (줄였으면 이유가 있음) |
| 5 | 케이스 화면 | 화면 MD 케이스 표, Figma의 Case, 디스크립션의 `참고 : CID/Case > Case n` 줄이 서로 1:1로 맞음. 표의 줄마다 근거(기존 원본 · 디스크립션 조건 · 요청자)가 있음. 기존 원본의 케이스가 빠지지 않음 |
| 6 | 빨간 글씨 | 빨간 글씨마다 번호(Q · C)가 있고, 같은 번호가 디스크립션 · 화면 · 화면 MD 표 · 작업 기록 표에 모두 있음. `※ 질문 대기` 줄 · 화면 MD 질문 대기 표 · 작업 기록 질문 대기가 1:1. `※ 변경 확인` 줄 · 화면 MD 변경 확인 표 · 작업 기록 변경 확인이 1:1. 1단계 "확인할 것"의 줄마다 이어진 번호가 적혀 있음. 2단계 대조에서 "기존 화면이 정책과 다름"으로 나온 곳마다 변경 확인이 있음 |
| 7 | 컴포넌트 | 가이드 컴포넌트를 떼어 내지 않고 인스턴스로 씀 |
| 8 | 예시 데이터 | 화면의 상태값 · Module · 품목 · 수량이 화면 예시 표 · 기준데이터 값임 |
| 9 | 용어 | 쓰지 않는 표현이 남지 않음 (단어 단위) |
| 10 | 반영 대기 | 1단계에서 고른 항목(`작업 중`)만 반영했고, 고르지 않은 항목은 `대기` 그대로임. 이 단계에서 `반영 완료`로 바꾼 줄이 없음. 화면 MD를 새 틀로 다시 썼으면 다시 쓰기 전과 뒤의 항목 수 · 항목 ID가 같음(`reference-rules/pending-changes.md` 6절) |
| 11 | 글자 넘침 | 기획 프레임 · 케이스 프레임 · 패널의 모든 글자가 자기 칸 안에 있음(넘침 · 잘림 · 겹침 없음). 글자 노드의 영역이 부모 칸 안에 있는지 확인하고, 스크린샷으로 한 번 더 봄 |
| 12 | 작업방 구성 | 섹션 이름 · 프레임 이름 · 섹션 안 순서 · 기획 프레임 너비 2252 · 패널 너비 332가 "신규 작업방 구성"과 같음 |

- 정책과 맞는지, 디스크립션이 읽는 사람 말투로 완결인지처럼 **판단이 필요한 점검은 4단계(검토)**에서 합니다.

- 스크립트: 화면 MD 틀 검사, 용어 점검(단어 단위), 질문 대기 1:1 검사 — 나중에 만듦

## 하지 않는 것

- 2단계 관문을 통과하기 전에 그리기
- 가이드에 있는 요소를 직접 그리거나 컴포넌트를 떼어 내기
- 기준데이터에 있는 값(상태값 · Module · 품목 · 수량)을 지어 쓰기
- 한쪽 CID만 그리고 끝내기, 기획 프레임만 그리고 케이스 표에 있는 케이스 화면을 미루기
- 근거 없는 케이스를 판단으로 더하기, 케이스에서 늘 보이는 항목을 지우기, 기획 화면 전체를 복제해 값만 바꾸기(달라지는 부분만 그림)
- 질문이 있다고 그 부분을 그리지 않거나 디스크립션에서 빼기
- 출처 없는 내용을 검은 글씨로 확정처럼 쓰기
- 고르지 않은 반영 대기 항목을 반영하기, "반영 대기"로 고른 다른 화면을 고치기
- 같은 페이지의 기존 그림을 옮기거나 지우기
- 기존 화면을 참고할 때 디자인 화면(디자인 프레임 · 디자인 파일)에서 모양이나 내용을 가져오기. 기존 화면은 UX 화면설계서(기획 프레임과 디스크립션)만 근거로 씀
- 기존 화면과 다르게 그리고도 `※ 변경 확인`을 두지 않기
- 글자가 칸을 넘거나 잘린 채로 끝내기, 넘친다고 글자 크기를 줄이기
