# 5. 완료

> 초안 · v0.3

**목적:** 화면이 확정된(UX 확정 · UI 확정) 뒤, 그 결과에 따라 문서에 업데이트할 것을 정리해 IA · 반영 대기 항목 · User Type과 L-IOS Client Mode 표 · 정책서 · 언어셋에 넣고, 이번 작업의 결과를 남기는 단계입니다. 화면에 반영된 것을 고치는 단계가 아닙니다. 흐름은 여기서 끝납니다.

**목표:** 정보를 절차대로 업데이트하고, 아래 "마침 점검"을 통과한 뒤 작업 기록을 `status: 끝남`으로 닫습니다.

## 절차

| 순서 | 하는 일 | 요청자 확인 |
| --- | --- | --- |
| 1 | 최종 확인: 이번 작업 결과를 모아 보고함 (CID, 반영 대기 항목, 이 작업의 결정, User Type · L-IOS Client Mode, 언어셋 요약, 끝난 방식) | 없음 (보여 주기만 함) |
| 2 | 정보 업데이트: IA · 반영 대기 항목 · User Type과 L-IOS Client Mode 표 · 정책서 · 언어셋. 끝에 모아 둔 질문을 묻고 답대로 업데이트 | 모아 둔 질문이 있을 때만, 업데이트를 마친 뒤 받음 |
| 3 | 최종 검토 후 작업 기록을 닫음 | 없음 (마침 점검에서 판단이 필요한 것이 나올 때만 받음) |

- 4단계 마침 점검을 통과한 뒤에 시작합니다(작업 기록 "단계" 표 4단계 줄의 "마침 점검" 칸 `통과 (날짜)`). 1단계에서 끝나는 작업은 절차 3번만 합니다(아래 "작업 기록에 쓰는 것"의 "끝나는 방식").
- **스스로 판단해 업데이트하지 않습니다.** 작업 기록 · 확정된 화면 MD · 논의 대상에 적힌 것만 옮깁니다. 적힌 것으로 정할 수 없거나 문서끼리 부딪치면, 그 업데이트는 하지 않고 작업 기록 "모아 둔 질문"에 적은 뒤 다른 업데이트를 이어 갑니다(`flow/README.md` "단계를 지나는 규칙" 9). 모아 둔 질문은 절차 2번 순서 7에서 한 번에 묻습니다.
- 할 일이 없는 순서는 "해당 없음 (이유)"로 지나갑니다. 예: 정책만 바뀐 작업은 IA · 언어셋이 해당 없음, 케이스 3만 있는 작업은 결정이 없으면 정책서가 해당 없음.
- 요청 전체를 반영하지 않기로 한 작업(4단계 절차 6번에서 원본을 되돌림)은 이 작업의 반영 대기 항목만 `대기`로 되돌리고(절차 2번 순서 2) 절차 3번으로 갑니다.
- 테스트로 하는 작업(`test: true`)은 순서는 그대로 하고 저장소 밖에만 남깁니다(`flow/README.md` "테스트로 할 때"). IA · 반영 대기 상태 · 논의 대상 · User Type과 L-IOS Client Mode 표 · 정책서 · 언어셋 원본은 고치지 않습니다.

### 1) 최종 확인

**순서**

1. **이 작업의 결정을 확인합니다.** 작업 기록 "이 작업의 결정" 표와, `work`에 이 작업 기록 이름이 적힌 `결정` 논의 대상이 같은지 봅니다. 다르면 논의 대상이 원본이므로 표를 논의 대상에 맞춥니다. 결정마다 `reference-rules/discussions.md` 6절 "결정 반영 순서"의 1 · 2(확인 · 영향 화면 찾기)를 합니다. 결정 문장이나 정한 사람이 없으면 "모아 둔 질문"에 적습니다.
2. **반영 대기 항목을 정리합니다.**
   - 이 작업의 대상 화면: 반영 대기 목록에서 상태가 `작업 중 (이 작업 기록 이름)`인 항목
   - 영향 화면: 작업 기록 "영향 화면" 표의 화면마다 바뀌는 곳(변경 전 · 변경 후). 영향 화면은 고치지 않고 모두 반영 대기 항목으로 남깁니다(`reference-rules/pending-changes.md` 1절). 결정에서 온 것은 그 결정의 논의 대상 ID를, 결정 없이 이 작업의 화면을 고쳐 맞춰야 하는 것은 원인 CID를 근거로 둡니다.
   - 그 화면이 다른 작업에서 이미 UI 확정(UI 작업이 없으면 UX 확정)까지 마친 화면이면 그 화면을 어떻게 둘지 "모아 둔 질문"에 적습니다.
3. **CID를 모읍니다.** 이 작업에서 붙인 새 CID(1단계 절차 4번 순서 4, 3단계에서 더 붙인 것)와 짝 CID, 이 작업에서 바뀐 IA 내용(메뉴 이름 · 화면 이름 · Type 등)을 작업 기록 "요건 목록" · 화면 MD에서 모읍니다. IA에 넣을 칸(앱 · Lv.1 ~ Lv.6 · Type · CID · 짝 CID)을 채울 수 없으면 "모아 둔 질문"에 적습니다.
4. **User Type · L-IOS Client Mode를 모읍니다.** 새 화면의 User Type · L-IOS Client Mode(4단계에서 답을 받아 화면 MD에 채운 값)가 `policy/permission-matrix.csv` · `policy/client-mode-matrix.csv`에 없는 메뉴 · 기능이면 더할 줄을 모읍니다.
5. **언어셋을 요약합니다.** 작업 기록 "언어셋" 절의 줄을 상태(신규 · 변경 · 제거 · 추가 (언어셋에 없음) · 언어셋에만 있음)별 개수로 모읍니다. `추가 (언어셋에 없음)` · `언어셋에만 있음`이 있으면 "고객에게 줄 언어셋 문서에 추가 · 삭제가 생김 (엑셀로 뽑아 전달)"을 한 줄 덧붙입니다.
6. **끝난 방식을 정합니다.** 작업 기록 "요건 목록"대로 아래 "작업 기록에 쓰는 것"의 "끝나는 방식"에서 고릅니다. 요건마다 끝난 방식이 다르면 요건이 하나라도 반영됐으면 `반영` 또는 `바뀌어 반영`으로 적고, 반영하지 않은 요건과 이유를 "요건 목록" 비고에 적습니다. 어느 것인지 정할 수 없으면 "모아 둔 질문"에 적습니다.
7. **보고합니다.** 순서 1 ~ 6을 표 하나로 보여 주고, 기다리지 않고 절차 2번으로 갑니다.

### 2) 정보 업데이트

절차 1번에서 모은 대로 넣습니다. "모아 둔 질문"에 걸린 것은 넣지 않고 두었다가 순서 7에서 답을 받은 뒤 넣습니다.

**순서**

1. **IA:** 새 CID와 바뀐 IA 내용을 `ia/ia-screens.csv`에 넣습니다(IA의 원본, `ia/README.md`). 넣은 것마다 `ia/change-requests.md`에 한 줄을 적습니다(상태 `반영 (날짜)`, 근거에 작업 기록 이름 · 요청자). 화면 MD · Figma의 CID가 작업 기록과 다르면 고치지 않고 "모아 둔 질문"에 적습니다.
2. **반영 대기 항목:**
   - 이 작업의 대상 화면: `작업 중 (이 작업 기록 이름)`인 항목을 `반영 완료 (날짜)`로 바꾸고, 그 화면 변경 이력에 반영한 항목 ID를 적습니다(`reference-rules/pending-changes.md` 4절). 요청을 반영하지 않고 끝나면 `대기`로 되돌립니다.
   - 영향 화면: 결정에서 온 것은 `reference-rules/discussions.md` 6절 "결정 반영 순서" 5로, 결정 없이 이 작업의 화면 때문에 맞춰야 하는 것은 타입 `다른 화면 파급`(근거 칸에 원인 CID)으로 그 화면 MD 반영 대기 목록에 항목을 만듭니다(`reference-rules/pending-changes.md` 2 · 3절). 작업 기록 "영향 화면" 표의 처리 칸에 `반영 대기 (항목 ID)`를 기입합니다.
3. **User Type · L-IOS Client Mode:** 절차 1번 순서 4에서 모은 줄을 `policy/permission-matrix.csv` · `policy/client-mode-matrix.csv`에 더합니다. 논의 대상은 만들지 않습니다. 새 메뉴라 모드별 LNB(Common UX COMM-3-a)도 바뀌어야 하면 Common UX는 고치지 않고 "모아 둔 질문"에 적습니다.
4. **정책:** 이 작업의 결정마다 `reference-rules/discussions.md` 6절 "결정 반영 순서"의 4 · 6 · 7(정책서 · 닫기 · 보고)을 합니다. 정책서에 반영한 뒤 이 작업에서 고친 화면 MD 머리말에 적어 둔 그 논의 대상 ID(`POL-EQP-004 · DS-0012`의 `DS-0012`, `flow/3-design.md` 공통 1의 6)를 뗍니다. 정리안(같은 절 3)은 절차 1번 보고로 보여 준 것으로 하고 확인을 기다리지 않습니다.
5. **언어셋:** 작업 기록 "언어셋" 절의 줄을 언어셋 원본(`language-set/db/`)에 반영하고 화면 MD "화면 표기 글자" 표를 맞춥니다. 하는 법은 `language-set/README.md` "고치는 법"과 "화면설계 흐름에서 반영하는 법"입니다. 원본을 고치지 못하는 동안(`language-set/README.md` "고치는 법" 머리)은 반영하지 않고 그 줄에 `새 버전 받은 뒤 반영`을 적습니다.
6. **Common UX:** 지금은 하지 않습니다. 후보를 올리는 기반이 준비되면 이 순서에 넣습니다(`common-ux/candidate-rules.md`).
7. **모아 둔 질문이 있으면 묻습니다.** 절차 1번과 이 절차에서 생겨 답이 비어 있는 줄을 한 번에 보여 주고(`reference-rules/work-log.md` "요청자에게 보여 주는 법" 5번), 답을 "모아 둔 질문"에 기입한 뒤 답대로 걸려 있던 업데이트(순서 1 ~ 5)를 합니다. 없으면 묻지 않고 절차 3번으로 갑니다.

### 3) 최종 검토 후 작업 기록을 닫음

**순서**

1. **마침 점검을 합니다**(아래 "마침 점검"). 작업 기록과 절차 2번에서 고친 문서를 대어 봅니다. 통과하지 못한 것은 작업 기록 · 논의 대상에 적힌 대로 고치고 다시 점검합니다. 적힌 것으로 고칠 수 없어 판단이 필요한 것만 그때 묻고, 답을 "모아 둔 질문"에 기입한 뒤 고쳐 다시 점검합니다.
2. **기입합니다.** 작업 기록 "단계" 표 5단계 줄의 "끝낸 날"과 "마침 점검" 칸에 `통과 (날짜)`, "남긴 것"에 끝난 방식을 적습니다. "이 작업이 남긴 것" 절(논의 대상 · 다른 화면의 반영 대기 항목)을 채우고, 머리말 `status`를 `끝남`으로 바꿉니다. `이어서 작업할 곳:` 줄을 `5단계 · 끝남 (날짜)`로 고칩니다.
3. **보고합니다.** 절차 2번에서 고친 문서(IA에 넣은 줄, 만든 · 바꾼 반영 대기 항목, User Type · L-IOS Client Mode 표에 더한 줄, 정책 문장, 언어셋에 반영한 줄과 반영하지 못한 줄)를 표로 보여 줍니다.

## 작업 기록에 쓰는 것

5단계가 작업 기록(`reference-rules/work-log.md` "틀")에 쓰는 곳입니다.

| 작업 기록의 절 · 칸 | 쓰는 것 | 절차 |
| --- | --- | --- |
| "이 작업의 결정" | 논의 대상과 다르면 논의 대상에 맞춤 | 1 |
| "요건 목록" | 반영하지 않은 요건의 비고에 이유 | 1 |
| "영향 화면" | 처리 칸에 `반영 대기 (항목 ID)` | 2 |
| "언어셋" | 원본을 고치지 못하는 동안 반영할 줄에 `새 버전 받은 뒤 반영` | 2 |
| "모아 둔 질문" | 생긴 질문과 답 | 1 ~ 3 |
| "단계" 표 5단계 줄 | "끝낸 날" · "마침 점검"에 `통과 (날짜)`, "남긴 것"에 끝난 방식(아래 "끝나는 방식") | 3 |
| "이 작업이 남긴 것" | 논의 대상, 다른 화면의 반영 대기 항목 | 3 |
| 머리말 `status` | `끝남` | 3 |
| `이어서 작업할 곳:` 줄 | `5단계 · 끝남 (날짜)` | 3 |

**끝나는 방식** ("단계" 표 5단계 줄의 "남긴 것"에 하나를 적음)

| 끝난 방식 | 적는 말 |
| --- | --- |
| 요청대로 끝남 | 반영 |
| 요청이 바뀐 채로 끝남 | 바뀌어 반영 |
| 기존 화면을 그대로 둠 | 반영 안 함 (이유). 이미 반영돼 1단계에서 종료하면 `반영 안 함 (이미 반영됨)` |
| 정책만 바뀌고 화면은 그대로 | 정책만 반영 |
| 진행 중인 다른 작업과 같은 요청이라 그 작업으로 이어 감 | 기존 작업으로 이어 감 (작업 기록 이름) |

- 1단계에서 끝나는 두 경우(`반영 안 함 (이미 반영됨)`, `기존 작업으로 이어 감`)는 `flow/1-requirements.md` 절차 2번 순서 6과 절차 4번 순서 2에서 정해집니다. 이때는 절차 3번만 합니다.

## 마침 점검

작업 기록을 닫기 전에 모두 통과해야 합니다(절차 3번 순서 1).

- 작업 기록 "단계" 표 1 ~ 4단계 줄마다 "마침 점검" 칸이 채워져 있음(1단계에서 끝난 작업은 2 ~ 4단계 줄이 `해당 없음 (이유)`)
- 새 CID와 바뀐 IA 내용이 모두 `ia/ia-screens.csv`에 있고, 줄마다 `ia/change-requests.md`에 `반영 (날짜)` 기록이 있음
- 대상 화면의 반영 대기 목록에 `작업 중 (이 작업 기록 이름)`인 항목이 없음
- "영향 화면" 표의 화면마다 처리 칸이 채워져 있고, 적힌 항목 ID가 그 화면 MD 반영 대기 목록에 있음
- 절차 1번 순서 4에서 모은 줄이 User Type · L-IOS Client Mode 표에 있음
- "이 작업의 결정" 표의 결정마다 논의 대상이 `종료`이고 6절 "반영"이 채워져 있음. `work`에 이 작업 기록 이름이 적힌 `논의 중` 논의 대상이 없음("후속 확인 필요" 줄은 남아도 됨)
- "언어셋" 절의 줄마다 언어셋 원본에 반영됐거나 `새 버전 받은 뒤 반영`이 적혀 있음
- 작업 기록 "모아 둔 질문"에 답이 비어 있는 줄이 없음
