# 3. 화면 설계 — 케이스 1 흐름: 화면 부분 수정(고도화)

> 3단계 문서 `flow/3-design.md`의 케이스 1 부분입니다. 버전은 `flow/3-design.md`를 따릅니다. 이 문서의 `공통 …`(예: `공통 3-10`), "절차 n번", "마침 점검 n", "남는 것"은 모두 `flow/3-design.md`의 그 자리를 가리킵니다.

## 흐름

이미 있는 화면(T · L 모두)을 요청에 따라 일부 고칩니다. 고칠 범위는 1 · 2단계에서 정해져 옵니다.

| 순서 | 할 일 | 자세히 |
| --- | --- | --- |
| 1 | 작업 기록 "설계" 절 "화면별 작업" 표에서 이 화면의 줄(케이스 1 · 요건 번호)을 확인함 (줄 만들기와 "읽을 것" 읽기는 절차 1번) | |
| 2 | **T 화면 MD를 먼저 고침** | 아래 1-2 |
| 3 | 바뀐 곳마다 변경 확인을 둠 | 아래 1-3 |
| 4 | **Figma를 열어 복제본을 만들고 T 원본을 고침** | 아래 1-4 |
| 5 | 같은 CID의 케이스 화면을 함께 고침 | 아래 1-5 |
| 6 | **요건 목록에서 작업 대상이 `O`인 짝 화면(L)에** 같은 순서로 고침 (2 ~ 5) | 아래 1-6 |
| 7 | 마무리 확인 (T · L 한 쌍), 작업 기록 `이어서 작업할 곳:` 고침 | `공통 3-10` |
| 8 | 모든 화면(CID)을 그렸으면 절차 3번으로, 남은 화면이 있으면 그 화면의 케이스 흐름으로 감 | |

**1-2. 화면 MD 고치기**

- `templates/screen.md` 구조를 그대로 씁니다(절을 빼거나 더하지 않음).
- **직전 버전의 빨간 표시:** 화면 MD를 고치기 전에 직전 버전의 바뀐 글 표시를 되돌립니다. 빨간 글씨 태그(`<span style="color:red">`)는 떼어 검정 글자로, 빨간 취소선은 `~~글자~~`로 둡니다. 그 뒤 이 작업에서 고치거나 더한 글자는 빨간 태그로 씁니다(`reference-rules/description.md` 7절 "바뀐 글 표시").
- 1 · 2단계에서 넘어온 것(작업 기록 "요건 목록"에서 작업 대상이 `O`인 줄의 요건, "뒤 단계용 확인 항목(claude)", 2단계 대조 결과)만 고칩니다. 고칠 범위는 1 · 2단계에서 정해져 오므로 3단계에서 따로 넓히지 않습니다.
- 기존 화면에 바로 고치며(시안을 따로 만들지 않음, 복제본은 1-4), 확정을 기다리지 않고 수정안이 바뀔 때마다 디스크립션을 화면과 함께 고칩니다.
- 디스크립션 · 케이스 · Alert · Confirm · Toast 표 · 화면 예시 글자 · 반영 대기 · 작업 중 결정 · Common UX 요소는 `공통 1`대로 씁니다. 화면 표기 글자 표는 3단계에서 적지 않습니다(`공통 1`의 9).
- **번호:** 있던 번호는 바꾸지 않습니다. 요소를 **더하면 끝 번호**를 붙입니다. 단독 기능이면 화면의 맨 끝 번호 다음, 이미 번호가 있는 영역에 속하는 기능이면 그 영역의 맨 끝 번호 다음이며, 화면에서 놓이는 위치와 상관없습니다. 요소를 **제거하면** 번호를 그대로 두고(디스크립션은 그 번호의 블록을 지우지 않고 취소선, "제거된 요소"), 그 번호는 새 요소에 다시 쓰지 않습니다. 번호를 화면 순서대로 다시 매기는 때는 아직 정하지 않았습니다(`background/todo.md` 6 "보류"의 "기존 화면을 고친 뒤 취소선 정리와 번호 다시 매기기"). 예(TI-SPT-01 Samples, 지금 1 검색 영역 1-1 ~ 1-6 · 2 리스트 · 3 [Export] · 4 페이지네이션): 검색 영역에 Sample Type 조건을 더하면 1-7 / 리스트 위에 [Print] 버튼을 더하면 5 / STAT Only를 빼면 1-6은 번호와 글을 그대로 둠
- 변경 종류마다 디스크립션은 아래 1-3 표의 "디스크립션" 칸대로 처리합니다.

**1-3. 변경 확인**

바뀐 곳마다 변경 확인을 둡니다(번호 · 사용자 확인 라벨 · 사용자 확인 목록 · 작업 기록 표는 `공통 2`). 업데이트 메모 제목은 `v{Ver} update`(Ver은 4단계 UX 확정 때 요청자가 정함, `reference-rules/description.md` 7절 "화면 정보에 적는 값", 색은 `reference-rules/description.md` 5절 "업데이트 메모"의 색 규칙).

| 변경 | 디스크립션 | 사용자 확인 목록 문구 | 사용자 확인 라벨 |
| --- | --- | --- | --- |
| 더함 | 새 번호로 씀 | `{요소} 추가 (이유)` | 그 번호 표시 옆 |
| 바꿈 | 그 번호의 글을 고침 | `{기존} → {바꾼 것} (이유)` | 그 번호 표시 옆 |
| 제거 | 글을 지우지 않고 **3단계에서 바로 빨간 취소선**을 그음(개발자가 지운 것을 알 수 있게) | `화면에서 제거, 확정 시 취소선 처리 예정 (이유)` | **두지 않음.** 화면에서 요소와 번호 표시를 떼므로 사용자 확인 목록에만 둠 |
| 케이스를 지움 | 제거된 요소 때문에 필요 없어진 케이스는 바로 지움 | 본 화면 사용자 확인 목록 문구 끝에 `… Case n 삭제` | 케이스 조각에는 두지 않음 |

- 4단계에서 확인된 뒤의 처리는 `공통 2`대로 합니다. 제거된 요소의 취소선 디스크립션은 지우지 않고 남깁니다.
- 고객 논의로 제거된 요소가 되살아나면 취소선과 Figma의 사용자 확인 목록 항목을 지우고 화면에 요소를 다시 넣습니다.
- 정해지지 않은 곳은 질문 대기(`공통 2`)입니다.

**1-4. Figma: 복제본을 만들고 원본을 고침**

- **복제본:** 원본을 고치기 직전에 원본의 복제본을 하나 만들어 두고, 고치는 것은 원본에 바로 합니다(고객 요청으로 원복하는 경우가 있음). T · L 각각 만듭니다.
  - 이름은 `CID-복제본`(예: `TI-SPT-01-복제본`), 위치는 원본 아래 200px입니다. 원본 높이가 바뀌면 복제본을 다시 원본 아래 200px로 옮깁니다(위치는 Figma 구조를 확인한 뒤 다시 정함, `background/todo.md` 3-8).
  - 4단계(수정 · 확인)가 끝나면 지웁니다.
  - 복제본은 바탕 · 후보 · 화면 MD 추출의 근거로 쓰지 않습니다.
- **직전 버전의 빨간 표시:** 복제본을 만든 직후, 원본을 고치기 전에 원본 패널의 빨간 글씨를 검정으로(코드는 파란색, `reference-rules/description.md` 7절 "참고 코드 표시"), 빨간 취소선을 검은 취소선으로 되돌립니다. 그 뒤 이 작업에서 고치거나 더한 글자는 빨간색, 제거된 요소와 제거된 문구는 빨간 취소선으로 씁니다(`reference-rules/description.md` 7절 "바뀐 글 표시").
- 화면 MD를 그대로 옮기며, 바뀌는 요소만 건드립니다. 컴포넌트 · 화면 예시 글자 · 번호 표시 · 질문 표시는 `공통 3`대로 합니다.
- 더하는 요소는 `공통 3-3`의 **"케이스 1 · 2" 표** 순서로 찾아 그립니다(Common UX 컴포넌트 → 후보 → 신규로 만듦).
- 더한 요소에는 1-2의 끝 번호로 번호 표시를 붙이고, 바꾼 요소는 번호 표시를 그대로 두며, 제거된 요소는 요소와 번호 표시를 뗍니다.
- **패널:** `공통 3-6`대로 옮기고, 화면 정보의 Date는 작성일, 작성자는 요청자. Ver은 4단계 UX 확정 때 요청자가 정해 기입함(그 전까지 기존 화면의 Ver 그대로, `reference-rules/description.md` 7절 "화면 정보에 적는 값").

**1-5. 케이스 화면 함께 고치기**

본 화면을 고치면 같은 CID의 케이스 화면도 함께 고칩니다(케이스 화면 공통 규칙은 `공통 5`).

1. 고칠 케이스는 화면 MD 케이스 블록 머리 줄의 "디스크립션 번호"로 찾고, 그 CID의 케이스 조각을 모두 훑어 고친 요소가 그려져 있는지도 봅니다.
2. 더한 요소의 그 조건에서의 값을 모르면 요청 · 정책에 있는 값, 없으면 본 화면의 화면 예시 글자와 같은 값을 넣고 질문 대기를 둡니다.
3. 제거된 요소 때문에 필요 없어진 케이스는 확정을 기다리지 않고 바로 지우고, 그 케이스 블록 머리 줄 아래에 `- 지움 (날짜, 이유)` 줄을 남깁니다(블록은 지우지 않고, 그 Case 번호는 다시 쓰지 않음).
4. 케이스 조각에서 생긴 질문 · 변경은 그 조각의 번호 표시 옆에 사용자 확인 라벨을 두고, 사용자 확인 목록 항목은 본 화면의 사용자 확인 목록에 둡니다. 본 화면 변경이 케이스에도 걸리면 사용자 확인 목록 문구에 걸린 케이스를 적습니다(예: `… Case 1 · 3에도 반영`, `… Case 2 삭제`).

**1-6. L 화면**

요건 목록에서 짝 화면(L)의 작업 대상이 `O`이면, L 화면이 이미 있으므로 T를 복제하지 않고, L 원본의 복제본을 만든 뒤 T와 같은 순서(화면 MD → 변경 확인 → Figma → 패널 → 케이스 화면)로 L 화면을 고칩니다. L 디스크립션이 T를 가리키는 말 없이 완결인지 확인합니다. T · L 번호는 따로 관리합니다(`공통 3-7`).
