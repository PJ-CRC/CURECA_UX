## T01 Prep 장비 Tub 정책 추가

```text
정책 변경 반영 
* Prep 장비 소모품 중 Tub 관련 정책 추가
   * Trolley를 통해 입고되는 Tub도 Buffer Cartridge와 동일하게 1회 사용 후 여분 Cap을 추가로 장착해야 재사용이 가능한 구조
   * 입고된 상태에서 재사용 시나리오 적용
      * 재사용을 위해 Trolley로 반환한 후 Event 메시지를 통해 Cap보충 안내를 하고, Cap을 보충할 수 있는 시나리오 적용.
```

## T03 Cold Storage 시약 이동 방식

```text
* Cold Storage 시약 이동 방식 추가 확인
   * 기존: 내부에 1개의 PCR 소켓만 적재하여 사용하는 방식(다른 PCR 시약이 필요할 경우, 갖고 간 PCR 시약을 다시 스토리지로 반환 후 다른 PCR 소켓을 갖고 가는 방식)
   * 변경
      * 내부 STArlet장비에 Tube 거치 rack이 있어, PCR 소켓을 갖고가서 Tube의 뚜껑을 열어 뚜껑은 소켓에 거치하고 Tube만 빼서 STArlet 장비에 거치하고 뚜껑만 있는 상태로 스토리지로 반환함
      * 사용 후 폐기 또는 리턴을 위해 뚜껑이 거치된 해당 PCR 소켓을 다시 갖고 가서 Tube 뚜껑을 디캡핑하여 Tube만 폐기하고 빈소켓은 반환, 또는 사용 후 남았으면 Tube를 꽂아서 반환
      * Cold Storage 오픈 시, 아래의 상태값에 따라 판단 가능
         * Tube가 없는 소켓 = 사용완료된 소켓
         * Tube Cap만 있는 소켓 = 현재 내부에서 사용 중으로 소켓 절대 제거 불가
         * Tube가 있는 소켓 = 신규 또는 잔여 사용량이 남은 시약의 소켓(Remove 기능으로 제거 가능)
```

## T04 트롤리 리셋 정책

```text
[트롤리 리셋 정책]
* 검체 트롤리
   * Rack 단위(검체 소켓 단위)
      * 회수 트롤리로 이동 완료된 시점
         * 리셋 범위
            * Rack 리셋 범위: 소켓 내 검체 값 / 소켓이 꽂혀 있던 트레이 위치 값
   * Tray 단위
      * 투입 트롤리 내 마지막 검체 Rack이 회수 트롤리로 이동 완료된 시점
         * 리셋 범위
            * Tray 리셋 범위: Tray에 연결된 트롤리 정보 값
   * 트롤리 단위
      * 트롤리 내 마지막 트레이 값이 리셋된 시점(모든 검체가 회수 트롤리로 이동이 완료된 상태)
      * 트롤리 내 1개의 검체 Rack 존재할 경우, 해당 검체가 있는 tray와 트롤리의 값이 리셋되지 않았기 때문에 계속해서 사용 중인 트롤리로 간주됨
* 소모품 트롤리
   * Rack 단위
      * Rack(또는 입고 단위)에 구성된 모든 소모품(또는 시약)이 모두 소진된 시점
(모두 소진되지 않고 트레이로 리턴됐을 경우는 리셋대상아님)
         * 리셋 단위: Rack이 꽂혀있던 트레이 위치값
   * Tray 단위
      * 트레이 내 마지막 소모품 Rack이 전처리 장비에서 모두 사용완료되어 트레이 위치값이 제거된 시점
         * 리셋 범위
            * Tray 리셋 범위: Tray에 연결된 트롤리 정보 값
   * 트롤리 단위
      * 트롤리 내 마지막 트레이 값이 리셋된 시점(모든 소모품이 소진 완료된 상태)
      * 검체 트롤리와 마찬가지로 트롤리 내 아직 소진되지 않은 소모품이 있을 경우, 사용 중인 트롤리로 간주되며 새로 작업 시, 신규 작업 여부를 문의 후 작업할 수 있도록 적용 예정

* 모든 정보를 이어서 작업할 수 있는 방향으로 잡아서, 기존에 트레이나 트롤리에 연결되어 있는 값들을 지우기 위해서 각 구성하는 메뉴로 들어가서 'remove(구. delete)'로 제거 후 사용하는 방향이 유저의 불편함을 유발할 수 있어 관련해서 기존에 다른 곳에 물려있는 데이터가 있거나 그 자리에 현재 점유중인 소모품이 있을 경우, 알럿으로 현재 스캔한 정보로 업데이트할 것인지에 대한 확인을 받고 바로 변경해서 작업하도록 적용
```

## T11 Buffer Cartridge Storage 정책

```text
[Buffer Cartridge Storage 정책]
* 속성
   * 여분의 Cap과 함께 입고
   * 최초 사용 후 시약이 남았을 경우, 다시 여분의 Cap으로 닫고 Storage로 반환
   * 사용 완료된 경우, Tub는 자동으로 폐기함으로 버려지고 트레이(소켓)은 입고된 위치로 반환됨
      * 유효기간 지난 것 또는 사용횟수가 초과한 것은 자동폐기 후 트레이만 반환
   * 트레이(소켓)은 재활용 대상
   * 최초 입고 후 1회 사용 후 다시 사용자가 여분의 Cap을 장착해줘야 재사용이 가능
* 시나리오
   * 사람: Tub 및 위치값 스캔 후 스토리지 적재
      * 트레이만 있을 경우, 제거 후 새로운 시약 적재
      * 트레이에 Tub는 있고 여분의 Cap이 없을 경우 Cap 보충
      * 비어 있는 경우, 위치 스캔을 통해 buffer공간에서 사용 중인 시약의 자리일 경우, 적재 못하게 알럿 노출. 미사용 공간이면 적재 가능
   * 장비
      * 일부 시약이 남아 재사용을 위해 다시 스토리지로 반환하면 Cap 보충 Event message 발생시켜 유저에게 인지 시킴
      * 실수로 cap보충하지 않고 장비가 사용할 때, cap이 없는 것을 알고 장비 멈춤 및 Event Message 발생하여 cap 보충해달라고 요청함
      * 카트리지 tub 사용의 특성은 남아도 cap닫아서 스토리지로 반화해야하고 다 사용해도 cap을 닫아서 폐기해야하기 때문에 반드시 cap이 있는 상태로 스토리지에서 장비로 이동되어야함. 폐기할때도 cap이 없으면 에러가 발생되어 장비가 멈춤
   * 캡 보충 후 머터리얼 셋업에서 cap보충 완료 버튼을 눌르면 장비가 인식하여 다시 사용할 수 있는 것을 인지하고 다시 가져가서 사용 진행
```
