## 제안 내용

작업자가 Figma에서 화면설계서 상태(UX · UI)를 어떻게 표시하고 관리할지 팀원과 정합니다. 정해지면 Figma 상태 → 메뉴 상태 → 일정 시트 상태 자동 연결(`old-rules/schedule.md` 4절)을 다시 이어 갑니다. 그때까지 자동 연결은 보류합니다(2026-11-04 사용자 결정).

논의할 것:

1. 상태를 표시하는 단위: 2단 메뉴(3.메뉴 탭 값) / 화면(CID) / 지금처럼 페이지 · 영역
2. 표시 방법: 정해진 컴포넌트(상태 카드) / 화면 정보 칸 / 페이지 · 영역 이름이나 색
3. 묶음 메뉴(`Material Setup - ALL`, `All`, `Common/정책`, `Run/Quick Start`) 줄을 자동으로 따라가게 할지, 손으로 관리할지
4. 지금 Figma에서 UX · UI 상태를 실제로 어디에 어떻게 적고 있는지 (기존 방식에서 옮겨 가는 방법)

Claude 추천안 (2026-11-04):

| 방법 | 장점 | 단점 |
| --- | --- | --- |
| A. 메뉴 상태 카드: 팀 라이브러리 컴포넌트 하나, 2단 메뉴마다 카드 하나. 메뉴는 3.메뉴 값 그대로, UX · UI 상태는 변형(variant)에서 고름 (추천) | 시트 줄과 1:1, 카드 수가 적음, 프로그램 · Claude가 정확히 읽음, 오타 없음 | 메뉴 안에서 화면별 상태 차이는 못 봄 |
| B. 화면(CID)마다 화면 정보에 상태 | 가장 자세함 | 화면이 약 190개라 바꿀 곳이 많고, 메뉴 상태로 모으는 규칙이 필요 |
| C. 지금처럼 페이지 · 영역 이름이나 색 | 바꿀 것이 없음 | 읽기 불안정, 표기가 흔들리면 놓침 |

## 이유와 근거

- 일정 시트(2-2.WBS 연동)는 메뉴를 2단(`Setting - SMTP Setting`)까지 적고, 저장소 메뉴 상태(`_menu.md`)는 1단 단위라 연결 단위가 맞지 않음
- 지금 Figma 상태 표시 방식은 프로그램과 Claude가 읽기에 안정적이지 않음 (사용자 의견, 2026-11-04)
