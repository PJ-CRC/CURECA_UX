## 칸

**메뉴 파일 (`db/{메뉴}.md`)**

| 칸 | 뜻 |
| --- | --- |
| Language ID | `LID-{메뉴 글자 3}-{세 자리}` (예: `LID-EVT-001`) |
| 재사용 | `ref`면 다른 항목의 Language ID를 다시 쓴 줄(글자가 같음). 엑셀에서는 Language ID 칸에 `ref: LID-…`로 적혀 있던 줄 |
| 상태 | `사용` / `삭제`. 지운 항목은 줄을 지우지 않고 `삭제`로 둠 |
| 검증 상태 | `법인 검토 완료` / `AI 번역`. 번역을 법인이 검토했는지. v0.05에서 옮길 때: 엑셀 A열이 비어 있던 줄과 `삭제` 줄은 `법인 검토 완료`(삭제 줄은 법인 검토를 마친 글자가 이번에 지워진 것, 2026-11-17 서보경 확인), `추가` · `변경` 줄은 `AI 번역`(법인 검토 전). 고친 줄은 번역을 다시 붙였으면 `AI 번역`으로 |
| 플랫폼 · Type | 플랫폼 `T` · `L` · `T/L`, Type `title` · `txt` · `btn` · `alt-txt` |
| English | 지금 쓰는 영어 글자. 엑셀의 "English (수정/추가 ver.)"가 있으면 그것, 없으면 "English (기존 ver.)". 바뀌기 전 글자는 `db/history.md`에 있음 |
| Korean | 한국어. v0.05에는 한국어가 없어 칸만 두고 비어 있음(2026-11-17). 흐름(4단계)에서는 채우지 않고 언어셋 담당자 · 법인이 채움(2026-11-18) |
| German · Portuguese · Spanish · Italian · French | 번역. `-`는 번역하지 않는 말(고유명사 등, 영어 그대로) |
| 참조 시트 | 공통 파일에서 이미 번역한 항목이면 그 Language ID(`LID-COM-…`, `db/common.md`) |
| 비고 | 어디에 쓰는 글자인지 |
| Menu · CID | 쓰는 메뉴와 화면(CID). 한 글자를 여러 화면이 쓰면 ` / `로 이음 |

**공통 파일 (`db/common.md`)**: Language ID(`LID-COM-{분류}-{세 자리}`, 분류 `TRM` 고유명사 / 용어집 · `MEN` 메뉴 / 내비게이션 · `SCD` 상태값 / 코드값 · `BTN` 버튼) · 상태 · 검증 상태 · 구분 · 플랫폼 · Type · 번역 여부(`번역` / `미번역`) · English · Korean · 다섯 언어 · 맥락 메모 · 비고. 검증 상태는 메뉴 파일과 같은 기준
- **두 ID의 쓰임:** 화면에서 쓰는 ID는 메뉴 파일의 Language ID입니다. 화면 MD "화면 표기 글자" 표에는 늘 이 ID를 적습니다. 공통 ID(`LID-COM-…`)는 화면 MD에 적지 않고, 이 원본 안에서 공통 항목을 가리키는 관리용입니다: 메뉴 줄의 "참조 시트"가 어느 공통 번역을 따르는지 잇고(공통 번역이 바뀌면 따르는 메뉴 줄을 찾음), 항목 이력의 키, 엑셀로 넘기고 돌려받을 때 줄을 맞추는 데 씁니다.

## 고치는 법

> **새 버전을 받을 때까지는 읽기만 합니다 (2026-11-17).** 언어셋 담당자가 v0.05 뒤의 검토를 반영한 새 버전을 보낼 예정이라, 그 버전이 확정될 때까지 화면설계 흐름은 이 원본을 찾아보기만 하고 고치지 않습니다. 더하거나 고칠 것은 작업 기록 "언어셋" 절에 모아 두고, 새 버전을 받아 원본을 바꾼 뒤 그 위에 반영합니다. 받는 절차는 새 버전이 올 때 정합니다(`background/todo.md` 5-3c ①).

언어셋을 고치면 원본 파일과 이력을 함께 고칩니다.

| 무엇 | 원본 파일 | `db/history.md` "항목 이력" |
| --- | --- | --- |
| 더함 | 그 메뉴 파일에 줄을 더함. Language ID는 그 메뉴 글자의 다음 번호. 같은 글자가 이미 있으면 새 번호를 만들지 않고 `ref`로 다시 씀 | `추가`, 변경 후에 새 글자 |
| 바꿈 | English · 번역 칸을 고침 | `변경`, 변경 전 → 변경 후 |
| 지움 | 줄을 지우지 않고 상태를 `삭제`로 | `삭제`, 변경 전에 지운 글자 |

- 항목 이력 한 줄: 날짜 · 버전 · 키 · 메뉴 · CID · 변경 · 변경 전 · 변경 후 · 근거(작업 기록 이름 · 요청) · 누가
- 버전: 버전 번호는 언어셋 담당자가 엑셀 "문서 이력"에서 매깁니다. 받은 버전을 반영한 줄은 그 번호를 적고, 원본에서 고친 줄은 "버전" 칸을 비워 두었다가 다음 버전을 받을 때 그 번호로 채웁니다.
- 화면설계 흐름에서는 5단계 완료 때 작업 기록 "언어셋" 절을 이 원본에 반영합니다(아래 "화면설계 흐름에서 반영하는 법", `flow/5-done.md` 절차 2번 순서 5).

## 화면설계 흐름에서 반영하는 법

5단계(완료) 절차 2번 순서 5에서 작업 기록 "언어셋" 절의 줄을 이 원본에 반영하고 `db/history.md` "항목 이력"에 한 줄씩 더한 뒤(위 "고치는 법"), 화면 MD "화면 표기 글자" 표를 맞춥니다. 순서는 언어셋 원본 → 화면 MD입니다. **[초안 2026-11-18, 테스트하며 다시 봄]**

| 작업 기록의 줄 | 언어셋 원본에 하는 일 | 항목 이력 | 화면 MD |
| --- | --- | --- | --- |
| Language ID 있음 (4단계에서 가져옴) | 그 줄의 CID 칸에 이 화면이 없으면 더함. 다른 메뉴의 줄이면 이 메뉴 파일에 `ref` 줄을 더함 | 더했으면 `재사용 추가` | 상태를 `-`로 |
| Language ID 없음 | 반영하기 직전에 같은 글자가 그 사이 원본에 생겼는지 한 번 더 봄. 있으면 위 줄처럼, 없으면 이 메뉴 파일에 새 줄(새 Language ID, 작업 기록의 번역 · 참조 시트 · 검증 상태) | `추가` | 새 ID를 채우고 상태를 `-`로 |
| `변경` | 변경 전 글자를 이 화면 말고 쓰는 화면이 없으면 그 줄의 영어 · 번역을 고침. 있으면 그 줄은 그대로 두고 변경 후 글자를 위 두 줄처럼 다루고, 그 줄의 CID 칸에서 이 화면을 뺌 | 고쳤으면 `변경`, 새 줄이면 `추가` | "변경 전 → 변경 후"를 변경 후만 남기고 ID를 맞추고 상태를 `-`로 |
| `제거` | 그 줄의 CID 칸에서 이 화면을 뺌. 남는 화면이 없으면 그 줄의 상태를 `삭제`로 | `삭제`로 바꿨을 때만 `삭제` | 그 줄을 지움 |
| `추가 (언어셋에 없음)` (케이스 3) | `Language ID 없음` 줄과 같음 | `추가`, 근거에 `케이스 3 옮기며 찾음 (작업 기록 이름)` | 새 ID를 채움(상태는 `-` 그대로) |
| `언어셋에만 있음` (케이스 3) | `제거`와 같음: 그 줄의 CID 칸에서 이 화면을 뺌. 남는 화면이 없으면 상태를 `삭제`로 | `삭제`로 바꿨을 때만 `삭제`, 근거에 `케이스 3 옮기며 찾음 (원본 화면에 없음)` | 고치지 않음(표에 없는 글자) |

- **이 화면 말고 쓰는 화면이 있는지 보는 법** (`변경` · `제거`): 그 Language ID 줄의 CID 칸과, 모든 메뉴 파일에서 그 ID를 다시 쓰는 `ref` 줄의 CID 칸을 함께 봅니다. CID 칸에 CID가 아닌 값(예: `Case`, `TI-STN-02_Toast`)이 있어 판단할 수 없으면 원본의 그 줄을 지우거나 고치지 않고 작업 기록 "모아 둔 질문"에 적습니다(5단계 절차 2번 순서 7에서 물음).
- **검증 상태:**

  | 원본에 반영하는 것 | 검증 상태 |
  | --- | --- |
  | 새 줄 (번역함) | `AI 번역` |
  | 새 줄 (공통에서 가져옴) | 공통 줄의 검증 상태 그대로 |
  | 영어를 고친 줄 | `AI 번역`으로 되돌림. 그 전에 `법인 검토 완료`였어도 되돌림 |
  | CID나 `ref` 줄만 더함, `삭제`로 바꿈 | 그대로 |
  | 법인 검토 결과를 받음 (흐름 밖) | 이 흐름의 순서가 아님. 아래 "법인 검토 받기" |

- 언어셋 원본에 반영하지 못한 줄은 화면 MD의 상태를 그대로 둡니다(다음 작업에서 다시 대상이 됨). 반영하지 못한 줄과 이유를 5단계 보고에 적습니다.
- 요청을 반영하지 않고 끝나면 비우지 않고 "화면 표기 글자" 표를 작업 전으로 되돌립니다.

**돌려받은 엑셀을 반영하는 법**

| 찾은 것 | 원본에 하는 일 | 항목 이력 |
| --- | --- | --- |
| 번역이 바뀐 줄 | 그 언어 칸을 고침 | `번역 수정 (언어)`, 그 언어의 변경 전 → 변경 후 |
| 넘길 때 `AI 번역`이었던 줄 (고쳤든 안 고쳤든, 검토를 마친 글자) | 검증 상태를 `법인 검토 완료`로 | 줄마다 남기지 않고 "문서 이력"에 요약 한 줄(예: "법인 검토 반영: 검토 완료로 바꿈 (312건), 번역 수정 (12건)") |
| 재사용(`ref`) 줄의 번역이 바뀜 | 다시 쓰는 원래 줄을 고침 | 원래 줄의 키로 `번역 수정 (언어)` |
| 영어가 바뀐 줄, Language ID가 원본에 없는 줄, 원본에 있는데 엑셀에 없는 줄 | 반영하지 않음 | 남기지 않음. 요청자에게 목록으로 보여 주고 물음 |

- 같은 글자를 다시 쓰는 줄(`ref`)이 원래 줄과 다르게 고쳐져 오면 반영하지 않고 물음.
- 반영한 뒤 바뀐 줄 수와 물을 것을 보고합니다.

## 옮기며 본 것 (v0.05)

- **한국어 칸이 없음:** 엑셀에는 영어와 다섯 언어만 있습니다. 원본에는 Korean 칸을 더해 두었고 비어 있습니다.
- **옮기지 않은 숨긴 시트 셋:** `0-F.얼럿_팝업`(44행) · `0-G.컨펌_팝업`(28행)은 Language ID가 없고 번역 상태가 모두 `미번역`, `Material Setup`(426행)은 목록 시트의 Material Setup 줄을 만들 때 쓴 작업 시트로 보입니다. 얼럿 · 컨펌은 알럿 체계가 정해지면 함께 이 원본에서 관리합니다(`background/todo.md` 5-2 · 5-3a).
- **엑셀 안에서 본 것:** `LID-IVT-034`가 두 줄에 있음 — Inventory의 줄이 삭제되고 같은 ID로 Material Setup에 옮겨 간 것(엑셀 비고 "Material Setup > Empty Waste Bin으로 이동 (같은 ID)"). `ref: LID-MAS-125`(Material Setup, 삭제된 줄)가 가리키는 항목이 목록에 없음(v0.06에서 `ref: LID-MAS-086`으로 고쳐 옴). 메뉴 이름은 엑셀의 "구분"(Instruments · Change Password)이 아니라 "Menu"(Instrument · Profile)가 맞음(2026-11-17 서보경 확인) — 메뉴 파일 이름 · 제목 · 항목 이력을 Instrument · Profile로 맞춤.
- 공통 시트의 `변경` 줄은 엑셀에 변경 전 값이 없어 이력의 변경 전 칸에 그렇게 적었습니다.
