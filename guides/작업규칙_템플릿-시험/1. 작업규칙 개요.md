# 1. 작업규칙 개요

> 기본 템플릿(CURECA 작업규칙 바탕, 2026-11-18). `{프로젝트}` · `※ 정할 것`을 팀에 맞게 채웁니다. 채우지 않은 `※ 정할 것`이 있으면 Claude는 그 부분을 추천안으로 처리하고 note에 알립니다.

이 문서는 Claude가 이 팀의 요청을 처리할 때 가장 먼저 읽는 문서입니다. 무엇을 어떤 순서로 읽는지만 두고, 절차는 「3. 화면설계 흐름」에, 쓰는 법은 4 ~ 7번 문서에 둡니다.

## 작업 시작 순서

1. 「2. 헌법」 — 모든 문서와 작업에 우선합니다.
2. 요청 글을 아래 표로 가릅니다. 애매하면 처리하지 않고 「보류」 + 질문으로 묻습니다.
3. 가른 문서를 읽고 그 순서대로 진행합니다. 앞선 대화가 아니라 UX 문서를 근거로 일합니다.

| 요청 (요청 글로 가름) | 읽을 문서 | 끝나는 곳 |
| --- | --- | --- |
| 화면설계: 화면 부분 수정 · 신규 화면 · 기존 화면 다시 그리기 | 「3. 화면설계 흐름」 1단계부터 | 단계마다 요청자 확인(보류 + 질문) |
| 끊긴 작업 이어 가기 | 「5. 작업 기록」 「끊긴 작업 이어 가기」 | 기록의 「이어서 작업할 곳」부터 |
| 논의 대상 올리기 · 결정 반영, 반영 대기 확인 | 「6. 논의 대상 · 반영 대기」 | 한 번에 끝남 |
| 문서만 고치기(정책서 문장 다듬기 · 용어 정리 등) | 해당 UX 문서 쓰는 법 | 한 번에 끝남 |
| 질문 · 자료 찾기 | UX 문서에서 찾아 답함(흐름을 타지 않음) | 한 번에 끝남 |

- 정책을 바꾸는 요청은 화면에 미칠 수 있으면 화면설계로, 화면과 상관없는 정리만 「문서만 고치기」로 가릅니다.
- 요청자가 케이스 · 단계를 고르지 않습니다(Workbench에 그 칸이 없음). 요청 글과 작업 기록으로 정합니다.
- `※ 정할 것` 팀에서 더 나누는 요청(예: 언어셋, 회의록 정리)이 있으면 표에 줄을 더합니다.

## 보류 기준

고치지 않고 「보류」 + 질문(선택지 2 ~ 4개)으로 묻는 경우:

- 요청이 어느 화면 · 무슨 일인지 요청 글로 가를 수 없을 때
- 근거(정책서 · 기준데이터 · 기존 화면)가 없거나 서로 다를 때 — 만들어 쓰지 않습니다
- 작업 페이지 밖을 고쳐야 할 때, 다른 팀 · 다른 파일에 영향이 있을 때
- `※ 정할 것` 대상 화면이 많을 때 나눠서 할지(예: 10개를 넘으면 묻기)

## 고칠 범위

- Figma는 작업 페이지 하나만 고칩니다. 다른 페이지 · 다른 파일은 읽기만 합니다.
- `※ 정할 것` 작업 페이지 안의 구역(파트 · 영역 · 진행상태 띠)과 새 프레임을 둘 자리
- 화면(프레임) 이름은 「7. ID · 파일 규칙」의 CID 규칙을 따릅니다.

## 완료 때 남길 것

- note 첫 줄: 한 일 한 문장. 그 아래 `- 화면: 무엇 → 어떻게` 한 줄씩. 끝에 작업 기준 줄(적용한 문서 이름).
- 화면을 바꿨으면 같은 요청 안에서 화면 정의서도 고칩니다. 다른 화면에 미치는 변경은 그 화면의 반영 대기 목록에 남깁니다.
- 정책 · 기준데이터 변경은 논의 대상으로 올리고, 결정된 뒤 반영합니다(헌법 4조).

## 늘 지키는 것

- 결정되지 않은 내용은 만들어 쓰지 않고 질문으로 남깁니다.
- 결정은 사람이 합니다. Claude는 제안하고 실행합니다.
- 「테스트로」 · 「반영하지 말고」라고 하면 순서는 그대로 하고 UX 문서는 고치지 않습니다.
