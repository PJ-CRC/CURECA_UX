# 반영 대기 목록

> 상태: 초안 (2026-11-10). `background/cleanup-plan.md` 3절(방향 B)에서 정한 것과 2026-11-10 결정(화면 작업이 있는 결정은 완료 때 반영, 임시 정책 없앰)을 옮긴 문서입니다. 2026-11-10부터 이 문서로 작업합니다.

**반영 대기 목록 = 내 작업 밖의 다른 화면에 반영해야 하는 변경을, 그 화면의 화면 MD에 남겨 두는 곳**입니다. 내가 지금 고치는 화면은 바로 고치므로 항목을 만들지 않습니다. 다른 작성자에게 알리는 대신 이 항목이 알림입니다(헌법 5조).

## 1. 항목이 생기는 때

| 때 | 무엇 |
| --- | --- |
| **화면설계 작업의 7단계 완료(화면 컨펌)** | 그 작업의 결정 반영(`reference-rules/discussions.md` 6절)으로 영향 화면에 항목이 생김. 정책이 바뀌지 않았어도 내 화면을 고쳐 다른 화면도 맞춰야 하면(예: 내가 고친 팝업을 부르는 화면) 이때 항목을 만듦 |
| **화면 작업이 없는 결정을 확인했을 때** | 회의 · 고객 답 · 정책 정리 · 후속 확인의 답으로 결정 반영을 돌릴 때 |
| **기준 자료 · 외부 원본이 바뀌었을 때** | 용어집 · 상태값 · 알럿 카탈로그 · Common UX · 언어셋을 고치거나, 씨젠 문서 · IA 새 버전을 반영할 때 |
| **주기 점검** | "주기 점검 해 줘"로 어긋난 곳을 찾았을 때 (5절) |

- 작업 중(0 ~ 6단계)에는 영향 화면을 작업 기록 "영향 화면" 표에만 두고 항목을 만들지 않습니다. 결정이 바뀌어도 다른 사람에게 번지지 않게 하려는 것입니다.
- 영향 화면을 이번 작업에서 **함께 고치면**(작은 변경, 요청자 확인 · 그 화면 작성자에게 구두 확인) 항목을 만들지 않고, 그 화면 변경 이력에 `연동 변경`과 원인(CID · DS ID), 고친 사람을 남깁니다. 큰 변경은 함께 고치지 않고 항목을 만듭니다.
- **작은 변경 · 큰 변경:** 작은 변경은 문구 · 표기 · 값만 바뀌고 배치와 요소 수가 그대로인 것입니다. 요소가 생기거나 없어지거나, 배치 · 흐름 · 상태값 구성이 바뀌면 큰 변경입니다.
- **함께 고친 화면의 화면 정보는 바꾸지 않습니다.** 화면설계를 바꾸는 수준이 아니므로 그 화면의 Ver · Date · 작성자는 그대로 두고, 고친 사람은 변경 이력의 `연동 변경` 항목에만 적습니다.

## 2. 타입 (왜 올라왔나)

| 타입 | 언제 | 근거 칸 |
| --- | --- | --- |
| 논의 결정 | 논의 대상의 결정이 반영됨 (영향 범위가 `정책서 + 화면` 또는 `화면`). 후속 확인의 답으로 바뀐 경우도 여기 | DS ID, 바뀐 정책 ID |
| 다른 화면 파급 | 다른 화면을 고쳐서 이 화면(짝 CID, 부르는 · 불리는 화면, 공통 팝업)도 맞춰야 함 | 원인 CID |
| 기준 자료 변경 | 용어집 · 상태값 · 알럿 카탈로그 · Common UX · 언어셋이 바뀜 | 자료 이름 · 항목 |
| 외부 원본 변경 | 씨젠 문서 · IA 새 버전 | 원본 이름 · 날짜 |
| 점검 발견 | 주기 점검 · 검토 · 기존 화면 옮기기에서 찾은 어긋남 · 오타 | 찾은 점검 |

맞지 않는 항목이 나오면 그때 타입을 하나 더합니다.

## 3. 칸과 쓰는 법

```markdown
## 반영 대기 목록

| ID | 타입 | 변경 전 | 변경 후 | 근거 | 상태 |
| --- | --- | --- | --- | --- | --- |
| R01 | 논의 결정 | 5-1 Status 칩 "Open · Close" | 디스크립션에 넣음: Main Mode에서만 바꿀 수 있음. 화면 예시도 Close 칩 비활성 | DS-0012, POL-EVT-002 | 대기 |
```

- **변경 전:** 그 화면에 지금 있는 문구 · 동작 (어느 번호의 무엇인지)
- **변경 후:** 디스크립션에 들어갈 내용은 `디스크립션에 넣음: …`, 화면 예시에 보이는 것(숫자 형식 · 단위 · 상태 · 칩 · 버튼 상태)은 그 뒤에 `화면 예시도 …`. **무엇으로 바꿀지 정해지지 않았으면 반영 대기 항목을 만들지 않습니다.** 정책에 관한 것은 논의 대상으로, 화면에 관한 것은 `※ 질문 대기`로 올립니다("확인 필요"는 새 항목에 쓰지 않음)
- **근거:** 원인 ID를 맨 앞에(예: `DS-0012 (원인 TI-STN-05), POL-ACC-006`). 같은 원인으로 만든 항목은 근거 칸의 원인 ID로 한꺼번에 찾습니다. 원인 문서에 항목 ID를 되적지 않습니다(한 방향으로 찾음).
- **ID:** 표 안에서는 `R01`, `R02` … 그 화면 MD 안에서 순서대로, 한 번 쓴 번호는 다시 쓰지 않습니다. 표 밖(커밋 메시지 · 다른 문서)에서는 `TI-INS-01-T-R03`처럼 CID를 붙입니다. 짝 CID에 같은 내용을 넣을 때도 항목은 화면마다 따로 두고, 근거 칸에 짝 항목의 전체 ID를 적어 잇습니다.
- **겹칠 때:** 같은 곳을 같은 내용으로 바꾸는 `대기` 항목이 이미 있으면 새로 만들지 않고 그 항목 근거 칸에 원인 ID를 더합니다. 같은 곳을 다르게 바꾸면 새 항목을 만들고 앞 항목은 `제외 (날짜, R05로 바뀜)`으로 둡니다.
- 화면 MD가 아직 없는 화면이면 빈 화면 MD를 먼저 만들고 그 안에 적습니다.

## 4. 상태

| 상태 | 뜻 |
| --- | --- |
| `대기` | 다음에 그 화면을 고칠 때 반영할 것 |
| `작업 중 (작업 기록 이름)` | 진행 중인 화면설계 작업이 이번에 반영하기로 고른 항목. 화면 컨펌 전이라 아직 확정이 아님 |
| `반영 완료 (날짜)` | 화면 컨펌(7단계 완료)으로 화면 MD · Figma에 반영이 끝남 |
| `제외 (날짜, 이유)` | 반영하지 않기로 함 (예: 취소선으로 제거된 항목, 다른 항목으로 바뀜) |

- 항목은 지우지 않습니다.
- **상태가 바뀌는 때 (화면설계 케이스 1 · 2 · 3 모두 같음):** 작업에서 나온 결정과 마찬가지로 **7단계 완료 때 확정**합니다.
  - 1단계 요청자 확인에서 "이번에 반영"으로 고르면 `대기` → `작업 중 (작업 기록 이름)`
  - 3단계에서 화면에 반영해도 상태는 `작업 중` 그대로
  - 7단계 완료(화면 컨펌) 때 `작업 중` → `반영 완료 (날짜)`. 그 화면 변경 이력에 반영한 항목 ID를 적음
  - 작업 도중 그 항목을 반영하지 않기로 하면 `대기`로 되돌림(또는 `제외`). 작업을 멈추면(`status: 멈춤`) `작업 중`인 항목을 모두 `대기`로 되돌림
  - "테스트로" 하는 작업은 상태를 바꾸지 않음
- `작업 중`인 항목은 다른 작업이 반영하지 않습니다. 같은 화면을 고치려면 0단계 겹침 확인에서 먼저 정합니다.
- **되돌릴 때:** 반영한 항목을 되돌려야 하면 되돌리는 내용을 새 `대기` 항목으로 만듭니다(근거에 되돌리는 이유와 앞 항목 ID).
- 컨펌 완료 · 전달 완료된 화면에 항목이 생기면 그 화면의 상태 처리는 7단계 문서를 따릅니다.

## 5. 주기 점검

Claude는 혼자 정기적으로 돌지 못하므로, 사람이 **"주기 점검 해 줘"**라고 요청할 때 돕니다(팀 프로그램에 점검 버튼을 두는 것은 요청서). 대조할 것:

1. 화면 MD 정책 참고의 정책 ID가 정책서에 있고, 폐기(Deprecated)되지 않았는지
2. 화면 MD의 말이 용어집 표준어인지 (단어 단위)
3. 화면 MD의 알럿 ID · 상태값이 알럿 카탈로그 · 상태값 표와 맞는지
4. 정책서의 `cids`와 화면 MD 정책 참고가 서로 맞는지
5. T/L 짝 화면의 반영 대기가 한쪽에만 있지 않은지
6. 화면의 기준점(`basis`) 뒤로 바뀐 정책인데 그 화면에 반영 대기 항목이 없는지

찾은 것은 타입 `점검 발견` 항목으로 만들고, 정책을 정해야 하는 것은 논의 대상으로 올립니다. 나중에 스크립트로 만들어 4명이 돌려도 결과가 같게 합니다.

## 하지 않는 것

- 작업 중(0 ~ 6단계)에 다른 화면에 항목 만들기 (완료 때 한꺼번에)
- 다른 작성자의 화면을 크게 고치기 (항목만 만듦)
- 항목 지우기, 원인 문서에 항목 ID 되적기

## 6. 예전 칸으로 적힌 항목 (2026-11-10)

이미 옮겨 둔 화면 MD의 반영 대기 목록은 예전 칸(`ID | 구분 | 지금 | 바꿀 것 | 근거 | 상태`)으로 적혀 있습니다. 한꺼번에 고치지 않고, 그 화면을 다시 그릴 때 화면 MD를 새 틀로 다시 쓰면서 바꿉니다. 그때까지는 이렇게 다룹니다.

| 예전 칸 | 읽는 법 |
| --- | --- |
| 구분 | 화면의 어디를 고치는지(디스크립션 · 표기 · 화면 정보 · 정책 반영 등). 새 "타입"과 뜻이 다름 |
| 지금 | 변경 전 |
| 바꿀 것 | 변경 후 |
| 상태 | 새 상태와 같음 (`대기` · `반영 완료` · `제외`). 예전 항목에는 `작업 중`이 없음 |

- **읽을 때:** 예전 칸의 `대기` 항목도 새 항목과 똑같이 다룹니다. 1단계에서 빠짐없이 읽고 이번에 반영할지 묻습니다.
- **예전 칸 표에 새 항목을 더할 때:** 표 머리를 새 칸(`ID | 타입 | 변경 전 | 변경 후 | 근거 | 상태`)으로 바꾸고 새 항목을 더합니다. 있던 항목의 값은 고치지 않습니다(타입 칸에 예전 구분 값이 남아도 됨). ID는 그 표의 가장 큰 번호에 이어 매깁니다.
- **다시 그릴 때:** 화면 MD를 새 틀로 다시 쓰면서 항목을 모두 옮깁니다. 이번에 반영하는 항목은 `작업 중`(7단계 완료 때 `반영 완료`), 반영하지 않는 항목은 `대기` 그대로이고, 항목 ID는 바꾸지 않습니다. 예전 구분 값은 타입으로 다시 매깁니다(근거 칸에 논의 대상 ID가 있으면 "논의 결정", 정책 · 기준 자료가 바뀐 것이면 "기준 자료 변경", 그 밖은 "점검 발견").
- **끝 관문에서:** 다시 쓰기 전의 항목 수와 다시 쓴 뒤의 항목 수가 같은지 확인합니다. 항목이 사라지면 통과하지 못합니다.
- **예전 항목의 `대기 (확인 필요)`:** 무엇으로 바꿀지 정해지지 않은 채 적어 둔 항목입니다. 1단계에서 "이번에 반영할지" 묻지 않고 요건서 "확인할 것"에 옮겨 적습니다. 정책에 관한 것은 2단계 요청자 확인에서, 화면에 관한 것은 3단계 `※ 질문 대기`로 묻습니다. 답이 정해지면 그 항목의 변경 후를 채우고 상태를 `작업 중`으로 바꿔 반영합니다. 답이 "바꾸지 않음"이면 `제외 (날짜, 이유)`로 둡니다.
