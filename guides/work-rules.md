# CURECA 작업규칙 (진입점)

> Workbench에서는 이 문서가 UX 문서 「작업규칙」의 첫 문서다. 원본은 CURECA_AI 저장소의 `CLAUDE.md`(2026-11-12 프로그램 폴더의 CLAUDE.md와 섞이지 않게 이름을 바꿔 분리). 규칙 문서 안에서 `CLAUDE.md`라고 적은 것은 이 문서다. CURECA_AI에서 다시 맞출 때도 `CLAUDE.md` → `work-rules.md`로 옮긴다.
> 상태: v0.2 (2026-11-10). 새 흐름(`flow/`)으로 전환했습니다. 예전 규칙은 `old-rules/`로 옮겼고 작업 근거로 쓰지 않습니다.

이 파일은 Claude가 이 저장소에서 작업을 시작할 때 가장 먼저 읽는 파일입니다. 여기에는 무엇을 어떤 순서로 읽는지만 두고, 절차는 `flow/`의 단계 문서에, 쓰는 법은 `reference-rules/`에 둡니다.

## 작업 시작 순서

1. [constitution.md](constitution.md) — 헌법. 모든 문서와 작업에 우선합니다.
2. 요청이 무엇인지 아래 표로 가릅니다. 애매하면 시작 전에 묻습니다.
3. 가른 문서를 읽고 그 순서대로 진행합니다. 앞선 대화가 아니라 저장소를 근거로 일합니다(헌법 7조).

| 요청 | 읽을 문서 |
| --- | --- |
| **화면설계** (케이스 1 화면 부분 수정(고도화) · 케이스 2 신규 · 케이스 3 기존 화면 다시 그리기) | [flow/README.md](flow/README.md) → [flow/0-start.md](flow/0-start.md)부터 단계 순서대로. 단계를 시작할 때마다 그 단계 문서와 작업 기록을 다시 읽음 |
| 끊긴 화면설계 작업 이어 가기, "열린 작업 리스트 보여 줘" | [reference-rules/work-log.md](reference-rules/work-log.md) "끊긴 작업 이어 가기" |
| 논의 대상: 올리기 · "논의 리스트 보여 줘" · 결정 반영 · 후속 확인 답 · 같은 질문 합치기 | [reference-rules/discussions.md](reference-rules/discussions.md) |
| 반영 대기: "○○ 반영 대기 보여 줘" · "주기 점검 해 줘" | [reference-rules/pending-changes.md](reference-rules/pending-changes.md) |
| 질문 · 자료 찾기 | 저장소에서 찾아 답함. 흐름을 타지 않음 |
| 그 밖 (회의록 정리, 정책서 쓰기, 언어셋, 용어 검토, 일정) | 아래 "아직 새 문서가 없는 일" |

## 단계 문서의 상태

| 단계 | 상태 |
| --- | --- |
| 0 시작 · 1 요건 정의 · 2 근거 · 분석 · 3 화면 설계 | 초안. 이 문서로 작업함. "※ 정할 것"으로 표시된 곳은 문서 끝의 안을 따르고, 따랐다는 것을 보고에 적음 |
| 4 검토 · 5 고객 UX 리뷰 · 6 다국어 · 7 완료 | 아직 채우지 않음. 3단계 끝 관문까지 하고 멈춘 뒤, 다음을 어떻게 할지 요청자에게 물음 |

## 읽는 문서와 읽지 않는 문서

- **작업 근거로 읽는 것:** `constitution.md`, `flow/`, `reference-rules/`, `examples/`(본보기), `templates/`, `policy/`, `glossary/`, `screens/`, `ia/`, `common-ux/`, `language-set/`, `meetings/`, `sources.md`, `work-logs/`, `discussions/`
- **이름이 `old-`로 시작하는 폴더 · 파일은 예전 문서입니다.** 작업 근거로 쓰지 않습니다. 새 문서와 다르면 새 문서가 맞습니다.
  - `old-rules/`: 예전 규칙. 내용은 `flow/` · `reference-rules/`로 옮겼거나 옮기는 중(`background/migration-map.md`)
  - `old-pending/` · `old-provisional/` · `old-customer-agenda/`: 예전 내부 논의 · 임시 정책 · 고객 논의. 아직 논의 대상으로 옮기지 않은 열린 항목이 있으므로, 걸린 정책 · 화면을 작업할 때는 **무엇이 정해지지 않았는지 확인하는 용도로만** 읽음
  - `old-screen-fixes/` · `old-changes/` · `old-decisions/`, `templates/old-*.md`: 쓰지 않음
- `archive/`는 결정의 출처를 찾을 때만 읽습니다.
- `background/`는 규칙을 만드는 작업 자료입니다. 화면설계 작업의 근거로 쓰지 않습니다. 할 일은 `background/todo.md` 한 곳에 모읍니다.

## 아직 새 문서가 없는 일

회의록 정리, 정책서 쓰기, 언어셋, 용어 검토, 일정처럼 새 문서가 아직 없는 일은 이렇게 합니다.

1. 헌법과 새 문서(`reference-rules/`)에 정해진 것을 먼저 따릅니다. 논의는 논의 대상으로, 다른 화면에 미치는 변경은 반영 대기 목록으로 남깁니다. 임시 정책 · 협의 대기 · 고객 논의 목록은 새로 만들지 않습니다.
2. 새 문서에 없는 부분만 `old-rules/`의 해당 문서를 참고합니다. 참고한 문서 이름을 보고에 적습니다.
3. 예전 규칙과 새 문서가 부딪치면 새 문서를 따르고, 부딪친 곳을 `background/todo.md`에 적습니다.

## 늘 지키는 것

- 결정되지 않은 내용은 만들어 쓰지 않고 질문으로 남깁니다. 화면에서는 기존 원본 → 정책서 → 공통 UX → 같은 메뉴의 다른 화면 순서로 따를 것을 찾아 그리고 빨간 글씨 `※ 질문 대기`로 표시합니다. 근거가 있어 기존 화면과 다르게 그린 곳은 `※ 변경 확인`으로 표시합니다.
- 기존 화면은 UX 화면설계서(패널이 붙은 기획 프레임과 디스크립션)만 근거로 씁니다. 디자인 화면에서 가져오지 않습니다.
- 결정은 사람이 합니다. Claude는 제안하고 실행합니다.
- "테스트로", "반영하지 말고"라고 하면 순서는 그대로 하고 저장소는 고치지 않습니다(`flow/0-start.md` "테스트로 할 때").
- 커밋은 요청받았을 때만 합니다.
