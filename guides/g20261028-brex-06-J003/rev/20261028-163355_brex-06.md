# CURECA UX 가이드

이 가이드는 Figma `UX AI TEST` › SH.L TEST 페이지의 **Connon UX** 섹션(Common UX 문서 2.0, 프레임 19장)을 기준으로 정리했다. 화면을 설계하거나 기존 화면을 고칠 때 이 규칙을 따른다. 상태값 · 표기 정의는 씨젠이 공유하는 「CURECA 시스템 구성 요소 및 상태 정보」 문서를 최우선으로 한다.

> 왼쪽 목차는 Figma 문서의 목차(COMM-0)와 같은 구조다. 대분류를 누르면 그 아래 항목이, 항목을 누르면 세부 내용이 오른쪽에 나온다. 그림을 누르면 크게 볼 수 있다.

### 프레임 구성

| 구분 | 크기 | 구성 |
|---|---|---|
| 목차 (`COMM-0`) | 1920 × 1295 | 대분류 1~5와 각 상세 프레임 CID · 이름, 기존 번호 |
| 대분류 표지 (`COMM-1` ~ `COMM-4`) | 1920 × 1080 | `Title`(Common UX · 대분류명 · 번호) + `Items`(하위 CID · 이름) |
| 상세 프레임 (`COMM-1-a` …) | 폭 1920, 높이는 내용에 맞춤 | `Header` + `Body` |

- **Header 항목**: Ver(예: 2.0.01) · Date · CID · 대분류(예: `1. Overview`) · 제목(예: `1-a. Gesture / Input Interaction Guide`) · 작성자 · 화면 · 화면명 · 경로 · Dev · SG, 그리고 한 줄 설명(「…을 정의합니다.」)
- 이전 문서에서 옮겨 온 프레임은 Header에 **기존 번호**를 함께 적는다(예: `기존 SB-2-a`).
- 한 주제가 길면 `(1/2)`, `(1/4)`처럼 나눠 프레임을 이어 붙인다.

## 1. Overview

Tablet 제스처와 PC 외부 입력(마우스 · 키보드) 액션을 정의한다.

### 1-a. Gesture / Input Interaction Guide

Tablet 제스처와 PC 외부 입력(마우스 · 키보드)의 액션 가이드를 정의한다.

![COMM-1-a](images/comm-1-a.png)
*COMM-1-a · Gesture / Input Interaction Guide*

**Tablet** — 제스처를 사용할 경우 아래 액션을 따른다.

| 이름 | 정의 |
|---|---|
| 탭 (Tap) | 화면의 일정 부분을 눌렀다가 떼는 동작. 버튼처럼 명확한 경우에는 표기 생략 가능 |
| 당겨서 새로고침 (Pull to refresh) | 당겨서 새로 고침 기능 사용 |
| 스와이프 (Swipe) | 화면의 두 지점을 일직선으로 이동했다가 떼는 동작. 화면을 수평으로 이동할 수 있음 |
| 스크롤 (Scroll) | 수직 · 수평 또는 어떤 방향으로든 밀어서 콘텐츠 사이를 이동 |

**PC** — 마우스 · 키보드 같은 외부 입력을 쓸 경우 아래 액션을 따른다.

| 이름 | 정의 |
|---|---|
| 클릭 (Click) | 마우스나 트랙패드로 버튼 · 링크 같은 요소를 클릭해 탐색 · 작업을 수행하는 필수 과정 |
| 프레스드 (Pressed) | 컴포넌트를 눌렀을 때의 상태 |
| 호버 (Hover) | 컴포넌트 위로 커서를 올려 추가 정보 · 도구 설명 · 옵션을 표시 |
| 드래그 앤 드롭 (Drag and Drop) | 항목을 클릭한 채 새 위치로 이동. 파일 탐색기 · 카드 순서 바꾸기 등에 사용 |
| 키보드 단축키 (Keyboard Shortcuts) | 메뉴를 거치지 않고 명령 실행. 표기는 `[키보드 단축키]`로 통일 (예: `[Ctrl + c]`) |
| 스크롤 (Scroll) | 마우스 휠 · 트랙패드 스와이프로 수직 · 수평 탐색 |
| 마우스 오른쪽 버튼 (컨텍스트 메뉴) | 선택한 개체 · 영역과 관련된 추가 옵션 제공 |

### 4-a. Data Notation Rules (2/4) · 장비 상태 · 컨트롤러

CURECA 장비 전체의 구동 상태값과 구동 컨트롤러, 장비 통합 상태 처리 조건, 도어 잠금 해제 조건을 정의한다.

![COMM-4-a(2/4)](images/comm-4-a-2.png)
*COMM-4-a(2/4)*

**전체 CURECA 구동 상태값**

| 코드명 | UI (영문) | UI (한글) | 설명 | UX action |
|---|---|---|---|---|
| NotInitialized | Not Initialized | 초기화 필요 | 초기화가 수행되지 않은 상태 | 초기화 안내 팝업, 초기화 관련 메뉴만 접근 가능 |
| Initializing | Initializing | 초기화 중 | 초기화 진행 중 | 로딩 · 진행바 표시, 모든 기능 제한, 완료 시 「준비 완료」 전환 · 안내 |
| Ready | Ready | 준비 완료 | 검사를 시작할 수 있는 상태 | 모든 기능 사용 가능, 작업 시작 버튼 활성화 |
| Running | Running | 가동 중 | 검사 정상 진행 중 (모듈 1대라도 Running, Error 없음) | 중지(Stop) 기능 제공 |
| PartialRunning | Partial Running | 부분 가동 중 | 일부 모듈 Running, 일부 Paused 또는 Error | |
| Stopping | Stopping | 가동 중지 중 | 사용자 Run Stop 요청으로 정지 중 (전체 장비 Stop) | 중지 진행 팝업 · 진행바, 모든 기능 일시 제한, 완료 시 「준비 완료」 |
| Paused | Paused | 일시 정지 | 일부 모듈 Paused, Running 모듈 없음 | |
| Error | Error | 오류 | 가동 중 모든 모듈 Error, 또는 비가동 중 일부 모듈 Error | 상황별 상이 |

**구동 컨트롤러 (버튼)**

| 버튼 | 내용 | 활성화 조건 |
|---|---|---|
| Initialize | 장비 초기화 | Not Initialized 상태 |
| Stop | 진행 중인 검사 중단(폐기) → Initializing → Ready | Running · Partial Running |
| Run | 검사 실행, 「Run Preparation」 페이지로 진입 | Ready · Running · Partial Running |
| Quick Start | Run Preparation 3~4단계 대신 요약 팝업 하나로 검사 실행 | (Run과 같음) |

**장비 통합 상태 처리 조건 (요약)**

- 부팅 후 초기화 전: 모든 모듈 NotInitialized. 아닌 모듈이 있으면 Error.
- Initialize 클릭 → Initializing → 완료 신호 + 모든 모듈 Ready → Ready.
- Run Start 클릭 → Running. 모든 모듈 Ready 또는 Running이면 Running 유지. Run 완료 전에는 모든 모듈이 Ready여도 Running 유지.
- (Running ≥ 1) AND (Pausing · Paused · Error ≥ 1) → PartialRunning.
- Run Stop 클릭 → Stopping, 완료 신호까지 유지.
- Paused ≥ 1 AND Running = 0 AND Pausing = 0 AND Error = 0 → Paused.
- Error ≥ 1 AND Running = 0 AND Pausing = 0 → Error. 통신 단절 · 프로그램 오류는 즉시 Error.
- ※ Run 완료: Prep · Dx에 할당된 모든 검체의 검사가 끝나고 결과가 D.A PC를 통해 T-IOS로 모두 전달된 경우(L-IOS에서 최종 판단).

### 4-b. Consumables and Reagents (5/5) · 수량 표기

소모품 · 시약의 재고 수량을 수량과 입고 단위 개수로 표기하는 형식을 정의한다. `n` = 시스템이 카운팅해 보유한 입고 단위 개수.

![COMM-4-b(5/5)](images/comm-4-b-5.png)
*COMM-4-b(5/5)*

| 구분 | 형식 | 예 |
|---|---|---|
| 소모품 · 묶음 입고 | `{수량} ea ({n} {단위})` | 480 ea (5 racks), 14 ea (1 socket) |
| 소모품 · 낱개 입고 | `{수량} ea` | 100 ea, 200 ea |
| 시약 | `{수량} rxns ({n} {단위})` | 200 rxns (2 racks), 288 rxns (3 DWPs) |

- **단수 · 복수**: 단위가 1개면 단수, 2개 이상이면 복수(단위명 뒤에 s) — `1 rack / 2 racks`, `1 tube / 2 tubes`, `1 DWP / 2 DWPs`, `1 set / 2 sets`, `1 socket / 2 sockets`
- **묶음 아이템**: 구성품 수량을 합산하지 않는다(구성품 수량이 모두 같다는 전제).
- baseUnit이 ea인 아이템(예: Buffer Cartridge Cap)은 `15 ea (3 sets)`처럼 표기한다.

| 항목 | 규칙 |
|---|---|
| 정의 | 긴 페이지를 스크롤할 때 화면 최상단으로 쉽고 빠르게 돌아가게 하는 퀵 컨트롤 |
| 노출 | 화면을 1개 화면 높이(1 Viewport, PC 500px 기준) 이상 내렸을 때 화면 우측 하단에 플로팅으로 페이드인 |
| 미노출 | 화면 최상단(Top: 0)에 도달하면 자동 페이드아웃 |
| 상태 | Enabled · Pressed · Focused |

### 5-d. Calendar

년 · 월 · 일을 확인하거나 선택하는 기능을 제공한다. (기존 COMM-5-d)

![COMM-5-d](images/comm-5-d.png)
*COMM-5-d · Calendar*

**Type 1 · Date Calendar**

| 항목 | 규칙 |
|---|---|
| 정의 | 날짜(년/월/일)를 확인 · 선택하는 캘린더. 시작 · 종료 두 달을 나란히 보여 준다 |
| 동작 | 날짜 입력 필드를 선택하면 필드 아래에 노출. 하루 또는 기간(시작일 ~ 종료일)을 선택하고 선택한 값은 하단에 표시. `Done`을 선택하면 입력 필드에 반영되고 아이콘이 완료 상태로 바뀜. `Done` 없이 입력 필드를 다시 선택하면 닫히고 Default로 초기화 |
| 조건 | 최초 진입 시 Default(오늘 기준 7일 전 ~ 오늘) 선택. 선택일로부터 최대 1년까지 선택 가능. 오늘 이후 날짜는 선택 불가. 날짜를 고르기 전에는 `Done` 비활성 |
| 표기 | 기간은 `YYYY-MM-DD ~ YYYY-MM-DD` (예: 2026-03-03 ~ 2026-03-09), 달 제목은 `YYYY.MM` |

| 번호 | 영역 | 동작 |
|---|---|---|
| 1 | ∨ 아이콘 | 선택 시 연 · 월 드롭다운 노출. 연 · 월을 고르면 해당 달로 이동 |
| 2 | `< >` 버튼 | 이전 · 다음 달로 이동 |

| 상태 | 설명 |
|---|---|
| 오늘 | 오늘 날짜 표시 (선택하면 선택 표시) |
| 선택 | 하루를 선택한 날짜 |
| 기간 선택 | 시작일 · 종료일은 선택 표시, 사이 날짜는 범위로 이어짐 |
| 선택 불가 | 선택 범위 밖 날짜 |

**Type 2 · Month Calendar**

| 항목 | 규칙 |
|---|---|
| 정의 | 월을 선택하는 캘린더. 시작 · 종료 두 해를 나란히 보여 준다 |
| 동작 | 월 입력 필드를 선택하면 필드 아래에 노출. 시작 월 ~ 종료 월을 선택. `Done` 등 완료 동작은 Date Calendar와 같음 |
| 조건 | 이번 달을 선택하면 어제까지의 합계를 보여 줌 (하단 안내 `* Current Month : Total up to yesterday`) |
| 표기 | `YYYY-MM ~ YYYY-MM` (예: 2025-12 ~ 2026-02) |

- 영역: 1 `< >` 버튼 — 이전 · 다음 연도로 이동
- 상태: 이번 달(이번 달 표시, 선택하면 선택 표시) · 선택(선택한 달) · 기간 선택(시작 월부터 종료 월까지 모두 선택 표시) · 선택 불가(선택할 수 없는 달)

### 5-e. Chips

콘텐츠를 구분해 제공할 때 쓴다. 임시 상태가 아닌 완결성 있는 메뉴 영역에서 쓸 수 있다. (기존 COMM-5-e · 목차 기준 새 CID는 `COMM-5-f`)

![COMM-5-e](images/comm-5-e.png)
*COMM-5-e · Chips (Figma 프레임 이름 기준)*

| 항목 | Type 1 · Filter Chip | Type 2 · Anchor Chip |
|---|---|---|
| 정의 | 여러 항목을 선택할 수 있는 칩. 여러 옵션을 선택해 목록을 넓힐 수 있음 | 목록 안의 특정 카드 위치로 바로 이동하는 칩. 지금 보고 있는 위치를 선택 상태로 표시 |
| 동작 | 칩을 선택하면 그 칩의 콘텐츠만 표시. 다시 선택하면 해제되고 전체 콘텐츠 표시. 여러 칩을 동시에 선택하면 선택한 칩의 콘텐츠를 모두 표시 | 칩을 선택하면 해당 카드가 목록 맨 위에 오도록 이동. 스크롤하면 맨 위에 있는 카드의 칩이 선택됨 |
| 조건 | Default: 모든 칩이 선택되지 않은 상태(전체 콘텐츠 노출). 텍스트 뒤 아이콘은 항목 상태(필요할 때만), 숫자는 건수 | Default: 첫 번째 칩 선택. 한 번에 하나만 선택되며 다시 선택해도 해제되지 않음 |
| 상태 | Unselected · Selected | Unselected · Selected |
| 크기(높이) | L 40px · S 32px (예시는 L 기준) | L 40px · S 32px (예시는 L 기준) |

### 5-n. Scroll Bar

제한된 영역을 넘는 콘텐츠는 스크롤로 영역 안에서 이동한다. (기존 COMM-5-k)

![COMM-5-n](images/comm-5-n.png)
*COMM-5-n · Scroll Bar*

| Case | 이름 | 정의 | 동작 |
|---|---|---|---|
| Case 1 | Title 영역 고정 | 콘텐츠가 특이 케이스 없이 단순 나열되는 가장 기본적인 스크롤 | 최상단 Title 영역은 화면 상단에 상시 고정, 하위 Content 영역만 Title 아래로 스크롤 |
| Case 2 | 상단 Title 및 Tab 고정 | 상단 Title 아래에 카테고리 · 메뉴 이동용 Tab이 있는 경우 | Title과 Tab 영역 모두 상단에 상시 고정, Content 영역만 두 영역 아래로 스크롤 |
| Case 3 | 하단 플로팅 / 고정 | 저장하기 등 최종 과업을 위한 핵심 액션 버튼(CTA)이 있는 경우 | 콘텐츠 양 · 스크롤 여부와 상관없이 핵심 버튼이 화면 최하단(Bottom)에 상시 고정. Content 영역은 하단 버튼 위까지만 스크롤 |

| Case | 번호 · 영역 | 동작 |
|---|---|---|
| Case 1 | 1 Title 영역 | 상시 고정 |
| Case 1 | 2 Content 영역 | Title 영역 아래로 스크롤 |
| Case 2 | 1 Title 영역 | 상시 고정 |
| Case 2 | 2 Tab 영역 | 상시 고정 |
| Case 2 | 3 Content 영역 | Title · Tab 영역 아래로 스크롤 |
| Case 3 | 1 Content 영역 | 하단 버튼 상단까지만 스크롤 |
| Case 3 | 2 고정 영역 | 화면 최하단에 상시 고정 |
