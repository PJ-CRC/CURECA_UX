# 팀 프로그램과 7단계 흐름 — 넘어야 할 허들

> 상태: 분석 1차 (2026-11-09). 팀 프로그램 v0.17.1(2026-11-09 릴리즈)과 같은 날 대표 저장소(history 브랜치) 사본을 읽고, 7단계 흐름(`background/work-flow-draft.md`)을 프로그램에서 돌릴 때 막히는 곳을 정리했습니다. 프로그램은 담당자와 함께 고칠 것이라, "우리 규칙에서 넘는 법"과 "요청서에 넣을 것"을 나눠 적었습니다.

## 1. 프로그램이 일하는 방식 (우리 흐름에 걸리는 것만)

## 4. 바로 쓸 수 있는 것 (설계에 반영)

- **새 세션 = 다른 눈:** 4단계 검토 에이전트는 Agent 도구 없이도, "검토" 요청을 따로 보내면 그린 세션과 다른 세션이 봄
- **보류 + `ask`:** 요청자 확인 관문을 그대로 얹을 수 있음
- **정리안 → 확인 · 반영 (`answer` → `answer-apply`):** 방향 A "결정 반영"의 "정리해 보여 주고 확인받은 뒤 반영"과 같은 모양
- **연관 항목 찾기:** 방향 B "영향 화면 찾기"와 같은 일. 규칙(찾는 곳 표)을 한 곳에 두면 프로그램도 그 표를 따르게 할 수 있음

## 5. 0단계 정할 것 1에 주는 영향

프로그램의 작업 기준은 **"어느 문서를 적용했나"(제목)**이고, 내용은 그 문서의 가장 최근 수정본입니다. 그래서 "무엇을 기준으로 그렸나"를 남기려면 **문서 제목 + 그때 수정본 번호**가 함께 있어야 합니다. 2026-11-09 결정(H4)으로 공통 4종은 팀 기준 하나, UX가이드만 Figma 파일마다 고릅니다.

안: 화면 MD 머리말과 작업 기록에

```yaml
basis: 2026-11-10 14:00 · Common UX - PC (g20261028-brex-06-J003)
basis_versions:
  rules: CURECA 작업규칙 @20261109-093829_brex-01
  policy: CURECA 정책서 @…
  glossary: 기준데이터 @…
  screens: 화면 정의서 @…
  ux_guide: Common UX - PC @…
```

- **2026-11-10 정함:** 시각 하나로 그때의 최신본을 모두 다시 찾을 수 있지만, 담당자가 바로 확인할 수 있게 분류별 수정본 번호도 함께 남김. 수정본이 없는 문서는 `@원본`
- `ux_guide`는 그 Figma 파일에 고른 가이드. 모바일 파일이면 모바일 Common UX
- 프로그램이 답변 `작업 기준` 줄에 수정본 번호까지 적어 주면(H4 요청), Claude는 그 줄을 그대로 옮기면 됨
