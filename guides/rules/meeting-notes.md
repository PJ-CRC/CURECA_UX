# 회의록

> 상태: 초안 v0.5 (2026-11-04). v0.5에서 점검 결과의 확인 필요를 [처리하기] → Claude와 대화해 정리하고 커밋하는 방법을 더함(6절 "점검 결과 처리"). v0.4에서 v0.4에서 완료는 누구나 [완료하기]로 정하고(8절 1번 닫음), 새 회의록의 참석자 기본값과 날짜 · 시간 · 참석자를 언제든 고치는 방법을 더함(5절). v0.3에서 v0.3에서 상태값 "정리 완료"를 "완료"로, 버튼 [회의록 합치기]를 [요약/분석하기]로 바꾸고, 회의록 취소와 완료할 때 답을 못 받은 안건 처리를 더함(5절). v0.2에서 합친 뒤 점검(정책서 · 임시 정책 · 논의 항목과 맞대어 중복 거르기, 빠뜨림 점검)을 더함(6절). 완료 방법, 요약/분석 화면, 회의록에서 안건에 답하는 방법은 목업으로 함께 정합니다(8절).

고객 회의의 회의록을 저장소에 남기고, 팀 프로그램에서 보고 작성합니다. 회의에서 받은 답은 논의·결정 항목에 반영하고, 회의에서 나온 정책은 임시 정책으로 이어지게 합니다. 회의 ID를 근거로 남겨, 어떤 정책이 어느 회의에서 정해졌는지 추적합니다.

## 1. 대상과 원본

- 대상은 **고객 회의**(고객사가 참석한 회의)입니다. 내부 논의는 회의록을 따로 쓰지 않고, 논의·결정의 내부 논의 목록에서 처리합니다.
- 원본은 저장소 `meetings/` 폴더입니다. 회의 하나에 파일 하나: `meetings/MT-YYYYMMDD-NN.md`
- 스프레드시트 0.회의록 탭은 2026-11-04까지의 기록을 옮긴 뒤 보관용으로만 둡니다. 새 회의록은 쓰지 않습니다.
- 팀 프로그램의 일정/작업 > 회의록 탭에서 보고 작성합니다. 주간 진행 현황의 회의 내역도 `meetings/`에서 읽습니다.

## 2. 회의 ID

- 형식: `MT-YYYYMMDD-NN` (회의 날짜 + 그날 순번). 순번은 시작 시각 순으로 01부터 붙입니다.
- 회의에서 정해진 것을 반영할 때 근거 칸에 회의 ID를 적습니다.

| 반영하는 곳 | 회의 ID를 적는 칸 |
| --- | --- |
| 고객 논의 목록 (`customer-agenda/agenda.md`) | 결정 칸의 근거 |
| 정책서 | 근거 절, 변경 이력 표의 근거 |
| 임시 정책 | 이유와 근거 |

## 3. 파일 구성

`templates/meeting.md`를 씁니다.

| 칸 | 내용 |
| --- | --- |
| 머리말 | `id`, `date`, `time`, `title`(주제), `attendees`(고객사 · 브렉스), `writers`(작성한 사람의 프로그램 아이디), `status`, `agenda`(회의 안건으로 올린 논의·결정 ID), `source` |
| 안건 | 회의 안건으로 올린 논의·결정 항목과 회의에서 받은 답 |
| 내용 | 주제별 `[주제]` 묶음으로 적은 회의 내용 |
| 결정 | 회의에서 정해진 것 |
| 할 일 | 담당 · 기한 · 내용 |
| 정책 후보 | Claude가 뽑은 신규 · 변경 정책 후보와 처리 결과 |
| 점검 결과 | 이미 정책 · 임시 정책에 있는 것, 논의 항목과 관련된 것, 빠뜨림 점검의 확인 필요 (6절) |
| 기타 | 위에 넣기 어려운 것 (운영 후 검토 사항 등) |
| 작성본 | 각자 작성본 목록 |

`status` 값: 작성 중 · 완료 · 원문(과거 회의록을 원문 그대로 옮긴 것)

## 4. 회의 전: 회의 안건 올리기

- 논의·결정 항목에서 [회의 안건으로 올리기]를 누르면, 그 항목이 다음 고객 회의의 안건 목록(`meetings/next-agenda.md`)에 들어갑니다.
- 회의록을 새로 만들면 안건 목록의 항목이 그 회의록의 `agenda`와 "안건" 절로 옮겨집니다.

## 5. 회의 후: 작성, 요약/분석, 완료

0. **새 회의록 · 취소:** [+ 새 회의록]을 누르면 `작성 중` 회의록이 만들어지고, 다음 회의 안건이 이 회의록의 안건으로 옮겨집니다. 참석자 기본값은 씨젠 - 김의식, 노경민 / 브렉스 - 서보경, 정다예, 하승현, 이상헌입니다. `작성 중`인 동안은 [회의록 취소]로 지울 수 있습니다. 취소하면 회의록과 작성본을 지우고, 안건은 다음 회의 안건 목록으로 되돌립니다. `완료`된 회의록은 취소하지 않습니다.
1. **각자 작성:** 참석한 사람(2~4명)이 각자 프로그램 아이디로 작성본을 씁니다. 작성본은 `meetings/drafts/{회의 ID}/{아이디}.md`에 임시로 둡니다.
2. **요약/분석:** [요약/분석하기]를 누르면 Claude가 작성본을 합쳐 정리본(`meetings/{회의 ID}.md`)을 만들고, 이어서 점검(6절)까지 합니다.
   - 같은 내용은 하나로 합치고, 한 사람만 적은 내용도 빠뜨리지 않습니다.
   - 서로 다르게 적은 곳은 정리본에 "확인 필요"로 표시하고 각자 적은 문장을 함께 남깁니다.
   - 작성본에 없는 내용을 더하지 않습니다(헌법 7조).
   - 작성본이 새로 들어오거나 고쳐지면 다시 합칠 수 있고, 그때 점검도 다시 합니다.
3. **안건 답하기:** 회의에서 받은 답을 안건에 반영하는 방법은 목업으로 함께 정합니다(8절). 반영할 때는 `rules/discussion-answer.md` 순서를 따르고, 근거 칸에 회의 ID를 적습니다.
4. **완료:** 요약/분석한 뒤 정리본을 확인하고 [완료하기]를 누르면 `완료`가 됩니다. [완료하기]는 누구나 누를 수 있습니다(2026-11-04 사용자 결정).
   - 완료할 때 회의에서 답을 받지 못한 안건은 이 회의록의 안건 목록(머리말 `agenda`, "안건" 절)에서 뺍니다. 논의·결정 항목은 그대로 남으니, 다음 회의에서 다시 다루려면 [회의 안건으로 올리기]를 다시 누릅니다.
   - 완료한 회의록 화면에서 작성본은 맨 아래에 접어 두고, [내용 보기]를 눌러야 펼쳐집니다.

**일시 · 참석자 고치기:** 날짜 · 시간 · 참석자(씨젠 · 브렉스)는 상태(작성 중 · 완료)와 관계없이 언제든 화면에서 바로 고칩니다. 과거 원문 회의록(`status: 원문`)은 원문 그대로 두므로 고치지 않습니다(7절).

- 날짜를 바꾸면 회의 ID를 새 날짜로 다시 붙입니다(2절 형식, 그날 순번은 이어서). 회의록 파일 · 작성본 폴더 이름과, 이미 이 회의 ID를 근거로 적은 곳(임시 정책 · 고객 논의 목록 · 정책서)도 함께 고칩니다.

## 6. 합친 뒤 점검과 정책 후보

합친 정리본을 지금의 정책 · 임시 정책 · 논의 항목과 맞대어 보고, 이미 있는 것은 거르고 새로 필요하거나 바뀌는 것만 정책 후보로 뽑습니다. 중복 등록과 빠뜨림을 막기 위해서입니다.

### 읽는 것

| 자료 | 위치 | 보는 것 |
| --- | --- | --- |
| 정책서 | `policy/{영역}/POL-*.md` | 정의 · 규칙 · 예외. 머리말의 `menus` · `cids`로 관련 정책을 먼저 좁힘 |
| 임시 정책 | `provisional/` (승인 대기 · 승인) | 바꾸는 정책과 바꾸는 내용 |
| 논의 항목 | `customer-agenda/agenda.md`, `pending/` | 같은 주제의 고객 논의 · 협의 대기 |
| 용어집 · 상태값 | `glossary/` | 회의 문장의 표현을 표준어로 맞춤 |

### 회의 문장마다 나누기

정리본의 내용 · 결정에서 정책이 될 만한 문장마다 다음 중 하나로 나눕니다.

| 결과 | 뜻 | 처리 |
| --- | --- | --- |
| 정책에 있음 | 지금 정책 규칙과 같은 내용 | 점검 결과에 "정책에 있음 (POL-… 규칙 n)"으로 남김. 후보로 올리지 않음 |
| 변경 | 지금 정책 규칙과 다른 내용 | 정책 후보 "변경". 바꾸는 정책 · 규칙 번호와 지금 규칙 문장을 함께 적음 |
| 신규 | 어느 정책에도 없는 내용 | 정책 후보 "신규". 넣을 정책(또는 새 정책 영역)을 적음 |
| 임시 정책에 있음 | 승인 대기 임시 정책과 같은 내용 | 후보로 올리지 않고 "PV-… 에 있음"으로 남김. 그 임시 정책의 근거에 회의 ID를 더할지는 [처리하기]로 정함(아래 "점검 결과 처리") |
| 임시 정책과 다름 | 승인 대기 임시 정책과 같은 규칙을 다르게 정함 | 정책 후보로 올리고 "PV-… 와 다름"을 표시. 등록하면 A/B 선택 문서로 합침(`rules/provisional-policy.md` 6절) |
| 논의 항목과 관련 | 고객 논의 · 협의 대기 항목에 대한 답 | 그 항목 ID를 붙여 안건 답하기로 넘김(5절 3번) |

### 빠뜨림 점검

- 안건으로 올린 항목 중 정리본에 답이 없는 것
- 결정 문장 중 위 분류가 안 된 것 (어느 정책과 이어지는지 모름)
- 할 일 중 담당이나 기한이 없는 것
- 작성본끼리 다르게 적은 곳 (5절 2번)
- 용어집의 쓰지 않는 표현

점검 결과는 정리본의 "점검 결과" 절에 적습니다. 위 항목은 "확인 필요"로 표시합니다.

### 점검 결과 처리

"확인 필요"인 줄과 "임시 정책에 있음"인 줄에는 **[처리하기]**가 있습니다. 누르면 논의·결정의 [답변하기]처럼 Claude와 대화하는 창이 열리고, 같은 순서(`rules/discussion-answer.md` 3절)로 처리합니다.

1. **Claude가 묻기:** 무엇을 확인해야 하는지 묻습니다(아래 표).
2. **답하기:** 사람이 답합니다.
3. **정리해 보여 주기:** Claude가 바뀌는 것을 정리해 보여 줍니다. 고칠 점을 말하면 다시 정리합니다.
4. **확인하고 커밋:** 확인하면 정리본(과 아래 표의 함께 바뀌는 곳)을 한 커밋으로 묶습니다. 커밋 메시지에 회의 ID를 적습니다. 그 줄은 "처리함 (아이디 · 날짜)"이 됩니다.

| 경우 | Claude가 묻는 것 | 바뀌는 것 |
| --- | --- | --- |
| 작성본끼리 다름 | 각자 적은 문장을 보여 주고, 회의에서 정해진 쪽이 무엇인지 | 정리본 문장, 관련 안건의 답 |
| 안건 답 없음 | 회의에서 받은 답이 있는지, 다음 회의에서 다시 다룰지 | 안건의 답, 또는 다음 회의 안건(`meetings/next-agenda.md`)에 다시 올림 |
| 할 일 담당 · 기한 없음 | 누가 언제까지 할지 | 할 일 표 (일정 시트 반영은 일정 관리 담당자) |
| 결정이 어느 정책과 이어지는지 모름 | 관련 정책이 있는지, 새 정책 후보인지, 정책과 상관없는 결정인지 | 점검 결과 분류, 또는 정책 후보 추가 |
| 쓰지 않는 표현 | Claude가 제안한 표준어로 바꿀지 | 정리본 문장 |
| 임시 정책에 있음 | 그 임시 정책의 이유와 근거에 회의 ID를 더할지 | 임시 정책 파일의 이유와 근거 |

- [처리하기]는 **누구나** 누를 수 있고, 완료 전후 언제든 쓸 수 있습니다.
- 처리하지 않은 줄이 있어도 [완료하기]는 막지 않고 알리기만 합니다. 그 줄은 "미처리"로 남습니다.
- 대화에서 정해지지 않은 것은 만들어 넣지 않고 다시 "확인 필요"로 둡니다(헌법 7조).

### 정리본에 남는 것

| 무엇 | 처리 |
| --- | --- |
| 결정 | "결정" 절에 정리 |
| 할 일 | "할 일" 절에 담당 · 기한 · 내용으로 정리. 일정 시트 반영은 일정 관리 담당자가 함 |
| 정책 후보 | 신규 · 변경 후보를 목록으로 보여 주고, 항목마다 **[임시 정책으로 등록] / [제외]** |
| 점검 결과 | 정책에 있음 · 임시 정책에 있음 목록과 빠뜨림 점검의 확인 필요. 줄마다 [처리하기] |

- 정책 후보 버튼은 **누구나** 누를 수 있습니다(2026-11-04 사용자 결정).
- [임시 정책으로 등록]을 누르면 `rules/provisional-policy.md` 순서로 등록합니다(겹치는 임시 정책 확인 포함). 이유와 근거에 회의 ID를 적습니다. 영향 화면은 PV의 "영향 화면"에 적고, 반영 대기 목록 줄은 그 임시 정책이 승인될 때 만듭니다(근거 칸에 회의 ID와 PV ID, `rules/screen-spec.md` 4절). 등록된 임시 정책의 승인은 그 룰을 따릅니다.
- [제외]한 후보도 지우지 않고 "제외"로 남깁니다.

## 7. 과거 회의록 (스프레드시트에서 옮긴 것)

- 2026-06-09 ~ 2026-11-03 회의 43건을 원문 그대로 옮겼습니다(`status: 원문`, `source: 스프레드시트 0.회의록`). 원문의 "내용"과 "기타"를 같은 이름의 절에 글자 그대로(코드 블록) 두고, 안건 · 결정 · 할 일 · 정책 후보 절은 두지 않습니다. 고객사 · 브렉스 참석자 이름도 원문 그대로 옮겼습니다.
- 과거 회의록에서 결정 · 할 일 · 정책 후보를 뽑는 일은 하지 않습니다(2026-11-04 사용자 결정).
- 원문의 요일 · 오타는 고치지 않습니다. 날짜와 요일이 맞지 않으면 머리말 아래에 "확인 필요"로 적습니다.

## 8. 정할 것

1. ~~완료: 누가, 언제 완료할지~~ → 누구나 [완료하기] (2026-11-04 정함, 5절 4번)
2. 요약/분석 화면과 프로그램 아이디 구분 (목업으로 함께 정함)
3. 회의록 화면에서 안건에 답하는 방법 (안건을 누르면 [답변하기] 창을 띄울지 등, 목업으로 함께 정함)
4. 회의 중 새로 나온 고객 질문을 고객 논의 목록에 새 항목으로 올리는 방법
5. 완료한 뒤 각자 작성본을 계속 보관할지 (지금 목업은 접어서 보관)
6. 답을 못 받은 안건을 다음 회의 안건으로 자동으로 다시 올릴지 (지금은 사람이 다시 올림)
