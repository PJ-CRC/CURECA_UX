## 3. 상태값

| 칸 | 값 (시트 드롭다운 그대로) |
| --- | --- |
| UX 상태 | 진행 중 · 리뷰 중(예정) · 디크 검토 · 완료 · 업무 범위 제외 |
| UI 상태 | 대기 · 진행 중 · 리뷰 중(예정) · 완료 · 작업필요X · 업무 범위 제외 |

| 값 | 뜻 |
| --- | --- |
| (빈 칸) | 시작 전 |
| 대기 | (UI) UX가 컨펌 완료되어 UI를 시작할 수 있음 |
| 진행 중 | 화면을 작업하는 중 |
| 리뷰 중(예정) | 리뷰를 기다리거나 받는 중 |
| 디크 검토 | (UX) 리뷰가 끝나 화면이 정해진 뒤, 디스크립션을 마지막으로 확인하는 단계. 리뷰 중에는 화면이 계속 바뀌므로 디스크립션은 마지막에 확인함 |
| 완료 | 끝남. UX는 담당자가 직접, UI는 Figma 상태를 따라 자동 |
| 작업필요X | (UI) 이 업무에 UI 작업이 없음 |
| 업무 범위 제외 | 이번 범위에서 빠짐. 세지 않음 |

흐름은 이렇습니다.

```
UX 상태:  (빈 칸) → 진행 중 → 리뷰 중(예정) → 디크 검토 → 완료(담당자가 직접)
UI 상태:  (빈 칸) → 대기(UX 컨펌 완료 때) → 진행 중 → 리뷰 중(예정) → 완료
          UI 작업이 없으면 작업필요X
```

## 4. Figma 화면설계서 상태와 연동

> **2026-11-04:** Figma 상태 표시는 신규 작업방의 메뉴 상태 카드로 정했습니다(`rules/screen-spec.md` 5절, PD-0006 A안). 카드 하나가 3.메뉴 탭 값 하나라 시트 메뉴 칸과 1:1로 맞습니다. 자동 연결은 팀 프로그램 R23이 생기면 시작하고, 그때까지 일정 상태는 담당자가 시트에서 직접 바꿉니다.

작업자는 Figma에서 화면설계서 상태를 바꿉니다. 그 상태가 메뉴 상태(`screens/{메뉴}/_menu.md`, `rules/status-lifecycle.md`)에 반영되면, 일정에서 같은 메뉴의 줄 상태도 자동으로 바뀝니다.

```
Figma 화면설계서 상태 → 메뉴 상태 (_menu.md) → 일정 상태 (시트 K · L 칸)
```

| 메뉴 상태 카드 | UX 상태 (K) | UI 상태 (L) |
| --- | --- | --- |
| UX 작업 중 | 진행 중 | - |
| UX 컨펌 중 | 리뷰 중(예정) | - |
| UX 컨펌 완료 | 디크 검토 | 대기 |
| UI 작업 중 | - | 진행 중 |
| UI 컨펌 대기 중 | - | 리뷰 중(예정) |
| UI 컨펌 완료 | - | 완료 |

- 바꾸는 줄: 메뉴 칸이 그 카드의 메뉴(3.메뉴 탭 값)인 줄 중, 그 칸의 상태가 "완료" · "작업필요X" · "업무 범위 제외"가 아닌 줄.
- 상태가 자동으로 바뀌면 일정 탭에 "Figma에서 반영" 표시와 바뀐 시각을 남깁니다.
- 연결한 뒤에도 시트에서 손으로 바꾸는 상태는 UX의 완료, UI의 작업필요X, 양쪽의 업무 범위 제외입니다. 나머지는 Figma 상태를 따라 바뀝니다.
