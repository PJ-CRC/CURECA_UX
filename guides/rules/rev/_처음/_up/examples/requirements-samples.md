## 요건 목록 예시 (요건 넷)

`flow/1-requirements.md` "요건 목록 틀"의 모양대로 쓴 예입니다. 그 문서에는 요건 3 · 4만 남겼습니다. 요건 1은 짝 화면을 함께 고침, 요건 2는 작업 대상 `미정`, 요건 3은 짝 화면을 고치지 않음과 바뀐 기록(취소선 · `바뀜`), 요건 4는 작업 도중 더해진 새 화면을 보여 줍니다.

```markdown
### 요건 1. Event 상세에 Effect 항목 추가
- 요청 상태: 최초
- 경로 분기 기준 (근거) · 읽는 강도: 3 동작 · 조건 · 값 · 순서가 바뀜 (Effect 값이 Scenario Code 설명에서 옴) · 정책 전부
- 지나가는 단계: 1 → 2 → 3 → 4 → 5
- UI 작업: 대상 (요소가 생김)

| 대상 화면 | 케이스 | 작업 대상 | 근거 |
| --- | --- | --- | --- |
| Event History Detail (TI-EVT-01-P) | 1 | O | |
| Event History Detail (LI-EVT-01-P) | 1 | O | 짝 화면 · 함께 고침 (두 화면에 같은 Effect 항목) |

### 요건 2. Event Popup에 Effect 항목 추가
- 요청 상태: 최초
- 경로 분기 기준 (근거) · 읽는 강도: 3 동작 · 조건 · 값 · 순서가 바뀜 (요건 1과 같음) · 정책 전부
- 지나가는 단계: 1 → 2 → 3 → 4 → 5
- UI 작업: 대상 (요소가 생김)

| 대상 화면 | 케이스 | 작업 대상 | 근거 |
| --- | --- | --- | --- |
| Event Message Popup (TI-EVT-02-P) | 1 | O | |
| Event Message Popup (LI-EVT-02-P) | 1 | 미정 | |

### 요건 3. [Export] 버튼 이름을 [Download]로
- 요청 상태: 최초
- 경로 분기 기준 (근거) · 읽는 강도: ~~1 글자 · 표기만 (버튼 이름만 바뀜) · 가볍게~~ 3 동작 · 조건 · 값 · 순서가 바뀜 (내보내기 범위 정책과 이어짐) · 정책 전부 `바뀜 (11-21, Claude, 2단계에서 정책을 읽음)`
- 지나가는 단계: 1 → 2 → 3 → 4 → 5
- UI 작업: 대상 (화면 표기 글자가 바뀜)

| 대상 화면 | 케이스 | 작업 대상 | 근거 |
| --- | --- | --- | --- |
| Event History (TI-EVT-P) | 1 | O | |
| Event History (LI-EVT-P) | 1 | X | 짝 화면 · 고치지 않음 (요청 글: T-IOS만) |

### 요건 4. [Download] 전에 내보낼 범위를 고르는 Popup
- 요청 상태: 추가 (11-20, 고객, 고객 검토에서 더함)
- 경로 분기 기준 (근거) · 읽는 강도: 6 화면이 생김 (IA에 없는 새 화면) · 정책 전부
- 지나가는 단계: 1 → 2 → 3 (구상부터) → 4 → 5 (IA 반영)
- UI 작업: 대상 (새 화면)

| 대상 화면 | 케이스 | 작업 대상 | 근거 |
| --- | --- | --- | --- |
| 새 화면 (내보낼 범위 선택) | 2 | O | 새 화면 · 대상 (Event History [Download]에서 여는 별도 Popup) |

작업이 지나가는 단계: 1 → 2 → 3 → 4 → 5
```
