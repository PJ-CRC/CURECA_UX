# Claude 작업 지침 (진입점)

> 상태: v0.3 (2026-11-14). 화면설계 흐름을 1 ~ 5단계로 새로 쓰는 중입니다(`flow/`). 예전 규칙은 `old-rules/`로 옮겼고 작업 근거로 쓰지 않습니다. 예전 0 ~ 6단계 문서(`old-flow/`)는 2026-11-17에 지웠습니다(git 기록에 있음).

이 파일은 Claude가 이 저장소에서 작업을 시작할 때 가장 먼저 읽는 파일입니다. 여기에는 무엇을 어떤 순서로 읽는지만 두고, 절차는 `flow/`의 단계 문서에, 쓰는 법은 `reference-rules/`에 둡니다.

## 작업 시작 순서

1. [constitution.md](constitution.md) — 헌법. 모든 문서와 작업에 우선합니다.
2. 요청이 무엇인지 아래 표로 가릅니다. 애매하면 시작 전에 묻습니다.
3. 가른 문서를 읽고 그 순서대로 진행합니다. 근거는 저장소입니다(헌법 7조). 대화에서 정한 것도 작업 기록 · 문서에 적어야 근거가 됩니다.

| 요청 | 읽을 문서 |
| --- | --- |
| **화면설계** (화면이나 화면에 미치는 정책을 바꾸는 요청. 화면 부분 수정(고도화) · 신규 · 기존 화면 다시 그리기) | [flow/README.md](flow/README.md) → [flow/1-requirements.md](flow/1-requirements.md)부터 단계 순서대로. 한 작업은 한 대화에서 단계를 이어 가고, 단계를 넘어갈 때마다 다음 단계 문서를 처음부터 다시 읽음. 작업 기록은 처음부터 읽지 않고, 새 대화로 이어 갈 때 끊긴 곳(`이어서 작업할 곳:` 줄)부터 읽음(`flow/README.md` "단계 전환") |
| 끊긴 화면설계 작업 이어 가기, "열린 작업 리스트 보여 줘" | [reference-rules/work-log.md](reference-rules/work-log.md) "끊긴 작업 이어 가기" |
| 논의 대상: 올리기 · "논의 리스트 보여 줘" · 결정 반영 · 후속 확인 답 · 같은 질문 합치기 | [reference-rules/discussions.md](reference-rules/discussions.md) |
| 반영 대기: "○○ 반영 대기 보여 줘" · "주기 점검 해 줘" | [reference-rules/pending-changes.md](reference-rules/pending-changes.md) |
| 흐름 · 규칙 문서(`flow/` · `reference-rules/`)를 쓰거나 고치기 | [flow/README.md](flow/README.md) "단계 문서 쓰는 법" |
| 질문 · 자료 찾기 | 저장소에서 찾아 답함. 흐름을 타지 않음 |
| 그 밖 (회의록 정리, 정책서 쓰기, 언어셋, 용어 검토, 일정) | 아래 "아직 새 문서가 없는 일" |

- 정책을 바꾸는 요청은 화면에 미칠 수 있으면 화면설계(1단계부터)로, 화면과 상관없는 정책서 정리(문장 다듬기, 근거 달기, 정책 ID 정리 등)만 "그 밖"으로 가릅니다.
- 화면설계 요청은 요청자가 케이스를 고르지 않습니다. 케이스는 1단계에서 요건마다 붙습니다.

| 1 시작 · 요건 정의 · 2 근거 · 분석 | 초안. 이 문서로 작업하고 테스트함 |

| 4 수정 · 확인 | 초안(2026-11-16). 작업 기록 틀에 맞출 것이 남아 있음(`background/todo.md` 1-5l L5) |

- 테스트는 요청할 때마다 어느 단계까지 할지 정합니다. 정하지 않았으면 시작 전에 묻습니다.

## 읽는 문서와 읽지 않는 문서

- **작업 근거로 읽는 것:** `constitution.md`, `flow/`, `reference-rules/`, `examples/`(작성예시문서), `templates/`, `policy/`, `alert/`(Alert · Toast 카탈로그), `glossary/`, `screens/`(asis `screens/asis/`, tobe `screens/tobe/`), `ia/`, `common-ux/`, `language-set/`, `meetings/`, `sources.md`, `work-logs/`, `discussions/`, `pending/`(반영 대기 목록)
- **이름이 `old-`로 시작하는 폴더 · 파일은 예전 문서입니다.** 작업 근거로 쓰지 않습니다. 새 문서와 다르면 새 문서가 맞습니다.
  - `old-rules/`: 예전 규칙. 내용은 `flow/` · `reference-rules/`로 옮겼거나 옮기는 중
  - `old-pending/` · `old-provisional/` · `old-customer-agenda/`: 예전 내부 논의 · 임시 정책 · 고객 논의. 아직 논의 대상으로 옮기지 않은 열린 항목이 있으므로, 걸린 정책 · 화면을 작업할 때는 **무엇이 정해지지 않았는지 확인하는 용도로만** 읽음
- `archive/`는 결정의 출처를 찾을 때만 읽습니다.
- `background/`는 규칙을 만드는 작업 자료입니다. 화면설계 작업의 근거로 쓰지 않습니다. 할 일은 `background/todo.md` 한 곳에 모읍니다.

## 아직 새 문서가 없는 일

회의록 정리, 정책서 쓰기, 언어셋, 용어 검토, 일정처럼 새 문서가 아직 없는 일은 이렇게 합니다.

1. 헌법과 새 문서(`reference-rules/`)에 정해진 것을 먼저 따릅니다. 논의는 논의 대상으로, 다른 화면에 미치는 변경은 반영 대기 목록으로 남깁니다. 임시 정책 · 협의 대기 · 고객 논의 목록은 새로 만들지 않습니다.
2. 새 문서에 없는 부분만 `old-rules/`의 해당 문서를 참고합니다. 참고한 문서 이름을 보고에 적습니다.
3. 예전 규칙과 새 문서가 부딪치면 새 문서를 따르고, 부딪친 곳을 `background/todo.md`에 적습니다.

## 늘 지키는 것

- 결정되지 않은 내용은 만들어 쓰지 않고 질문으로 남깁니다. 화면에서는 기존 원본 → 정책서 → Common UX → 같은 메뉴의 다른 화면 순서로 따를 것을 찾아 그리고 질문 대기로 표시합니다. 근거가 있어 기존 화면과 다르게 그린 곳은 변경 확인으로 표시합니다. 둘 다 디스크립션 본문에 넣지 않고 사용자 확인 라벨과 사용자 확인 목록에만 둡니다(`reference-rules/description.md` 5절). 오타 · 표기 정리, 반영 대기에 적힌 값 그대로, Common UX · 기존 화면대로 더한 설명처럼 3단계에서 확인된 변경은 라벨 · 목록 없이 작업 기록에만 남깁니다(같은 절 "변경 확인").
- 기존 화면은 UX 화면설계서(패널이 붙은 기획 프레임과 디스크립션)만 근거로 씁니다. 디자인 화면에서 가져오지 않습니다.
- 결정은 사람이 합니다. Claude는 제안하고 실행합니다.
- "테스트로", "반영하지 말고"라고 하면 순서는 그대로 하고 저장소는 고치지 않습니다(`flow/README.md` "테스트로 할 때").
- 커밋은 요청받았을 때만 합니다.
- 규칙 · 틀 · 안내 문서에는 변경 이력 표를 쌓지 않습니다(바뀐 것은 git 기록). 어느 문서가 이력을 남기는지는 `flow/README.md` "문서 버전"에 있습니다.
