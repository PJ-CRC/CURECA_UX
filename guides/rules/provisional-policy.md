# 임시 정책

> 상태: 초안 v0.6 (2026-11-04). v0.6에서 승인 담당자 1명을 없앰: 임시 정책은 모두에게 보이고, 함께 확인한 사람이 [승인] · [반려]를 누르며, [승인]하면 반영됨(헌법 4조 v1.6). v0.5 (2026-11-03): v0.4에서 회의 중심 절차와 상태 8단계를 걷어 내고, 등록 → 승인·반려 → 반영 세 단계로 줄임 (헌법 4조 v1.4). v0.5에서 겹치는 임시 정책 확인과 A/B 선택 문서(6절)를 더함. 같은 날 상태 이름 "검토 중"을 "승인 대기"로 바꾸고 시작 기준을 적음.

임시 정책은 공통 자료(정책서·룰 문서)에 아직 없지만 작업에 먼저 쓰는 정책입니다. 공통 자료는 누구도 직접 고치지 않으므로(헌법 4조), 누구든 기존 정책을 바꿔야 하거나 고객 답을 기다리지 않고 진행해야 하면 임시 정책으로 등록해 그 기준으로 작업합니다.

## 1. 흐름

1. **등록:** Claude가 먼저 "승인 대기" 임시 정책 중 같은 정책을 바꾸는 것이 있는지 확인합니다(6절). 없으면 `templates/provisional-policy.md`로 `provisional/PV-0001.md`를 만들고, 적용한 화면 머리말 `provisional`에 PV ID를 넣습니다. 번호는 `provisional/`과 `provisional/closed/`의 가장 큰 번호에 1을 더합니다.
2. **함께 확인하고 승인·반려:** 등록된 임시 정책은 UX 문서의 임시 정책 메뉴에 모두에게 보입니다. 함께 확인한 뒤 확인한 사람이 [승인] 또는 [반려]를 누릅니다. 따로 정한 승인 담당자는 없습니다. 회의를 기다리지 않아도 되고, 필요하면 회의에서 같이 봅니다. 승인하면서 내용을 고칠 수 있습니다.
3. **반영:**
   - 승인: [승인]을 누르면 Claude가 공통 자료에 반영하고 공통 규칙 버전을 올린 뒤, 파일에 반영 버전을 적고 `provisional/closed/`로 옮깁니다. 같은 커밋에서 영향 화면의 반영 대기 목록에 줄을 만듭니다(4절).
   - 반려: 사유를 적고 `provisional/closed/`로 옮깁니다. 적용한 화면은 작성자가 기존 정책으로 되돌리고(적용한 화면의 `대기 (임시 정책 적용 예정)` 줄은 `제외 (날짜, PV 반려)`), 영향 화면에는 줄을 만들지 않습니다(4절).

닫힌 파일은 지우지 않습니다(헌법 9조).

## 2. 상태

| 상태 | 뜻 |
| --- | --- |
| 승인 대기 | 대표 저장소에 올라와 UX 문서 목록에 보임. 작성자는 이 기준으로 작업 중이고 승인 전 |
| 승인 | 함께 확인하고 [승인]을 누름. 공통 자료에 반영하면 `closed/`로 옮김 |
| 반려 | 적용하지 않기로 함 |

- 작성자 PC에서 만든 임시 정책은 대표 저장소에 올려야 모두에게 보입니다. 적용한 화면을 올릴 때 PV 파일도 함께 올립니다.
- 상태는 [승인]·[반려](또는 파일에 직접 적은 결정)로만 바뀝니다. 누가 눌렀는지는 결정 칸의 결정자에 남습니다: 승인 대기 → 승인 또는 반려.

## 3. 작업할 때

- 임시 정책은 등록한 작업과, 그 PV ID를 머리말에 적은 화면에서만 씁니다. 승인 전에는 공통 규칙(UX 문서)에 넣지 않으므로 다른 팀원의 Claude는 모릅니다.
- Claude는 바뀌는 규칙만 PV 내용을 따르고, 나머지는 공통 규칙을 따릅니다.
- 이번 작업에서는 적용한 화면만 고칩니다. 적용한 화면을 이번에 다 그리지 못하면 그 화면의 반영 대기 목록에 `대기 (임시 정책 적용 예정)` 줄을 만듭니다.
- 같은 정책을 쓰는 다른 화면은 고치지 않고 파일의 "영향 화면"에만 적습니다. 그 화면들의 반영 대기 목록 줄은 **승인될 때** 만듭니다(2026-11-04 사용자 결정, `rules/screen-spec.md` 4절).

## 4. 영향 화면

Claude가 바꾸는 정책을 쓰는 화면, 적용한 화면을 부르거나 적용한 화면이 부르는 화면, T/L 짝 CID를 찾아 영향이 있는 것만 적습니다(찾는 법은 `rules/screen-spec.md` 4절 "영향 화면 찾기"). - 승인되면 Claude가 영향 화면을 다시 찾아 이 표와 맞춘 뒤, 그 화면들의 반영 대기 목록에 줄을 만들고 줄의 전체 ID를 이 표의 "반영 대기 줄" 칸에 적습니다. 승인하면서 내용을 고쳤으면 고친 내용으로 씁니다.
- 반려되면 영향 화면에는 줄을 만들지 않습니다. A/B 선택이면 고른 안의 영향 화면에만 줄을 만듭니다(`rules/screen-spec.md` 4절 "원인이 바뀌면").

| 영향 | 뜻 |
| --- | --- |
| 화면 변경 | 화면 구성, 동작, 알럿이 바뀜 |
| 디스크립션 변경 | 화면은 그대로이고 디스크립션만 바뀜 |
| 확인 필요 | 영향이 있는지 그 화면 작성자가 봐야 함 |

영향받는 화면 작성자는 UX 문서의 임시 정책 메뉴에서 확인합니다. 메신저(Slack 등) 알림은 추후 연동합니다.

## 5. UX 문서의 승인·반려 버튼

팀 프로그램 UX 문서의 임시 정책 메뉴에 [승인]·[반려] 버튼을 둡니다. 모든 사람에게 보이고, 확인한 사람이 누릅니다(따로 정한 승인 담당자 없음). 버튼은 파일의 상태와 결정 칸을 채워 대표 저장소에 커밋하는 일을 대신합니다. 원본은 항상 파일이고, 프로그램이 없으면 파일에 직접 적습니다.

- [승인]: 상태 "승인", 결정 칸에 날짜·승인·결정자·메모
- [반려]: 상태 "반려", 결정 칸에 날짜·반려·결정자·사유(꼭 적음)
- A/B 선택 문서는 [A안 승인]·[B안 승인]·[반려]로 바뀝니다(6절).
- 목록에서 "바꾸는 정책"이 같은 "승인 대기" 임시 정책은 같은 표시로 묶어 보여 주고, [승인]을 누를 때 같은 정책을 바꾸는 다른 임시 정책이 있으면 먼저 알려 줍니다. 동시에 등록돼 Claude가 못 찾은 경우를 막기 위해서입니다.

## 6. 겹치는 임시 정책

Claude는 임시 정책을 새로 등록할 때마다 `provisional/`의 "승인 대기" 임시 정책을 모두 읽고, "바꾸는 정책"이 같은 것을 찾습니다. 찾은 결과에 따라 다음처럼 처리하고, 처리한 내용을 작성자에게 말합니다.

| 경우 | 처리 |
| --- | --- |
| 같은 규칙을 같은 내용으로 바꿈 | 새로 만들지 않고 그 PV를 씀. 작성자의 화면을 그 PV의 "적용한 화면"에 더함 |
| 같은 규칙을 다른 내용으로 바꿈 (충돌) | 새로 만들지 않고 기존 PV를 A/B 선택 문서로 합침(아래). 새 내용이 B안이 됨 |
| 같은 정책의 다른 규칙을 바꿈 | 새 PV를 만들고, 두 파일의 "같은 정책을 바꾸는 임시 정책"에 서로를 적음. 두 임시 정책을 함께 보고 정함 |

- 같은 규칙에 서로 다른 예외나 조건을 더하는 경우처럼, 규칙 번호가 달라도 같은 상황을 다르게 정하면 충돌로 봅니다. 충돌인지 애매하면 작성자에게 묻습니다.
- "바꾸는 정책"은 `POL-EQP-008 규칙 5`, `POL-EQP-008 추가`처럼 정책 ID와 규칙 번호로 적습니다. 그래야 찾을 수 있습니다.

### A/B 선택 문서

충돌하는 두 임시 정책을 한 파일에서 나란히 보고 하나를 고르게 하는 문서입니다. `templates/provisional-policy-ab.md`를 씁니다.

- 기존 PV 번호를 그대로 씁니다. 기존 내용이 A안, 새 내용이 B안입니다. 세 번째가 생기면 C안을 더합니다.
- 화면 머리말 `provisional`에는 `PV-0003`(A안) 또는 `PV-0003-B`(B안)처럼 적습니다. 기존 화면은 고치지 않아도 됩니다.
- Claude가 "두 안의 차이"에 무엇이 다른지와, 각 안을 고르면 고쳐야 할 화면을 정리합니다.
- 함께 확인한 뒤 [A안 승인], [B안 승인], [반려] 중 하나를 누릅니다. 승인하면서 내용을 고칠 수 있습니다. 고르지 않은 안을 적용한 화면은 "영향 화면"(화면 변경)이 되고, 그 작성자가 고칩니다.
