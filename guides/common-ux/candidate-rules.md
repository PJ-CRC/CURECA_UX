# Common UX 후보 올리는 법

> 상태: 초안 (2026-11-12). 목록은 [candidates.md](candidates.md).

목적은 하나입니다. **Common UX에 없는데 여러 화면에서 쓰이는 요소를 찾아, Common UX에 추가할지 정할 근거를 쌓는 것**입니다.

## 이어지는 순서

1. **3단계 (화면 설계):** 가이드에 컴포넌트가 없는 요소를 그리면, 작업 기록 "컴포넌트 없이 그린 요소" 표에 남깁니다. 후보를 가져다 썼으면 후보 ID를 적고, 새로 그렸으면 "신규로 만듦" · "기존 화면에서 따옴"을 적습니다(`flow/3-design.md` 공통 3 "Figma 그리기" 3번(`공통 3-3` 요소를 찾는 순서), "남는 것").
2. **5단계 (완료):** 그 표를 보고 후보 목록에 올립니다. **지금은 하지 않습니다(2026-11-19).** 후보를 올리는 기반이 준비되면 5단계 절차에 다시 넣습니다(`flow/5-done.md` 절차 2번 순서 6).
3. **쓴 화면 수가 3화면 이상이 되면:** 상태를 `추가 제안 (날짜)`로 바꾸고 완료 보고에 적습니다. Common UX에 넣을지는 요청자가 Common UX 담당자와 정합니다.

## 5단계에서 올리는 법

| 작업 기록에 적힌 것 | 후보 목록에 하는 일 |
| --- | --- |
| 후보 ID (후보를 가져다 씀) | 그 줄의 "쓴 화면"에 CID를 더하고 "쓴 화면 수"를 1 올림 |
| 신규로 만듦 | 새 줄을 만듦. 상태 `후보`, 쓴 화면 수 1 |
| 기존 화면에서 따옴 (케이스 3) | 목록에 같은 요소가 있으면 위의 "후보 ID"처럼 1 올리고, 없으면 "신규로 만듦"처럼 새 줄을 만듦 |

- **같은 요소인지:** 요소 이름 (종류) · 하는 일 · 모양이 같으면 같은 요소로 봅니다(2026-11-13 하는 일을 더함). 애매하면 새 줄로 만들지 않고 요청자에게 묻습니다.
- **T/L 짝:** 같은 요소를 T와 L에서 함께 쓰면 1화면으로 셉니다.
- **같은 화면에서 여러 번:** 한 화면 안에서 여러 번 써도 1화면으로 셉니다.
- 테스트 작업(`test: true`)은 올리지 않습니다.

## 하지 않는 것

- 3단계에서 그리면서 바로 후보 목록에 올리기 (완료되지 않은 그림이 후보가 됨)
- 쓴 화면 수가 기준을 넘었다고 Claude가 Common UX에 직접 넣기
