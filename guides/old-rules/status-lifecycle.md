# 문서 상태

> 상태: 초안 v0.3 (2026-11-04). v0.3에서 Figma 상태 표시를 신규 작업방의 메뉴 상태 카드로 정함(2절, `old-rules/screen-spec.md` 5절, PD-0006(`old-pending/closed/PD-0006.md`)). v0.2에서 UX 상태도 작업자가 Figma에서 바꾸고, 메뉴 상태가 일정(스프레드시트) 상태로 이어지게 함(2절, `old-rules/schedule.md` 4절).

화면설계서의 진행 상태, 표시(플래그), 기록 형식, 폐기 처리를 정합니다. 여기서 말하는 "상태"는 기획 문서의 진행 상태이며, 장비의 상태값(`glossary/status-values.csv`)과는 다릅니다.

## 1. 관리 단위

- 상태는 메뉴 단위로 관리합니다. 메뉴는 대시보드 LNB에서 눌리는 단위(IA 1~2 depth)입니다.
- 메뉴에 속한 CID들은 상태를 함께 씁니다. 변경 이력과 표시는 CID별로 남깁니다.

## 2. 상태값

| 축 | 값 | 바꾸는 방법 |
| --- | --- | --- |
| UX | 작업 중 / 컨펌 중 / 컨펌 완료 | 담당 기획자가 신규 작업방의 메뉴 상태 카드(`old-rules/screen-spec.md` 5절)에서 바꾸고, 프로그램 또는 Claude가 메뉴 상태에 반영 |
| UI | 작업 중 / 컨펌 대기 중 / 컨펌 완료 | 작업 중·컨펌 대기 중은 디자이너가 메뉴 상태 카드에서 바꾸고 Claude가 매일 점검. 컨펌 완료는 담당 기획자 요청으로 Claude가 반영 |
| 전달 | 전달 대기 / 전달 완료 | 자동 (프로그램 또는 Claude). 흐름 보류 중(2026-11-05, `old-rules/figma-sync.md` 2절)에는 바꾸지 않음 |
| 공통 | 폐기 | 결정 기록 또는 CR이 있어야 바꿀 수 있음 (6절) |

- UI의 "컨펌 대기 중"은 전사 공통 값이라 이름과 뜻을 바꾸지 않습니다. 디자인 완료, 고객 리뷰 요청 대상입니다.
- "컨펌 완료"는 요청하면 바로 바꿉니다.
- 메뉴 상태가 바뀌면 일정(스프레드시트)에서 같은 메뉴의 업무 줄 상태도 따라 바뀝니다. 대응표는 `old-rules/schedule.md` 4절입니다 (표시 방법은 메뉴 상태 카드로 정함. 자동 연결은 팀 프로그램 R23이 생기면 시작) (시트 값 기준. UX 작업 중 → 진행 중, 컨펌 중 → 리뷰 중(예정), 컨펌 완료 → 디크 검토, UI는 UX 컨펌 완료 때 대기, 이후 작업 중 → 진행 중, 컨펌 대기 중 → 리뷰 중(예정), 컨펌 완료 → 완료).
- 컨펌 완료(UX 또는 UI)와 전달 완료로 바뀔 때, 그 메뉴에서 **수정된 CID만** 화면 정보 `date`를 그날로 바꿉니다. 수정된 CID는 직전 컨펌 완료(전달 완료면 직전 전달 완료) 이후 변경 이력에 새 줄이 생긴 CID입니다. 수정하지 않은 CID는 `date`와 `version`을 그대로 둡니다(`old-rules/repository-and-id.md` 6절). 작업방 → 공유방 → 개발사 흐름이 보류 중(2026-11-05, `old-rules/figma-sync.md` 2절 · `old-rules/screen-spec.md` 0 · 5절)이라, 이행 기간이 끝날 때까지 전달 상태(전달 대기 / 전달 완료)는 바꾸지 않습니다.
- 전달 완료 후 다시 바뀌는 화면은 전달 대기로 돌아가고, 버전을 올려야 한다고 알립니다(`old-rules/repository-and-id.md` 6절).

## 3. 큰 변경과 작은 변경

| 구분 | 무엇이 바뀌나 | 처리 |
| --- | --- | --- |
| 큰 변경 | 흐름, 레이아웃, 상태값, 컴포넌트 구성 | 메뉴의 UX 상태를 "작업 중"으로 되돌림 |
| 작은 변경 | 문구, 라벨, 디스크립션, 수치 | 상태는 유지하고 해당 CID에 "변경 예정" 표시 |

## 4. 표시 (플래그)

| 표시 | 붙이는 경우 | 함께 적는 것 |
| --- | --- | --- |
| 변경 예정 | 컨펌 완료 화면에 작은 변경이 확정됨 | CR ID |
| 임시 정책 포함 | 고객 확답 전 임시 정책을 적용함 (`old-rules/provisional-policy.md`) | PV ID |
| 연동 변경 | 다른 화면이나 정책의 변경으로 함께 고쳐짐 | 원인 CID 또는 정책 ID |
| Figma 반영 대기 | 프로그램이 멈춘 동안 저장소만 바뀜 (`old-rules/claude-work.md` 8절) | 없음 |
| CID 확정 대기 | IA에 없는 새 화면을 제안 CID로 작업 중 (`old-rules/repository-and-id.md` 2절) | `ia/change-requests.md`의 줄 번호 |

- 화면 옆 버전별 메모(포스트잇)는 변경 이력에서 자동으로 만듭니다. 같은 내용을 두 번 쓰지 않습니다.

## 5. 기록 형식

상태와 화면 정보는 파일 맨 위 `---` 사이의 머리말에 적습니다. 프로그램과 Claude는 이 칸만 읽고 바꿉니다. 키는 영어, 값은 이 문서와 용어집의 표기 그대로 씁니다.

### 메뉴 파일 `screens/<메뉴>/_menu.md`

```yaml
---
menu: Dashboard
cids: [TI-DAS, LI-DAS]
owner: 서보경
ux_status: 컨펌 중          # 작업 중 | 컨펌 중 | 컨펌 완료 | 폐기
ui_status: 작업 중          # 작업 중 | 컨펌 대기 중 | 컨펌 완료 | 폐기
delivery_status: 전달 대기  # 전달 대기 | 전달 완료
delivered_version:          # 전달 완료 때 기록 (예: 2.1.13)
delivered_date:             # 전달 완료 때 기록 (YYYY-MM-DD)
redrawn:                    # 신규 작업방에 새로 그린 날 (old-rules/screen-spec.md 0절)
---
```

본문에는 상태 이력 표를 둡니다. 상태가 바뀔 때마다 한 줄씩 더하고, 지우지 않습니다(헌법 9조).

| 날짜 | 축 | 바뀐 내용 | 바꾼 사람 | 근거 |
| --- | --- | --- | --- | --- |
| 2026-10-30 | UX | 작업 중 → 컨펌 중 | 서보경 | 고객 리뷰 요청 |

### 화면설계서 `screens/<메뉴>/<CID>.md`

```yaml
---
cid: TI-DAS
pair_cid: LI-DAS              # 짝이 없으면 비움
tl_relation: 기능 추가         # 동일 | 권한 차이 | 기능 추가 | 단독
title: Dashboard              # 화면
path: Dashboard               # 경로
type: Page                    # Page | Popup | Tab
version: 2.1.13               # Ver (old-rules/repository-and-id.md 6절)
date: 2026-10-30              # 수정된 CID만 컨펌 완료·전달 완료 때 갱신
author: 서보경
service_mode: [Main Mode, Console Mode, TSS Mode]   # L-IOS 화면만
user_type: [Service, Admin, User]
policies: []                  # 정책 ID
flags:
  - type: 변경 예정
    ref: CR-0001
---
```

- 머리말 아래 본문의 구성은 `old-rules/screen-spec.md`를 따릅니다.
- 변경 이력은 화면설계서 본문의 "변경 이력" 표에 남깁니다.

### 검증할 수 있는 것

- 컨펌 완료나 전달 완료인데 `date`가 비어 있음
- `flags`의 ID(CR, PV)가 해당 폴더에 없음
- `pair_cid` 파일에 이 화면이 짝으로 적혀 있지 않음
- `cids`에 있는 CID의 파일이 없거나, 파일은 있는데 `cids`에 없음
- 상태값이 2절의 값이 아님

## 6. 폐기

- 정책 변경으로 사라진 화면은 지우지 않고 "폐기"로 바꿉니다. 결정 기록 또는 CR 링크가 있어야 합니다.
- 화면설계서 파일은 `archive/`로 옮기고 Claude의 근거 자료에서 뺍니다.
- Figma: 작업방에서는 폐기 보관 영역으로 옮기고, 컨펌·개발사 페이지에서는 뺍니다(공유방 · 개발사 페이지는 흐름 보류 중, `old-rules/figma-sync.md` 2절). 이미 개발사에 전달된 화면이면 릴리즈 노트에 폐기를 적습니다.
- IA: 행을 지우지 않고 폐기 표시와 폐기 버전을 남깁니다.
- 정책: 그 화면에만 쓰이던 정책 ID는 Deprecated 처리하고, 다른 화면에도 연결된 정책은 유지합니다.
